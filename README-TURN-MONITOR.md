# Мониторинг TURN/MEDIA — предварительное обновление

Добавлен блок «TURN-серверы» в «Сервисы и система → Мониторинг проектов». Он показывает несколько MEDIA-узлов, свежесть отчёта и результат локального STUN Binding, присланный Voice Node Agent. Источник — существующий Server Mesh, без изменения схемы БД и без изменений VPN-узлов. Доступ к данным — только ADMIN.

## Что установить и проверить

1. Сделайте резервную копию основного проекта и базы. Этот архив собран из предоставленной версии основного TrioZ; инструкция ниже относится именно к ней. Схема БД не меняется; актуальные миграции проекта всё равно должны быть установлены ранее.
2. Обновите исходники основного проекта по принятой для вас процедуре и перезапустите сервер согласно существующей документации. Патч из старого архива Voice **не применять поверх этого обновлённого архива**: он уже включён.
3. В `/admin/servers` создайте дочерний узел типа MEDIA на каждый сервер. Сохраните выданный одноразово токен агента в секретном хранилище.
4. На соответствующей машине настройте и отдельно запустите обновлённый Voice Node Agent: `TRIOZ_MAIN_URL=https://<центральный-домен>`, `TRIOZ_AGENT_TOKEN=<токен MEDIA>`, `TURN_STUN_PORT=3478` или фактический UDP-порт. Агент проверяет только `127.0.0.1`, поэтому он и TURN должны находиться в совместимом сетевом namespace. Состояние должно появиться в `/admin/monitor` после heartbeat. Если агент запускается в контейнере, loopback контейнера не является loopback хоста; настройте сеть осознанно.
5. Проверьте реальную работу TURN отдельно из внешней сети с выдачей временных credentials и передачей данных через relay, а также TLS и firewall провайдера. Локальный STUN ответ не подтверждает ни авторизацию, ни ретрансляцию, ни доступность из интернета.

## Состояние реализации

- В предоставленном архиве нет блока `monitor-smtp`; новый блок расположен непосредственно перед «Ресурсами серверов». Для размещения относительно существующего в другой версии `monitor-smtp` нужен актуальный исходный код этой версии.
- Алгоритм привязки голосового канала к ближайшей вышке **не реализован**. Настройки действующих TURN и обработчики голосовых комнат не изменены, чтобы не ломать текущую связь.
- Встроенный TURN LiveKit работает с подключениями LiveKit и не является универсальной заменой coturn для текущего mesh WebRTC. Для новой вышки текущих голосовых каналов нужен совместимый coturn и отдельная интеграция выбора узла.
- Сборка типов и тесты пройдены на копии проекта; тесты отчётов используют mock базы, а UI — mock-данные. Действующие VPS, реально работающий TURN relay, WebRTC и многопользовательский сценарий не проверялись.
