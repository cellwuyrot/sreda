# Исправления сборки Android (apps/android)

Устранены дефекты, из-за которых сборка либо не компилировалась, либо давала
APK, который невозможно запустить или установить.

## 1. Устаревший дубликат PushService

**Файл:** `app/src/main/java/ru/trioz/connect/PushService.kt` — удалён.

Коммит `6b0d085` перенёс службу в отдельный набор исходников `app/src/push/`, но
старая копия осталась в `main`. Когда рядом лежал `google-services.json`, в
сборку попадали оба файла сразу: около 30 ошибок компиляции —
`Conflicting declarations` для `EXTRA_LINK` и `CALL_CHANNEL_ID`. Без
`google-services.json` тот же файл не собирался по другой причине: импорты
Firebase недоступны, так как зависимость подключается только вместе с файлом
доступов.

Актуальная версия службы — `app/src/push/java/ru/trioz/connect/PushService.kt`,
она и остаётся единственной.

## 2. Подмена основного манифеста push-манифестом

**Файл:** `app/build.gradle.kts`

Было:

```kotlin
sourceSets["main"].manifest.srcFile("src/push/AndroidManifest.xml")
```

У одного набора исходников манифест ровно один, поэтому строка не подмешивала
push-манифест, а **заменяла** им основной. Как только в проекте появлялся
`google-services.json`, из APK исчезало всё содержимое основного манифеста:
`ConnectApp`, `MainActivity`, фильтр `MAIN`/`LAUNCHER` и все разрешения. Сборка
при этом проходила успешно, APK устанавливался — но без иконки в лаунчере и без
возможности запуска.

Стало:

```kotlin
sourceSets["debug"].manifest.srcFile("src/push/AndroidManifest.xml")
sourceSets["release"].manifest.srcFile("src/push/AndroidManifest.xml")
```

У наборов `debug` и `release` собственные манифесты по умолчанию не заданы, так
что подмены не происходит: manifest merger сливает push-манифест с основным —
ровно то поведение, которое подразумевалось изначально.

## 3. Неверный метод BigTextStyle

**Файлы:** `app/src/main/java/ru/trioz/connect/NotificationBridge.kt:102`,
`app/src/push/java/ru/trioz/connect/PushService.kt:106`

У `NotificationCompat.BigTextStyle` метод называется `bigText()`; `setBigText()`
существует только у платформенного `android.app.Notification.BigTextStyle`.
Оба вызова исправлены на `bigText(...)`.

## 4. Неподписанный релизный APK

**Файл:** `app/build.gradle.kts`

Без `app/keystore.properties` релизная сборка оставалась неподписанной, а
неподписанный APK Android ставить отказывается — телефон показывает
«Приложение не установлено» без пояснений.

Теперь при отсутствии ключа релиз подписывается отладочным `signingConfig`
(он генерируется автоматически на любой машине), а в лог уходит предупреждение
уровня `warn`: такой APK устанавливается и проверяется, но для публикации не
годится. При наличии `keystore.properties` поведение прежнее — подпись
настоящим ключом.

## 5. Вылет сразу после сплэш-экрана из-за конфигурации сети

**Файл:** `app/src/main/res/xml/network_security_config.xml`

Блок `<domain-config>` (послабление HTTP для локальной отладки) был вложен в
`<debug-overrides>`. Спецификация Android разрешает внутри `<debug-overrides>`
только `<trust-anchors>`; любой другой тег валит разбор конфигурации сети с
`ParserException`. Разбор ленивый — он происходит при первом сетевом запросе
WebView, уже после сплэш-экрана, поэтому отладочная сборка стабильно падала
сразу после запуска (в релизе `debug-overrides` не применяется вовсе, и вылет
не воспроизводился).

Настройки доменов вынесены на верхний уровень `<network-security-config>`.
Cleartext (HTTP) теперь разрешён только для петлевых адресов
(`10.0.2.2`, `localhost`, `127.0.0.1`); весь остальной трафик остаётся строго по
HTTPS за счёт `android:usesCleartextTraffic="false"` в манифесте.

## Про уведомления в закрытом приложении (google-services.json)

Файл `app/google-services.json` в репозиторий не добавляется: это ключи
конкретного проекта Firebase, и сгенерировать валидный файл в обход консоли
Firebase нельзя. Сборка это учитывает и работает без него (см. `build.gradle.kts`
и п. 1): приложение собирается и запускается, просто не получает Push-токен и не
показывает уведомления в закрытом состоянии. Чтобы включить доставку,
положите свой `app/google-services.json` рядом с модулем — плагин Google
Services и зависимость FCM подключатся автоматически (инструкция —
`apps/android/README.md`).

## Проверка

Правки проверены осмотром кода и статически: дубликата `PushService` больше нет
(в `main` не осталось ни класса, ни ссылок на Firebase), общие константы
`EXTRA_LINK`/`CALL_CHANNEL_ID` объявлены единожды в `PushTokens.kt`,
`setBigText` не встречается нигде, основной манифест сохраняет `application`
целиком, а `<domain-config>` вынесен из `<debug-overrides>`. Реальные сборки
Gradle в этой итерации не запускались: в окружении нет Android SDK.

Полезно знать при сборке в изолированном окружении: если исходящий трафик идёт
через прокси с собственным корневым сертификатом, его нужно импортировать в
`cacerts` JDK — иначе `sdkmanager` и Gradle не смогут ничего скачать.
