# Connect — Android-клиент

Нативная Android-оболочка мессенджера **TZ.Connect**. По той же схеме, что и
десктоп-версия (`apps/desktop` на Electron), приложение — это тонкая оболочка
поверх `WebView`, которая открывает раздел **`/connect`** уже работающего
веб-сервера. Остальной сайт внутри приложения не показывается.

Приложение называется **Connect**, идентификатор пакета — `ru.trioz.connect`.

## Что делает оболочка

- Открывается сразу на `/connect` и держит навигацию **внутри клиента**. Политика
  — белый список путей (см. `Config.kt`): сам мессенджер (`/connect`), вход
  (`/auth`), приглашения (`/invite`), вложения (`/uploads`), служебное (`/api`) —
  и собственные разделы человека: `/settings` (профиль и центр уведомлений),
  `/workspace`, `/partner`, `/editor`, `/admin`. Любой сайтовый раздел (лендинг
  `/`, `/user/…`, `/library`, `/projects`, `/games`, …) немедленно возвращает в
  `/connect`.

  Раньше список был короче — только мессенджер, — и из-за этого в приложении не
  было ни профиля, ни уведомлений, ни рабочей среды, а у партнёра, редактора и
  администратора — их разделов: колокольчик существовал, но вёл в запрещённый
  путь, и оболочка возвращала человека назад. Разделение теперь такое: свои
  разделы ЧЕЛОВЕКА — часть клиента, витрина сайта — нет. Клиентские SPA-переходы Next.js дополнительно
  глушатся на веб-стороне (`AndroidShellGuard`, скрытие сайтовых ссылок по
  классу `tz-android`), а `doUpdateVisitedHistory` в `MainActivity` —
  последний рубеж. Списки путей в `Config.kt` и
  `apps/web/src/lib/shell.ts` должны совпадать.
- Внешние ссылки открывает в системном браузере.
- Голосовые/видеоканалы (WebRTC): запрашивает системные разрешения на **микрофон**
  и **камеру** и пробрасывает их в веб-часть.
- Вложения: системный выбор файлов (`<input type="file">`) и загрузка файлов
  через `DownloadManager` (с cookie сессии).
- Геолокация на карте: запрашивает разрешение на местоположение.
- Полноэкранное видео, сохранение сессии (cookie), кнопка «Назад» листает
  историю внутри WebView — благодаря отражению мобильного стека экранов в
  history (см. `useMobileHistoryStack` в веб-части) системная «назад» ведёт
  по уровням мессенджера: чат → каналы → список сообществ.

## Требования

- **Android Studio** (Koala/Ladybug и новее). JDK 17 и Android SDK ставятся
  вместе с ним — отдельно ничего устанавливать не нужно.
- Устройство или эмулятор с **Android 8.0 (API 26)** или новее.

Версии инструментов зафиксированы в проекте: Gradle 8.9 (через wrapper),
Android Gradle Plugin 8.6.1, Kotlin 1.9.25, `compileSdk`/`targetSdk` 34.

## Куда смотрит приложение (адрес сервера)

По умолчанию оболочка грузит `https://connect.trioz.ru/connect`. Адрес задаётся
**на этапе сборки** в `app/build.gradle.kts`:

```kotlin
buildConfigField("String", "APP_URL", "\"https://connect.trioz.ru\"")
buildConfigField("String", "START_PATH", "\"/connect\"")
```

Поменяй `APP_URL` на адрес своего сервера (например, свой домен или
`https://<твой-домен>`), если разворачиваешь TZ.Connect отдельно.

> Для локальной отладки на эмуляторе раскомментируй строку в блоке `debug` —
> `http://10.0.2.2:3005` указывает на `localhost:3005` хоста. Cleartext-HTTP
> для `10.0.2.2`/`localhost` уже разрешён в `res/xml/network_security_config.xml`.

## Сборка APK через Android Studio (самый простой путь)

1. Запусти Android Studio → **Open** → выбери папку **`apps/android`** (именно её,
   не корень монорепозитория).
2. Дождись окончания **Gradle Sync** (Studio сама докачает зависимости и,
   при необходимости, нужную версию Android SDK).
3. Меню **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
4. Внизу появится уведомление «APK(s) generated…» — нажми **locate**. Файл лежит
   здесь:

   ```
   apps/android/app/build/outputs/apk/debug/app-debug.apk
   ```

5. Перекинь `app-debug.apk` на телефон и установи (нужно разрешить «Установку из
   неизвестных источников»). Либо подключи телефон по USB с включённой отладкой
   и нажми ▶ **Run** — Studio сама соберёт и установит приложение.

## Сборка из командной строки

Из папки `apps/android` (нужен установленный Android SDK; путь к нему Studio
записывает в `local.properties`, либо задай переменную `ANDROID_HOME`):

```bash
cd apps/android

# Debug-сборка (быстро, для проверки):
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

# Release-сборка (неподписанная):
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release-unsigned.apk
```

На Windows вместо `./gradlew` используй `gradlew.bat`.

## Подписанный release-APK (для распространения)

Debug-APK подписан отладочным ключом и годится только для тестов. Для «боевого»
APK нужен свой ключ:

1. **Создай ключ** (один раз):

   ```bash
   keytool -genkeypair -v -keystore connect-release.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias connect
   ```

2. Рядом с `app/build.gradle.kts` создай файл **`keystore.properties`**
   (он уже в `.gitignore`, в репозиторий не попадёт):

   ```properties
   storeFile=../connect-release.jks
   storePassword=ТВОЙ_ПАРОЛЬ
   keyAlias=connect
   keyPassword=ТВОЙ_ПАРОЛЬ
   ```

3. Добавь в `app/build.gradle.kts` чтение этого файла и `signingConfig` для
   `release` (шаблон — в комментарии ниже), затем:

   ```bash
   ./gradlew assembleRelease
   ```

   Проще всего сделать это через мастер Android Studio:
   **Build → Generate Signed Bundle / APK → APK** — он проведёт по шагам и
   сам пропишет подпись.

## Раздача APK с сайта (кнопка на /about)

APK раздаётся **тем же механизмом, что и десктоп-инсталляторы**: положи файл
под именем **`connect.apk`** в хранилище загрузок веб-приложения — обычно
`apps/web/public/desktop` (в Docker это постоянный том `desktop_data`,
смонтированный в `/app/apps/web/public/desktop`):

```bash
cp app/build/outputs/apk/release/app-release.apk \
   ../../apps/web/public/desktop/connect.apk
```

После этого на странице **/about** рядом с кнопками Windows/macOS/Linux
появится «Скачать для Android» (для посетителей с Android-телефона она
становится основной кнопкой), а файл будет доступен по адресу
`/api/download/desktop?os=android` — скачивается всегда как `connect.apk`,
даже если в хранилище он лежит под другим именем (подойдёт любой `*.apk`).
Роут «живой» (`force-dynamic`): файл виден сразу, без пересборки сайта.
На дев-сервере подхватывается и свежая сборка прямо из
`apps/android/app/build/outputs/apk/{release,debug}` — без копирования.

> Раздавай пользователям **подписанный release-APK** (см. раздел выше):
> debug-сборка подписана отладочным ключом и предназначена только для тестов.

## Возможности и ограничения

| Функция | Статус |
|---------|--------|
| Текстовые чаты, DM, реакции, вложения | ✅ работает |
| Голосовые каналы, видео (WebRTC) | ✅ работает (после выдачи разрешений) |
| Загрузка/скачивание файлов | ✅ работает |
| Геолокация на карте | ✅ работает (после выдачи разрешения) |
| Полноэкранное видео | ✅ работает |
| Профиль, уведомления, рабочая среда, разделы по роли | ✅ через кнопку профиля в списке сообществ |
| Демонстрация экрана (screen share) | ⚠️ не поддерживается в WebView-оболочке |
| Уведомления при закрытом приложении | ✅ работает после настройки доставки (см. ниже) |

Уведомления, которые приходят внутри открытого приложения, отображаются как
обычно — их показывает мост `NotificationBridge`. Уведомления при **закрытом**
приложении идут через службу доставки, и для них нужен один файл доступов — как
его получить, написано ниже.

## Уведомления при закрытом приложении

Раньше уведомления жили только пока приложение открыто: они приходили живым
соединением, и выгруженный системой процесс молчал до следующего запуска. Теперь
сообщение доставляет служба доставки Firebase Cloud Messaging — она живёт в самой
ОС и будит приложение ровно на время показа уведомления, без вечной плашки
«приложение работает» и без расхода батареи на удержание соединения.

**Собирается и без этого.** Плагин доступов применяется только если файл лежит на
месте (см. `app/build.gradle.kts`): нет файла — APK собирается как раньше, просто
уведомления в закрытом приложении не приходят. Сборка не падает.

### Что сделать один раз

1. **Firebase**: console.firebase.google.com → создать проект (или взять
   существующий) → **Add app → Android** → идентификатор пакета
   **`ru.trioz.connect`**. Отпечаток SHA-1 для уведомлений не нужен.
2. Скачать **`google-services.json`** и положить его в **`apps/android/app/`**
   (файл в `.gitignore` — в репозиторий он не попадает и не должен).
3. **Сервер**: в Firebase → **Project settings → Service accounts → Generate new
   private key** — скачается JSON. Из него на сервер в `.env` уходят три значения:

   ```dotenv
   FCM_PROJECT_ID=<project_id из JSON>
   FCM_CLIENT_EMAIL=<client_email из JSON>
   FCM_PRIVATE_KEY="<private_key из JSON, одной строкой, переводы строк как \n>"
   ```

   Не заданы — сервер молча не отправляет: сервис работает как раньше.
4. Пересобрать APK (**Build → Build APK(s)**) и перезапустить веб-часть.

### Как проверить, что работает

1. Установить APK, войти, разрешить уведомления (Android 13+ спросит сам).
2. **Полностью закрыть приложение** (свайпом из списка задач).
3. С другого аккаунта отправить личное сообщение.
4. Уведомление должно прийти в шторку; нажатие открывает приложение сразу на этой
   переписке.

Если не пришло — смотреть в таком порядке: разрешение на уведомления у
приложения, наличие `google-services.json` в сборке, три переменные на сервере,
журнал сервера (строки `[push]`).

### Что важно знать

- **Двойных уведомлений нет:** пока приложение открыто, уведомление показывает
  живое соединение, а доставленное службой отбрасывается (признак «приложение на
  переднем плане» ведёт `ConnectApp`).
- **Один телефон — один владелец:** адрес устройства переприязывается к тому, кто
  вошёл последним, а при выходе снимается. Иначе прежний владелец продолжал бы
  получать уведомления о своей переписке на чужом уже телефоне.
- **Выключатель уведомлений в настройках аккаунта** отключает и доставку в
  закрытое приложение — проверка стоит у самой отправки.
- **Устройства без сервисов Google** (например, часть Huawei) доставку не
  получат: служба доставки — часть этих сервисов. Уведомления при открытом
  приложении там работают по-прежнему.
- **Принудительно остановленное приложение** (кнопка «Остановить» в настройках
  Android) не получает ничего до следующего запуска — так устроена сама система.
