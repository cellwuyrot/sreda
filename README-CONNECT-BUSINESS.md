# Обновление sreda: TZ.Connect → подписки Business

## Изменения
- Меню TZ в левом верхнем углу /connect: понятный статус доступа, отдельные действия подключения и переход к подписке. При отсутствии права больше не открывается заведомо недоступный переключатель.
- Оплата и управление подпиской ведут на https://business.trioz.ru/subscriptions — это раздел нужного пользователю Business, а не отдельная касса в TrioZ. Ссылка открывается в новой вкладке, переписка остаётся на месте. Используется тот же аккаунт TZ ID; если локального сеанса Business нет, сайт Business предложит вход.
- При действующем праве сохраняются существующие включение, экспорт профиля и управление серверами в окне подключения. Профиль, отмеченный активным на сервере, не называется доказанно работающим локальным туннелем.
- В настройках профиля /settings?cat=subscriptions (старый cat=premium работает) — карточки Надёжного соединения и Premium со статусами и ссылками на Business, только если соответствующие предложения настроены.
- Доступ через Premium не побуждает оплачивать отдельную VPN-подписку. Доступ по роли не требует покупки Premium.
- Сохранены настроенные реквизиты для ручной оплаты. Удалены противоречащие интеграции фразы «Онлайн-оплата пока не подключена» и старый основной сценарий оплаты из пула ссылок. Старые финансовые таблицы/API и ранее выданные права не удалены.
- Цены читаются из общего каталога: сумма 200 ₽ не зашита в интерфейс.
- Ошибка сети не представляется отсутствием подписки. У загрузки предложений есть таймаут и повторная попытка.

## Когда показывается ссылка
Новый GET /api/subscriptions/business требует входа, проверяет ограничение аккаунта и не кеширует персональный ответ.

Используется существующий общий каталог, не новый набор ключей:
1. SERVICE_HUB_ENABLED=1 в запущенном основном проекте.
2. Приложение Business в TZ ID включено; это серверный клиент с зарегистрированным точным callback https://business.trioz.ru/api/auth/tz-id/callback.
3. В его существующих разрешениях есть services:manage и services:fulfill.
4. Услуга опубликована, имеет тип VPN или PREMIUM, поддерживаемый способ оформления и хотя бы одну положительную цену за 1/3/6/12 месяцев.

Выключенное приложение, скрытая услуга, тип MANUAL, некорректная цена и ненастроенный Premium не создают фиктивных кнопок покупки. Недоступность БД/каталога показывается как ошибка, а не как отсутствие предложения. Публичный ответ содержит только вид услуги, название, цены и фиксированный URL Business, без клиентских секретов, токенов и метаданных приложения.

Ссылка подтверждает наличие предложения в каталоге, но не банковскую готовность: ключи, кассу и флаги оформления по-прежнему проверяет Business. Передача ссылкой не активирует права. Выдача остаётся за прежним проверенным подтверждением оплаты и синхронизацией.

## Установка
Это полный исходный архив основного проекта с корневой папкой sreda-main. Папку надо использовать как содержимое вашего репозитория, а не вложить второй проект внутрь /var/www/trioz.

Не заменяйте .env, загрузки, базу и runtime-данные. В архиве нет .env с секретами, node_modules, .next и БД. Перед обновлением сохраните вашу обычную резервную копию репозитория/сервера. Не используйте git reset --hard или git clean для обхода конфликтов.

После переноса исходников в Git выполните на сервере:

```bash
cd /var/www/trioz &&
export PATH="/opt/tzbiz-node22/current/bin:$PATH" &&
git pull --ff-only &&
npm ci --ignore-scripts &&
npm exec -w apps/web -- prisma generate &&
npm run test -w apps/web -- --maxWorkers=2 &&
npm run test -w apps/id &&
npm run build &&
/usr/bin/pm2 restart trioz --update-env &&
/usr/bin/pm2 save
```

Новых зависимостей и миграций относительно предыдущего архива общего каталога нет. Если предыдущие миграции услуг ещё не были применены, сначала завершите прежнее развёртывание по DEPLOY-SERVICES.md с резервной копией БД. Для данного интерфейсного обновления отдельно запускать миграцию не нужно.

Перезапускается только PM2 trioz. Код приложения TZ ID (apps/id) и Business этим обновлением не менялся; перезапуск tz-id/tzbiz не нужен. Главный проект и apps/id используют общую схему/интеграцию, как и до обновления.

## Проверка после развёртывания
1. Обычный пользователь без подписки: /connect → TZ → видны условия настроенного Надёжного соединения → «Оформить в Business» открывает /subscriptions в новом окне/вкладке. Пройти вход тем же аккаунтом TZ ID, если потребуется. Для проверки перехода платить не обязательно.
2. Пользователь с VPN: /connect → TZ → «Открыть подключение» → доступны прежние включение/экспорт и управление профилем. Дополнительно видна ссылка управления подпиской, если предложение опубликовано.
3. Пользователь с Premium: не предлагается отдельно купить соединение. Действующие права не пересчитываются от наличия/отсутствия опубликованного предложения.
4. /settings?cat=subscriptions: ссылки VPN/Premium появляются независимо — каждая только при наличии корректного предложения. Скрыть Premium в каталоге: исчезает только его покупка, а не существующее право клиента.
5. Временно недоступный API: интерфейс сообщает ошибку проверки/загрузки, предлагает повторить и не утверждает «подписка закончилась».
6. Проверить обе темы и мобильную ширину. Десктопная и Android-оболочки сохраняют прежние механизмы профилей; нативный туннель на настоящих устройствах в этом обновлении не тестировался.
