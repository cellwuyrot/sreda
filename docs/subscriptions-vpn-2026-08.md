# Раздел «Подписки»: Premium и «только VPN»

Дата: август 2026. Кодовый маркер: `VPN-PLAN`, для полосы прокрутки — `UI-SCROLL`.

## Зачем

Раздел настроек `Premium` переименован в «Подписки» и разделён на две части:

1. **Premium** — всё, что было раньше (статус, срок, возможности, сравнение, оплата).
2. **Только VPN** — новая подписка, которая даёт РОВНО одно право: включать и выключать VPN.

## Данные

Миграция: `prisma/migrations/20260918000000_vpn_only_subscription/migration.sql`.

- `User.vpnAccess` (`Boolean`, по умолчанию `false`) — есть ли отдельная подписка.
- `User.vpnAccessUntil` (`DateTime?`) — срок; `null` = бессрочно.
- `model VpnSubscription` — история платежей (тариф, способ оплаты, сумма, чек, статус, кто выдал).

**Почему отдельная таблица, а не поле `tier` в `PremiumSubscription`.** Все существующие запросы к Premium-подпискам не имеют фильтра по виду подписки. В общей таблице деньги за VPN молча попали бы в выручку Premium, а срок VPN-платежа мог бы считаться сроком Premium.

## Кто может включить VPN

Проверка одна и та же на всех путях (`src/lib/vpn.ts`):

```
hasPremium(user) || hasActiveVpnPlan(user)
```

| Состояние | Туннель | Остальные возможности Premium |
|---|---|---|
| Premium активен | да | да |
| Роль ADMIN | да | да |
| Подписка «только VPN» | да | **нет** |
| Обычный профиль | нет | нет |

Затронуты три точки проверки: `hasVpnEntitlement` и `isPeerEntitled` в `src/lib/vpn.ts` и выборка поля в `src/app/api/servers/report/route.ts` (без неё узел получил бы `undefined` и сбрасывал бы пиров).

Флаг `isPremium` новая подписка не трогает ни при выдаче, ни при отмене, ни при истечении срока.

## Серверная часть

- `src/lib/vpnPlan.ts` — клиентски-безопасный модуль (без prisma): тарифы, названия, `vpnPlanExpiry`, `hasActiveVpnPlan`, `vpnDaysLeft`.
- `src/app/api/admin/vpn/subscriptions/route.ts` — только `ADMIN`:
  - `GET ?userId=` — история + текущий доступ;
  - `POST` — выдать/продлить (срок считается ОТ КОНЦА действующего, оплаченные дни не теряются);
  - `PATCH {subscriptionId, status:"canceled"}` — отмена; доступ снимается только если других активных записей нет.
  - Все изменения пишутся в журнал (`logAction`, цель `VpnSubscription`).
- `src/lib/vpnExpiry.ts` + задача в `apps/web/server.ts` (замок `trioz:lock:vpn-expiry`, раз в шесть часов) — снимают доступ по истечении срока и шлют клиенту `account-vpn-updated`.
- `GET /api/profile` теперь возвращает блок `vpn: { active, expiresAt, daysLeft, viaPremium }` рядом с `premium`.
- `POST /api/vpn/me` при отказе говорит про оба основания: «VPN доступен по подписке «VPN» или по Premium».

## Интерфейс

- `src/app/settings/page.tsx`: категория называется «Подписки», внутри две части с разделителями «Premium» и «Только VPN». У второй части свой статус, свой счётчик дней, список «что входит / что не входит» и свой блок оплаты (`#vpn-payment`).
- Идентификатор категории оставлен прежним (`premium`), чтобы старые ссылки `?cat=premium` не сломались; дополнительно принимается `?cat=subscriptions`.
- Если VPN уже доступен по Premium, вторая часть прямо говорит: отдельная подписка не нужна.
- `src/app/admin/premium/page.tsx`: у администратора в строке пользователя появилась кнопка «Только VPN» с отдельной модалкой (тариф, способ оплаты, сумма, чек, история, отмена).

## Полоса прокрутки на странице настроек (`UI-SCROLL`)

Страница настроек прокручивается документом, поэтому видимая справа полоса — это полоса `html`, а не внутреннего контейнера.

- Класс `html.tz-hide-scrollbar` в `src/app/globals.css` скрывает только индикатор: `scrollbar-width: none`, `::-webkit-scrollbar { width: 0 }` и `scrollbar-gutter: auto` (иначе от правила `FIX-B11` осталась бы пустая полоска в 6px).
- `overflow` не меняется, поэтому прокрутка колесом, клавишами, тачпадом и жестом работает как раньше.
- Класс ставится и снимается в `useEffect` самой страницы настроек — на остальных экранах (переписка, холст) полоса остаётся.
