# Android: VPN, политика допуска и выпуск

## 1. Что реализовано и что ещё требует проверки

Android-клиент `ru.trioz.connect`, версия 0.4.0, versionCode 3; Android 8+ (API 26), targetSdk/compileSdk 36.

- Кнопка TZ и окно соединения используют встроенный AmneziaWG, а не импорт `.vpn` в стороннее приложение. Выбор сервера сохранён.
- WebView запрашивает системное согласие на VPN. Туннель работает в нативном сервисе с постоянным уведомлением и действием отключения.
- Приватный ключ создаётся на устройстве отдельно для аккаунта, хранится зашифрованным AES-GCM с ключом Android Keystore. В JavaScript и на сервер передаётся только публичный ключ; экспорт профиля и QR в Android скрыт. Браузерный экспорт не менялся.
- Перед включением ожидается применение peer дочерним агентом. «Подключено» означает свежее рукопожатие, а не просто поднятый интерфейс. Без рукопожатия предусмотрен тайм-аут; доступны счётчики трафика. Это ещё не доказательство работы DNS и выхода в Интернет.
- Политика допуска проверяется до подключения и примерно каждые 3 секунды во время работы. При запрете туннель отключается. Повреждённая политика запрещает подключение, а не пропускает его.
- VPN-мост принимает сообщения только от главного фрейма точного HTTPS-origin приложения. Для него нет устаревшего `addJavascriptInterface`.
- Нативный backend: зафиксированная зависимость `com.zaneschepke:amneziawg-android:2.3.7` из Maven Central, сторонний Apache-2.0 fork, не заявление об официальной библиотеке оригинального проекта. При выпуске проверить лицензионные уведомления транзитивных зависимостей.

**Ограничения:** нет always-on/lockdown/kill switch. После отключения VPN Android может использовать обычную сеть — это указано в согласии. Не обещать отсутствие утечек до испытаний IPv4/IPv6/DNS. Сохраняется действующее серверное ограничение профилей аккаунта; переключение устройства/сервера может заменить прежнее подключение. Новый VPN-код не является полным аудитом остальных функций оболочки.

Автотесты, lint и сборки выполнены в Linux. APK/AAB проверены со временным тестовым ключом; сборка Firebase проверяет компиляцию, не доставку уведомлений. **Работа TUN, маршрутизации, энергосбережения и push на физическом устройстве не проверена. До публичного выпуска обязательно пройти раздел 7.**

## 2. Как управлять списком приложений

Единственный исходный файл: `apps/android/vpn-admission-policy.json`. Из него Gradle генерирует и runtime-политику, и точечные `<queries>` манифеста. Редактировать сгенерированные файлы в `build/` не нужно.

Из корня репозитория:

```bash
python3 apps/android/tools/vpn-policy.py list
python3 apps/android/tools/vpn-policy.py add --package com.example.app --label 'Название приложения'
python3 apps/android/tools/vpn-policy.py remove --package com.example.app
python3 apps/android/tools/vpn-policy.py disable
python3 apps/android/tools/vpn-policy.py enable
python3 apps/android/tools/vpn-policy.py validate
python3 -m unittest discover -s apps/android/tools -p 'test_*.py'
```

Команды изменения увеличивают `version` политики. Допускаются только **точные package ID**, не маски, максимум 200 записей. После изменения увеличить Android `versionCode`, собрать и распространить новый APK/AAB. Изменение файла на веб-сервере уже установленное приложение не обновляет. При новой версии политики пользователь снова видит пояснение перед включением.

Начальные записи:

| Package ID | Подпись |
|---|---|
| `com.vkontakte.android` | ВКонтакте |
| `ru.oneme.app` | MAX |
| `com.yandex.browser` | Яндекс Браузер |
| `ru.yandex.searchplugin` | Яндекс |
| `ru.yandex.yandexmaps` | Яндекс Карты |
| `ru.yandex.yandexnavi` | Яндекс Навигатор |

Это конкретные примеры, **не все приложения этих компаний**. Проверять актуальные ID варианта приложения на своём тестовом телефоне: в Play URL параметр `id=...` или локально `adb shell pm list packages`. Для проверки одного ID: `adb shell pm path com.example.app`. Не присылайте полный список установленных приложений и не добавляйте его в серверные логи.

Проверка выполняется локально через PackageManager текущего Android-профиля. Список установленных приложений не отправляется в API; `QUERY_ALL_PACKAGES` не запрашивается. Рабочий профиль, клонирование, root, изменённый клиент и приложения с другими ID ограничивают достоверность проверки. Внешний VPN-профиль или изменённый клиент могут обойти эту политику: сервер не получает доказательства отсутствия приложений.

**Наличие приложения не доказывает перехват трафика. Политика допуска не скрывает IP сервера и не гарантирует защиту от ТСПУ или блокировок.** Проверяйте допустимость такой политики для выбранного канала распространения, не описывайте перечисленные приложения как доказанно вредоносные.

## 3. Подготовка сборки

Нужны JDK 17, Android SDK (platform 36, build-tools 35.0.0; при запросе Gradle установить дополнительную версию), platform-tools, Python 3. Android Studio актуальной версии может установить SDK. На Linux:

```bash
export JAVA_HOME=/путь/к/jdk17
export ANDROID_HOME=/путь/к/android-sdk
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
sdkmanager --licenses
sdkmanager 'platforms;android-36' 'build-tools;35.0.0' 'platform-tools'
python3 apps/android/tools/vpn-policy.py validate
python3 -m unittest discover -s apps/android/tools -p 'test_*.py'
bash apps/android/gradlew -p apps/android --no-daemon --max-workers=2 testDebugUnitTest lintDebug assembleDebug
```

Wrapper скачивает Gradle 8.11.1; AGP 8.10.1/Kotlin 2.2.0 заданы в проекте. Не запускать одновременно тяжёлые Android- и Next.js-сборки на сервере с малым объёмом RAM. Нативные библиотеки поставляются в AAR, локальная сборка NDK для обычного выпуска не требуется. `local.properties` при необходимости содержит `sdk.dir=...` и не публикуется.

Debug: `apps/android/app/build/outputs/apk/debug/app-debug.apk`, пакет `ru.trioz.connect.debug`. Это тестовый клиент, **не релиз**. Для WebMessage API нужен поддерживаемый актуальный Android System WebView; устаревший клиент/WebView не переводится на небезопасный мост. Для VPN используется точный HTTPS-origin `BuildConfig.APP_URL`; HTTP-отладка не даёт доступ к нативному VPN.

### Сначала обновить веб-часть

WebView загружает сайт: одного нового APK со старым JS недостаточно. Развернуть соответствующую версию этого архива на основном проекте. Пример для существующего каталога с правильным origin/main и без несохранённых изменений:

```bash
cd /var/www/trioz &&
git pull --ff-only &&
npm ci &&
npm run migrate &&
NODE_OPTIONS='--max-old-space-size=4096' npm run build &&
pm2 restart trioz --update-env
```

Используйте подходящий проекту Node (в проверке Node 22), сохраните `.env` и пользовательские данные. Команда не предназначена для исправления конфликтов Git. Новых миграций базы для Android VPN нет. Платежи, права подписок, привязки партнёрских проектов и серверное управление peer не переписаны. Дочерний VPN-узел должен уже работать: свежий отчёт агента, правильные endpoint/ключ/параметры AWG, NAT и FORWARD. Подключение Android не исправляет сеть сервера.

## 4. Подписанный APK и AAB

Если приложение уже публиковалось, **сохранить существующий package ID и схему подписи**; versionCode 3 заменить на число выше последнего опубликованного. Новый случайный ключ не позволит обновить установленный APK, подписанный другим ключом.

Для первого выпуска создать upload key вне Git и вне одноразового каталога сборки; команда спросит пароли интерактивно:

```bash
mkdir -p "$HOME/.config/trioz-android"
chmod 700 "$HOME/.config/trioz-android"
keytool -genkeypair -v \
  -keystore "$HOME/.config/trioz-android/upload.jks" \
  -alias connect-upload -keyalg RSA -keysize 3072 -validity 10000
```

Создать `apps/android/app/keystore.properties`, права 600 (не коммитить):

```properties
storeFile=/абсолютный/путь/к/upload.jks
storePassword=ВАШ_ПАРОЛЬ_ХРАНИЛИЩА
keyAlias=connect-upload
keyPassword=ВАШ_ПАРОЛЬ_КЛЮЧА
```

Поддержка подписи **уже есть**, Gradle переписывать не нужно. Сохраните резервную копию ключа и паролей в защищённом хранилище.

```bash
chmod 600 apps/android/app/keystore.properties
bash apps/android/gradlew -p apps/android --no-daemon --max-workers=2 \
  testDebugUnitTest lintDebug assembleRelease bundleRelease
```

Результаты:
- `apps/android/app/build/outputs/apk/release/app-release.apk` — установка вручную/раздача с сайта;
- `apps/android/app/build/outputs/bundle/release/app-release.aab` — загрузка в Google Play, напрямую на телефон не устанавливается.

Без ключа release завершается ошибкой. Автоматического отката на debug нет. Проверка APK:

```bash
"$ANDROID_HOME/build-tools/35.0.0/apksigner" verify --verbose apps/android/app/build/outputs/apk/release/app-release.apk
"$ANDROID_HOME/build-tools/35.0.0/zipalign" -c -P 16 4 apps/android/app/build/outputs/apk/release/app-release.apk
```

Play App Signing разделяет upload key и ключ подписи распространяемого приложения. Если нужны совместимые обновления между сайтом и Play, заранее спланируйте подпись/каналы; APK, подписанный только upload key, не обязательно совместим с APK из Play. Не выкладывайте временный тестовый APK как production.

### Существующий builder

Builder должен работать в **отдельном клоне**, не `/var/www/trioz` с рабочим сайтом. Он очищает Android-каталог сборки. Постоянный конфиг хранить за пределами клона:

```text
/защищённый/каталог/android/keystore.properties
/защищённый/каталог/android/upload.jks
/защищённый/каталог/android/google-services.json   # если нужен push
```

В `keystore.properties` указан абсолютный путь к JKS. Пользователь builder должен иметь доступ только к своим конфигам. В окружении службы builder задать `TRIOZ_ANDROID_CONFIG_DIR=/защищённый/каталог/android`, сохранить существующие `TRIOZ_BUILD_REPO` и `TRIOZ_ARTIFACT_DIR`, перезапустить builder с обновлённым окружением. Скрипт `apps/builder/scripts/build-android.sh` копирует конфиги после очистки; без ключа release не выпускается. Явный `TRIOZ_ANDROID_DEBUG=1` допускается только в тестовом окружении с отдельным каталогом артефактов, чтобы не заменить публичный APK debug-версией. AAB создаётся как `connect.aab`, APK — существующим механизмом `connect.apk`.

## 5. Firebase: только если нужны push-уведомления

Для VPN Firebase **не нужен**. Без `google-services.json` работает вариант без FCM.

1. В Firebase Console создать/выбрать проект, добавить Android-приложение с package `ru.trioz.connect`. Debug при необходимости зарегистрировать отдельно как `ru.trioz.connect.debug`.
2. Скачать подходящий `google-services.json`, разместить в `apps/android/app/` локально или во внешнем каталоге builder. Не включать в выдаваемый исходный архив. Убедиться, что package соответствует варианту сборки.
3. Включить Firebase Cloud Messaging HTTP v1; на сервере использовать отдельную служебную учётную запись с минимально необходимыми правами отправки.
4. В окружении **веб-сервера**, не Android, задать `FCM_PROJECT_ID`, `FCM_CLIENT_EMAIL`, `FCM_PRIVATE_KEY` (PEM; существующий код поддерживает `\n`). Обновить окружение процесса веб-приложения. Приватный ключ service account никогда не помещать в APK, Git, браузер или публичные артефакты.
5. Пересобрать Android. На Android 13+ запросить/разрешить уведомления; войти в аккаунт, проверить регистрацию токена и реальную доставку при открытом приложении, в фоне и после перезапуска.
6. Для сервисов, которым нужны SHA-сертификаты (например, конкретная схема Google Sign-In), внести правильные SHA debug/release и Play **app signing** certificate. FCM сам по себе не требует добавлять SHA как универсальное условие.

Наличие Firebase-конфига и успешная сборка не доказывают доставку. Отдельно проверить вход, выход, смену аккаунта, удаление устройства, открытие чата из уведомления и звонки. Не включать Analytics/другие SDK без корректировки согласий и Data safety.

## 6. Google Play: последовательность выпуска

1. Подтвердить аккаунт разработчика, контактные/организационные сведения и владение приложением; выбрать окончательный package ID до первой публикации.
2. Пройти проверки раздела 7 на подписанном release. Повысить versionCode перед каждой новой загрузкой. Сформировать AAB со своим upload key.
3. Создать приложение в Play Console, настроить Play App Signing, загрузить AAB сначала во **внутреннее тестирование**. Проверить установку именно из Play и обновление поверх предыдущей версии.
4. Заполнить карточку: название, описание без обещаний «неблокируемости», значок, скриншоты настоящего приложения, возрастной рейтинг, категории и контакты.
5. Опубликовать реальную политику конфиденциальности по доступному HTTPS-адресу и добавить ссылку в приложение/Console. Описать не только VPN, но и аккаунт, сообщения, медиа, push и локальную проверку заданных пакетов. «Вообще не собираем данные» для этого проекта неверно. Проверка пакетов остаётся локальной — не означает, что остальное приложение ничего не передаёт.
6. Заполнить Data safety по фактической работе всех SDK и сервера, шифрованию/срокам хранения/удалению. Проверить существующее удаление аккаунта в настройках и backend. В Console дать **действующий внешний URL** инструкции/запроса удаления, доступный без установленного приложения; если такой публичной страницы нет, её нужно создать и проверить до подачи. Не придумывать URL.
7. Заполнить декларацию `VpnService`: объяснить основную пользовательскую функцию, системное согласие, обработку трафика и приложить требуемую демонстрацию. Проверить декларации foreground service `specialUse`, уведомлений и full-screen intent для звонков, если эта функция остаётся в поставке. Если функциональность/политика аккаунта не соответствует требованиям Play, сначала устранить расхождение, не обходить проверку.
8. Приложению с аккаунтом предоставить проверяющему рабочий тестовый вход и действующий доступ к VPN, доступные узлы и точные шаги. Указать условие допуска; не выдавать ложные заявления о поведении сторонних приложений.
9. В Android этой версии экран цифровой подписки **только показывает существующий доступ**: предложение оплаты и переход в Business за покупкой скрыты. Google Play Billing не реализован. Для продаж цифровой услуги внутри Play-приложения требуется отдельно реализовать допустимую схему оплаты. Проверить **все** пути навигации и ссылки приложения перед модерацией: скрытие одного экрана не гарантирует соответствия. Программы альтернативной оплаты/внешних предложений зависят от региона и регистрации в программе, не включаются автоматически.
10. Для личных аккаунтов, созданных после 13.11.2023, применяется требование закрытого тестирования: минимум 12 участников непрерывно 14 дней и запрос production access; свериться с актуальным Console. Для других аккаунтов требования могут отличаться.
11. Проверить отчёты pre-launch, требования target API и 16 KB page size, предупреждения безопасности. После одобрения — постепенный rollout, мониторинг ANR/crash/отзывов, возможность остановить распространение.

**Это инструкция выпуска, не гарантия одобрения Play.** Политика допуска по установленным приложениям требует прозрачного объяснения и отдельной проверки соответствия правилам. Не публиковать до реальных испытаний VPN, настройки собственных ключей, серверной конфигурации и всех обязательных страниц/деклараций.

## 7. Обязательные испытания на устройствах

Записывать результат каждого пункта, версию Android/WebView, версию приложения и проверяемый узел, без приватных ключей/конфигов/полного списка приложений.

- Android 8 (минимальный), 13/14 и 16; минимум одно настоящее устройство. Отдельно устройство/эмулятор с 16 KB page size для нативных библиотек.
- Вход, разрешение VPN (согласие и отказ), повторное включение, отключение из приложения и уведомления; отзыв разрешения/другой VPN. Отказ не должен показывать «подключено».
- Выбор двух разных серверов: endpoint/публичный IP выхода соответствует выбранному узлу. Дождаться свежего handshake и изменения rx/tx **при живом трафике**.
- Проверить сайты по HTTPS, DNS, IPv4/IPv6 и ожидаемые маршруты; отсутствие выхода при наличии handshake — искать NAT/FORWARD/DNS/MTU, а не объявлять успех по значку.
- Wi-Fi ↔ мобильная сеть, airplane mode, выключенный экран, фон/энергосбережение 15–30 минут, уничтожение процесса и повторное открытие. Поведение должно соответствовать отсутствию always-on и kill switch.
- Список допуска: нет запрещённых приложений → подключение разрешено; указанное приложение установлено → отказ; установить его во время VPN → отключение примерно за 3 секунды; удалить → снова разрешено. Отключить политику отдельной тестовой сборкой и проверить отсутствие блокировки. Проверить текущий/рабочий профили и задокументировать границы видимости.
- Два аккаунта на одном телефоне и один аккаунт на двух устройствах: права, ключи и ограничения peer не должны путаться. Подписка отсутствует/истекла/отозвана → сервер запрещает доступ. Активная оплаченная/ручная выдача → правильный пользователь получает доступ.
- Старый WebView/несовместимый мост → понятное требование обновления без небезопасного fallback. Внешняя страница/iframe не получает VPN API.
- Конфигурация AWG совпадает с узлом; не подменять её параметрами другого контейнера. Для дочернего сервера проверить диагностику сети и живой трафик.
- FCM: Android 13+ разрешения, foreground/background, перезапуск, выход/смена пользователя, нажатие уведомления. Вызовы/микрофон/камера/вложения/геолокация — регрессия оболочки после target API 36.
- Production: установка APK и отдельно Play internal AAB, подпись, обновление без потери сессии, удаление аккаунта, privacy/deletion URL, отсутствие недопустимых путей покупки. После удаления приложения локальный VPN-ключ удаляется; следующая установка регистрирует новый публичный ключ.
