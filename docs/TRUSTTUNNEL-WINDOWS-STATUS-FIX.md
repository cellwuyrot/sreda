# Windows: корректное состояние TrustTunnel

## Что изменено

- Состояние службы `TrioZTrustTunnel` в Windows определяется по числовому коду ServiceController через PowerShell, без зависимости от языка и кодировки вывода `sc.exe`. При недоступности основной проверки используется прежний `sc.exe`; неизвестный результат остаётся ошибкой и не считается ни запущенной, ни отсутствующей службой.
- Проверка, начавшаяся до операции запуска или остановки, не может перезаписать более новое состояние. Сообщение об ошибке запуска очищается после последующего подтверждения работающей службы.
- Работающая служба отображается зелёной кнопкой с подписью «Служба TrustTunnel запущена» даже при недоступном API доступа. Работа службы не доказывает подключение к endpoint или прохождение интернет-трафика — это прямо указано в окне. Настройка kill switch, маршруты, профиль, Gateway и агент не менялись.

## Важно для выпуска

Причина конкретного сбоя на ПК пользователя точно не установлена: `sc.exe` показывал RUNNING, а приложение сообщало, что не может проверить службу. Исправление устраняет зависимость от форматирования `sc.exe` и одну гонку, но требует проверки в реальном окружении. Не считать результат проверенным до выполнения проверок ниже.

1. Сохранить резервную копию проекта и БД, обновить web-часть на сервере штатным способом. Для этого исправления нет новой миграции и не нужны изменения turn, endpoint или агента. При рестарте веб-процесса возможен краткий обрыв соединений.
2. Собрать и установить Windows-приложение с версией выше уже опубликованной и установленной; проверить политику обновления и факт отсутствия подписи. Нужны именно обновлённые web и desktop: веб-интерфейс загружается с сервера, проверка службы работает в установленном приложении.
3. На тестовом ПК запустить TrustTunnel; проверить согласованность зелёной кнопки со службой Windows `sc.exe query TrioZTrustTunnel`, затем отдельно проверить доступность сайтов и внешний IP. Зелёный означает только запущенную службу, не проверку интернета.
4. Проверить включение и отключение несколько раз, отмену UAC, реальную остановку службы, отключение из трея без интернета, отсутствие перекрытия с AmneziaWG и обработку недоступного API. Не очищать чужие адаптеры или маршруты. При блокировке интернета остановить локальный TrustTunnel через трей или PowerShell от администратора: `Stop-Service -Name TrioZTrustTunnel`.
5. Проверить откат до предыдущей проверенной версии. Не удалять и не публиковать реальные `.env`, ключи и профили. Локальные unit-тесты не заменяют Windows-сборку и проверку реальной сети.
