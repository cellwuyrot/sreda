# TrioZ Android — результаты первого этапа

## Статус

**Аудит и план подготовлены. Первый тестовый этап реализован. Полностью нативная версия ещё не готова к публичному запуску.** Сервер не обновлялся, production-артефакты не публиковались, установленное приложение и его данные не менялись.

Полный отчёт о недостающих функциях и последовательность приёмки: `AUDIT-AND-PLAN.md` в этой папке.

## Реально добавлено

### Нативное Compose-превью (только debug)

- Постраничная история сообщений каналов и открытых личных диалогов: курсор, загрузка более ранних сообщений, удаление пересечений страниц без сортировки по ID и защита от зацикленного курсора.
- Отправка обычного текста **только в каналы**. Проверка длины по бесплатному/Premium-пределу; сервер продолжает проверять права, бан, slowmode и прочие ограничения.
- Ошибка запроса не очищает набранный текст. После сетевой ошибки/5xx результат может быть неизвестен; автоматического повтора нет, предлагается проверить историю перед ручным повтором. В API каналов пока нет идемпотентной записи, поэтому exactly-once доставка не обещается.
- Отмена HTTP вместе с coroutine, таймауты, ограничение ответа до 4 МиБ, запрет redirect/чужого origin/выхода из `/api/`.
- POST помечен одноразовым: в том числе `503 + Retry-After: 0` не вызывает скрытую повторную запись OkHttp.
- Локальный выход из тестовой сессии, удаление cookie из памяти, новый клиент для следующего входа. Старое WebView-хранилище не читается и не очищается. Это не отзыв всех серверных сессий.
- Цветовая схема Material-компонентов согласована с палитрой превью, включая поля и кнопки в тёмной теме. Это ещё не полный перенос тем проекта.
- Debug-only параметр `-Ptrioz.debugAppUrl=https://ваш-стенд` и адрес сервера на экране входа. Параметр не меняет release-origin.
- Исправлен выявленный тестами конфликт OkHttp: VPN-зависимость разрешала 5.3.0, а старые TLS/mock-библиотеки ожидали внутренности 4.12.0. Версии debug-клиента и его тестовых библиотек согласованы на 5.3.0.

**Личные сообщения остаются без отправки.** Защищённые диалоги и зашифрованный текст не расшифровываются. Вложения, realtime, read receipts, устойчивые черновики и восстановление сессии не реализованы. Черновик хранится лишь до ухода с экрана/закрытия процесса.

### Удалённый сборщик

- Блокировка disposable-клона и каталога публикации через `flock`: два задания не меняют одновременно код/файлы релиза.
- Имя APK не может содержать путь. Каталог публикации должен быть заранее подготовлен с нужным доступом для веб-сервера; скрипт не расширяет права автоматически.
- Перед заменой публичных файлов проверяются **оба непустых** APK и AAB; оба сначала копируются в закрытый staging.
- При обычном сбое публикации выполняется откат; при сбое самого отката предыдущие файлы сохраняются в staging для оператора. Копии конфигурации удаляются и в этом случае.
- Сохранены запрет публичной debug-публикации, `umask 077` и права `0600` для копий конфигурации; публичные файлы имеют `0644`.

Это не полноценная транзакция: SIGKILL/отключение питания между двумя rename ещё могут оставить разные версии APK/AAB. Версионированные релизы с отдельным продвижением, проверка установленной подписи/версии и реальные формы конфигурации/секретов в админке **остаются в плане**, а не объявляются сделанными.

## Что не проверено и блокирует приёмку

- Нативные личные/групповые звонки, E2EE-миграция, отправка ЛС, вложения, офлайн/realtime, весь профиль и админка.
- Работа с реальным сервером/БД, настоящим builder и FCM, приём уведомлений на устройстве, VPN-туннель/утечки/смена сети.
- Установка, UI-взаимодействия на телефоне, фон/Doze/process death и обновление поверх действующего release без потери ключей и истории.
- Пентест, доступность, соответствие темам проекта и performance/battery-приёмка.

## Тестовый APK

`TrioZ-native-stage1-debug.apk`: package `ru.trioz.connect.debug`, versionName `0.4.0`, versionCode `3`, minSdk 26, targetSdk 36. Собран **без Firebase-конфигурации**; доставки FCM в этом APK нет. Это не обновление production-приложения и не полностью нативный релиз.

Обычная иконка по-прежнему запускает прежний WebView-клиент. Нативное превью запускается отдельно:

```bash
adb install -r TrioZ-native-stage1-debug.apk
adb shell am start -n ru.trioz.connect.debug/ru.trioz.connect.nativeui.NativePreviewActivity
```

Если на устройстве уже есть debug-приложение с другой подписью, обновление не пройдёт. **Не удаляйте приложение и не очищайте данные ради обхода ошибки подписи.** Сначала определите установленный пакет и сохранность данных.

В переданном APK origin по умолчанию `https://trioz.ru`. Кнопка отправки создаёт реальное сообщение; запрос списка сообществ может запустить существующее серверное автоприсоединение. Для испытаний используйте отдельный тестовый аккаунт/сообщество, предпочтительно пересоберите APK для вашего staging. Пароли и production-ключи не отправляйте в чат.

## Повторение проверок

После `npm ci`, генерации Prisma Client и установки JDK 17/SDK 36/build-tools 35.0.0:

```bash
npx prisma generate --schema apps/web/prisma/schema.prisma
./scripts/test-android-launch.sh
```

Для отдельного staging APK:

```bash
cd apps/android
./gradlew -Ptrioz.debugAppUrl=https://staging.example.org :app:assembleDebug
```

Замените пример своим HTTPS-origin. Скрипт проверок не публикует файлы, не устанавливает APK и не входит в аккаунты TrioZ. Отдельная проверка production-подписи и обновления выполняется позднее на стенде.
