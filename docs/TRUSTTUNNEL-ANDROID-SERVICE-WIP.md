# Android TrustTunnel: экспериментальная интеграция — не релиз

Android debug теперь содержит отдельный экспериментальный сервис, мост и панель в окне VPN. Панель не зависит от подписки Premium, но появляется только при успешной проверке сервером роли ADMIN проекта и allowlist. Администратор группы не получает доступ автоматически. Глобальный провайдер не переключается; выпуск Android release не входит в этот эксперимент. Оба серверных флага отключены по умолчанию. **Не включайте пилот, пока не завершены остальные блокеры из `TRUSTTUNNEL-PILOT-SNAPSHOT-WIP.md`.**

Профиль выдаётся по POST с новой проверкой аккаунта и аудитом; секрет не выводится на экран. Мост принимает сообщения только из основного фрейма доверенного origin. Это не защищает от XSS на доверенном сайте; проверить безопасность сайта и журналов. Конфиг в памяти содержит пароль, уничтожение памяти не гарантировано. Отзыв выдачи не отзывает уже выданный пароль на Endpoint.

`apps/android/app/libs/trusttunnel-test.aar` собран локально из официального TrustTunnelClient v1.1.12, commit `067deb837ed994d6ae902e3bb40b69f6266af216`; SHA-256 `22033cea3f93c379071563073116ad7db1120049d1875eace39c789579efcc62`. Исходная лицензия проекта находится в `docs/licenses/TrustTunnelClient-1.1.12-APACHE-2.0.txt`; проверить также условия всех включённых транзитивных компонентов перед распространением. AAR пока содержит только **arm64-v8a**, поэтому debug APK ограничен этой архитектурой, Android 8.0+. Это локально собранный debug SDK, а не проверенный подписанный официальный бинарный релиз. Профиль намеренно привязан к `turn.trioz.ru` и `170.168.18.20:8443`; изменение адреса потребует обновления валидатора и сборки. TCP/HTTP2, TLS-проверка не отключается.

Для исключения конфликтов проверяется состояние Amnezia и запрос системного разрешения. TrustTunnel защищает свои исходящие сокеты через `VpnService.protect`; трафик самого приложения не исключён из VPN. Локальные/LAN диапазоны исключены из маршрутов. При отключении VPN Android может вернуться к обычной сети; kill switch не подтверждён на устройстве. Состояния, гонки при отказе разрешения, lifecycle, сеть, сертификаты, DNS, маршруты, отзыв и секреты остаются для реальной проверки и доработки. Логирование SDK перенаправлено в пустой обработчик; полный аудит логов ещё нужен.

Проверено в изолированной среде: `:app:assembleDebug` и два unit-теста формата профиля прошли; в APK присутствуют SDK и запись сервиса. Пять UI-тестов с фиктивным мостом/ответами прошли. Это не установка APK, не проверка устройства и не проверка связи. Генерируемый push-debug манифест включает оба debug-компонента; полный push APK с настоящим google-services.json не собирался. Исходный Android release отдельно падает на отсутствии Compose Runtime в classpath, та же ошибка была воспроизведена на исходной версии; пользователь просил debug.
