# Исправления по итогам аудита безопасности (август 2026)

Документ описывает, что изменено и что нужно сделать при выкатке. Все правки
помечены в коде комментариями `FIX-SEC` / `FIX-CSP` / `FIX-RNG` — их можно
найти поиском по репозиторию.

Голосовой тракт (TURN/coturn, `turnserver.conf`, выдача учётных данных в
`/api/voice/turn`, логика голосовых комнат в `server.ts`) НЕ трогался — по решению
владельца проекта.

## 1. Аутентификация и сессии

- `src/lib/auth.ts`: ограничение попыток входа — 20 с IP и 10 на учётную запись за
  15 минут. Раньше перебор пароля не ограничивался ничем.
- Срок сессии сокращён до 2 суток с обновлением раз в час; `useSecureCookies`
  включается автоматически при https-адресе.
- Смена пароля теперь гасит все старые сессии: поле `User.passwordChangedAt`,
  проверка в callback сессии (кеш 30 с).
- `/api/auth/register`: проверка типов, формата почты, длины имени и
  ОБЯЗАТЕЛЬНЫЙ код подтверждения почты (раньше код можно было не присылать).
- `/api/auth/reset-password`: больше не различает «пользователь не найден» и «код
  неверен» — ответ общий (нет перебора адресов).

## 2. Права доступа

- `/api/groups/[id]/transfer-ownership`: добавлены проверка бана, лимит (5/час) и
  валидация типа `memberId`.
- `server.ts`: кеш членства в сокете — 60 → 15 секунд (окно, когда исключённый
  ещё читает переписку, короче вчетверо).
- `server.ts`: строгая выдача вложений (`UPLOADS_STRICT`) теперь включена ПО
  УМОЛЧАНИЮ; отключается явно через `UPLOADS_STRICT=0`.

## 3. Криптография

- `src/lib/e2ee.ts`: общий ключ теперь выводится через HKDF-SHA256, а не берётся
  сырыми битами ECDH (формат `e2ee:v2:`). Старые сообщения и файлы читаются
  по-прежнему (автоматический откат к legacy).
- Исправлена ошибка двойного `JSON.stringify` при импорте ключей; экспорт
  больше не «чинит» ситуацию тихой генерацией новой пары ключей.
- `/api/e2ee`: строгая проверка JWK (только публичная часть EC P-256, отказ при
  наличии `d`), лимиты, отпечаток ключа в ответе и подтверждение при замене
  существующего ключа (защита от тихой подмены собеседника), запись в журнал
  действий.
- `src/lib/games/random.ts`: исход игровых бросков считается через
  `crypto.getRandomValues`, а не `Math.random()`.

## 4. Входные данные

- `/api/dm/read`: убран `$executeRawUnsafe` — заменён обычным `prisma.update`.
  Сырых SQL-запросов со склейкой строк в коде больше нет.
- `src/lib/sanitize.ts`: однократное декодирование HTML-сущностей без повторного
  прохода и вырезание невидимых символов (подмена имён, обход фильтров).
- `src/lib/fileValidation.ts` + `/api/messages/upload`: у видео и аудио теперь
  проверяются сигнатуры (mp4/webm/ogg/mp3/wav/flac), а не только заявленный MIME.

## 5. Заголовки и CSP

- CSP переехала из `next.config.mjs` в `src/middleware.ts` и теперь использует
  одноразовый nonce вместо `script-src 'unsafe-inline'` (главная защита от XSS
  раньше не работала вовсе). `'unsafe-eval'` остаётся только в режиме
  разработки; `'wasm-unsafe-eval'` сохранён ради шумоподавления.
- `src/app/layout.tsx`: встроенный скрипт темы получает nonce.
- `nginx.conf`: `X-Frame-Options` → `DENY`.

## 6. Инфраструктура

- `nginx.conf`: `X-Forwarded-For` формируется из `$remote_addr`, а не дописывается к
  клиентскому значению; `real_ip_recursive off`. Раньше клиент мог подставить себе
  любой адрес и обойти лимиты или забанить чужой.
- `nginx.conf`: у рабочего блока заданы реальные `server_name` — без этого заглушка
  по Host не работала. Замените на свои имена при переносе.
- `src/lib/clientIp.ts`: единое вычисление адреса клиента с учётом
  `TRUSTED_PROXY_HOPS`; им пользуются и лимиты, и идентификация устройств.
- `deploy/fail2ban/filter-trioz-auth.conf`: пояснено, почему фильтр не ловит перебор
  пароля (NextAuth отвечает 302) и что теперь его останавливает.
- `.env.example`: убраны `admin123` / `user123` / `trioz_secret`; описаны
  `TRUSTED_PROXY_HOPS` и `UPLOADS_STRICT`.

## 7. Electron

- `electron-builder.yml`: `verifyUpdateCodeSignature: true` и памятка про `CSC_LINK`.
- `src/main/updater.ts`: запрет понижения версии и черновиков
  (`allowDowngrade = false`, `allowPrerelease = false`).

## 8. Android

- `android:allowBackup="false"` — cookie сессии и токен доставки больше не уезжают в
  резервную копию.
- `network_security_config.xml`: разрешение HTTP для localhost перенесено в
  `<debug-overrides>`.
- `MainActivity.kt`: выключены сторонние cookie и
  `javaScriptCanOpenWindowsAutomatically`.
- `NotificationBridge.kt`: каждый метод моста проверяет, что страница — нашего
  адреса. Раньше любой документ в WebView мог показывать уведомления от имени
  мессенджера и читать `pushToken()`.

## Что сделать при выкатке

1. `npm ci`
2. `npx prisma migrate deploy` — ОБЯЗАТЕЛЬНО: добавлено поле
   `User.passwordChangedAt` (миграция `20260915000000_user_password_changed_at`),
   и сброс пароля без неё упадёт.
3. `npm run build`
4. Переменные окружения: добавить `TRUSTED_PROXY_HOPS` (1, если впереди только наш
   nginx). Проверить, что `UPLOADS_STRICT` не выставлен в `0`.
5. `nginx -t && systemctl reload nginx`; `fail2ban-client reload`.
6. Для десктоп-сборок — выдать CI переменные `CSC_LINK` и `CSC_KEY_PASSWORD`.

## Что НЕ сделано сознательно

- TURN/coturn и модель выдачи учётных данных голоса — по решению владельца.
- Обновление зависимостей (в том числе Electron 33, который уже вне поддержки) —
  требует сети и прогона тестов.
- Android: перевод `PushService` на `EncryptedSharedPreferences` — нужна новая
  зависимость `androidx.security`.

> Правки не компилировались и не прогонялись тестами: сборка требует установки
> зависимостей из сети. Перед выкаткой обязательно прогоните `npm run build`
> и проверьте вход, регистрацию, отправку файлов и личные переписки.
