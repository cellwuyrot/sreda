# Sreda / TrioZ — исправления по техническому ревью

Дата: 2026-10-27. Это отчёт об изменениях, а не прежний read-only аудит.

## Итог

Внесены исправления прав доступа календаря, SSRF-защиты превью, таймаута чтения картинки, локального хранения и импорта E2EE-ключей, жизненного цикла защищённых чатов, контроля версий холста, индекса вложений и доверия к Electron IPC. Добавлены регрессионные тесты и обязательные проверки CI. Сохранены исправления первоначальных пяти пользовательских багов.

**Не следует трактовать эту поставку как безусловную готовность production.** T06 закрыт в части правдивого UX, а не полноценного восстановления неизвлекаемых ключей; T09 требует проверки миграций на копии реальной БД; T10 ограничивает установку одним realtime-процессом, но не реализует распределённый realtime; T13 требует настройки coturn; T14 ещё требует испытаний нативных возможностей на целевых ОС.

## Дополнительно: целостность рабочих сред

Файлы: `apps/web/src/app/api/workspace/route.ts`, `apps/web/src/app/api/channels/[id]/workspace/route.ts`, `apps/web/src/components/workspace/WorkspaceCanvas.tsx`, `apps/web/src/lib/workspaceMerge.ts`, новый `workspaceValidation.ts`.

- PUT требует `baseUpdatedAt`: `null` означает только создание, строка — версию полученного снимка. Отсутствующая версия даёт **428**, конфликт — **409**. В БД запись условная по владельцу + updatedAt, без безусловного upsert; timestamp увеличивается монотонно для успешной записи.
- При конфликте клиент получает серверный снимок, выполняет трёхстороннее слияние base/local/remote и повторяет сохранение через debounce.
- Отслеживаются удаления, переименования, новые пустые доски и правки карточек/связей; удаляются висячие связи. Независимое перемещение карточки не отменяет удалённое переименование доски. Камера каждого известного холста остаётся локальной.
- Правило конфликта edit/delete: изменённый объект сохраняется. Одновременные изменения одной и той же карточки разрешаются в пользу локальной карточки. Это **не CRDT и не посимвольное совместное редактирование**: слияние разных полей одной карточки не гарантируется. Лимит пяти досок не обходится слиянием; превышение отвергается, а не обрезается с потерей данных.
- Сервер валидирует v3, доски, активную доску, типы и основные payload-поля карточек, связи, координаты/масштаб и таймер. Лимиты снимка считаются в UTF-8 байтах. Это не универсальный валидатор всех будущих расширений схемы.
- Групповой IDB-кеш теперь разделён по userId/channelId. Явный 401/403 не разрешает показ кеша; текущие карточки очищаются, отложенная запись блокируется. Без полученной версии серверное сохранение не выполняется. Запоздавший снимок старше подтверждённой версии игнорируется; после повторного подключения сокета запрашивается актуальное состояние.
- Legacy v2 читается клиентом и преобразуется в v3; старый клиент без baseUpdatedAt больше не может перезаписать данные.

## Испытания

Полный Vitest: **2356 passed, 168 файлов, 0 failed, 0 skipped**. Команда: `npm run test -w apps/web -- --maxWorkers=2`.

Проверки охватывают:
- отрицательные ACL календаря и общего холста;
- условные записи personal/group workspace, отсутствие версии, malformed payload и create-only конфликт;
- слияние независимых изменений, удалений/переименований/пустых досок и локальных камер;
- смешанный DNS, IP pinning HTTP lookup, отказ до открытия сокета, hung DNS, slow body и закрытие upstream;
- account-isolation, legacy adoption, отказ/неоднозначное завершение импорта, неверную пару и backup чужого аккаунта, версии кеша shared key;
- запрет массового beacon-delete и область явного удаления;
- отзыв доступа к тому же вложению и отказ индекса;
- TURN REST credential/URI и проверку origin/frame/window привилегированного IPC;
- первоначальные UI-регрессии и существующие тесты проекта.

Браузер Chromium 153: реальный ввод в autoFocus-поле; вход/выход из нативного Fullscreen API; два WebRTC-сценария recvonly без микрофона (слушатель — инициатор и отвечающий), в обоих получена audio track и установлено ICE-соединение. Проверены настоящие WebCrypto + IndexedDB: разные аккаунты, невозможность экспорта nonextractable, сохранение старого active при отказе, восстановление pending после потери ответа. Это изолированный локальный стенд с тестовыми API-ответами, **не полный пользовательский E2E production-приложения** и не NAT/TURN-тест.

Сырые журналы и JSON-результат находятся в `checks/`. Итог по build/typecheck/lint — в `VALIDATION.md`.

### Почему теперь нет прежнего 21 падения

В предыдущей поставке 21 падение воспроизводилось и на исходном архиве. Исправлены устаревшие фикстуры/ожидания, а не ослаблены проверки или бизнес-правила:
- DM-list ожидает действующий фильтр PERSONAL + SECURE;
- notification-тест учитывает имя Socket.IO события;
- upload MIME-тесты явно мокают отдельный signature-validator; реальные проверки сигнатур продолжают тестироваться отдельно;
- календарные тесты мокают канонические права;
- VPN-тесты корректно работают со строковым конфигом, сравнивают точную команду route, имена бинарников текущего vendor-скрипта и PowerShell-кавычки;
- тест даты подписки фиксирует время, а не зависит от дня запуска.

Полный `npm run test:types -w apps/web` остаётся отдельным техническим долгом: расширенный tsconfig захватывает ошибки типов тестовых фикстур и деклараций matchers, включая регрессионные тесты первого этапа. Production-typecheck не отключался и проходит; тесты выполняются Vitest полностью. Ни `skip`, ни исключение падающих runtime-тестов для получения зелёного результата не добавлялись.

## Что ещё не доказано / не реализовано

1. **PostgreSQL.** Здесь не было PostgreSQL/Docker для проверки clean migration и обновления существующей БД. Историю нельзя объявлять согласованной только по смене команды deploy. Мокированный CAS-тест проверяет условие запроса, а не блокировки настоящего PostgreSQL.
2. **Много участников.** Нужен двухбраузерный интеграционный прогон на настоящем сервере с БД, delayed/out-of-order ответами, потерей сокета и восстановлением сети. Изолированные merge/API-тесты не заменяют его. Таймер и пользовательская камера не стали распределёнными операционными структурами.
3. **E2EE recovery.** Неизвлекаемый утраченный приватный ключ восстановить невозможно. История старых пар сохранена локально, но автоматический выбор исторического ключа при чтении старых сообщений не реализован. Нет нового key-id протокола, device provisioning или escrow. Без Web Locks доступна только same-tab очередь + серверный CAS, не полноценная межвкладочная транзакция.
4. **Защищённые чаты.** Автоматическое удаление на закрытии вкладки намеренно заменено явным удалением конкретного разговора. Серверный TTL/срок хранения не добавлен. Не обещать пользователю исчезновение истории по закрытию окна.
5. **SSRF.** Фильтр защищает указанные preview-маршруты; другие внешние интеграции не переведены автоматически на externalFetch. Нужны egress firewall/прокси и стендовые HTTPS/SNI, DNS-rebinding, redirect и load-тесты. Сжатые ответы не распаковываются этим helper: запрашивается identity.
6. **Вложения.** Уже скачанные файлы нельзя «отозвать». Старые ответы с прежним Cache-Control могут жить до истечения их TTL. Существующая политика доступа загрузившего и документов услуг не изменена. После сбоя индекса возможен файл-сирота на диске: безопасная уборка без удаления используемых файлов требует отдельной сверки.
7. **Redis.** noeviction предпочитает явный отказ записи тихому вытеснению lock/counter. Нужны мониторинг памяти и проверка degraded/fail-closed поведения зависимых функций. Runtime healthcheck с реальным Redis здесь не запускался.
8. **TURN.** Требуется одинаковый новый секрет на web/coturn, правильный listener/realm/network/firewall. Static fallback не исчезает без перенастройки. Длинный вызов за сроком credential, allocation refresh, ICE restart, мобильная сеть и NAT требуют испытания на coturn-стенде.
9. **Desktop.** Проверены типы, чистая policy и mocked IPC; не запускались полноценный Electron, installers, WASAPI, системные permission dialogs и захват экрана Windows/macOS/Linux.
10. **Резервные копии/нагрузка.** Не выполнялись реальные восстановление БД/вложений, нагрузочный тест, аудит всех интеграций или независимый криптоаудит.

Инструкция внедрения и отката: [ROLLOUT-RU.md](./ROLLOUT-RU.md). Исторический read-only отчёт сохранён рядом отдельно; его открытые статусы не являются статусами этой поставки.
