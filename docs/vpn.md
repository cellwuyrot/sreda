# VPN в TrioZ: узел на сервере и подключение «по кнопке»

Кодовый маркер клиентской части: `VPN-ONECLICK`.

Этот документ — практическое руководство: как поднять VPN-узел на сервере и как
пользователю включить туннель одной кнопкой в приложении. Устройство серверной
части (модель «на вытягивание», ключи) подробно описано в
[`apps/vpn/README.md`](../apps/vpn/README.md); здесь — сжатая инструкция и то, что
появилось с одно-кнопочным включением.

## Из чего состоит VPN

```
┌ Устройство пользователя ────────────┐        ┌ Главный сервер (apps/web) ─┐
│ TZ Connect (десктоп-оболочка)        │  HTTPS │ /api/vpn/me — выдаёт        │
│  • генерирует пару ключей X25519     │ ─────► │   публичные данные пира    │
│  • public → серверу, private остаётся│        │ /api/servers/report —      │
│  • поднимает туннель ВСТРОЕННЫМ    │        │   раздаёт узлам их пиров    │
│    wireguard-go по кнопке «Вкл»      │        └───────────┬────────────────┘
└───────────────┬──────────────────────┘                    │ «на вытягивание»
                │ WireGuard/AmneziaWG (UDP)                  ▼
                └────────────────────────────►  ┌ VPN-узел (apps/vpn) ───────┐
                                                 │ wg0, агент тянет список     │
                                                 │ пиров и приводит к нему     │
                                                 └─────────────────────────────┘
```

Три участника:

- **Главный сервер** (`apps/web`) — хранит пиров, назначает адреса, отдаёт
  клиенту данные для профиля (`GET/POST /api/vpn/me`) и раздаёт узлам их списки
  пиров (`POST /api/servers/report`). Сам туннель он не поднимает.
- **VPN-узел** (`apps/vpn`) — отдельная Linux-машина с `wireguard-tools` (или
  AmneziaWG). Раз в минуту приходит к главному серверу с отчётом и получает
  список своих пиров, приводя к нему интерфейс `wg0`. Входящего API у узла нет —
  он спокойно живёт за NAT.
- **Клиент** — десктоп-оболочка TZ Connect. С `VPN-ONECLICK` она **сама
  поднимает туннель**: генерирует ключи, регистрирует публичную половину и по
  кнопке «Включить» отдаёт готовый профиль main-процессу, который запускает
  ВСТРОЕННЫЙ `wireguard-go` из ресурсов приложения (на всех трёх ОС).
  Ни файла-профиля, ни стороннего клиента пользователь не скачивает.

> **Ключевой инвариант.** Приватный ключ создаётся на устройстве владельца и
> никуда не уходит по сети. Сервер знает только публичные ключи и выданные
> адреса. Поэтому «выдать чужой доступ» технически нечем.

## Часть 1. Установка VPN-узла на сервере

Требуется Linux и Node 20+. Для обычного WireGuard — пакет `wireguard-tools`;
для устойчивого к блокировкам — AmneziaWG (`amneziawg-tools`, бинарник `awg`).

### 1.1. Поставить инструменты

```bash
# Обычный WireGuard
apt update && apt install -y wireguard-tools

# Включить форвардинг пакетов (нужно для выхода клиентов в интернет)
sysctl -w net.ipv4.ip_forward=1
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-trioz-vpn.conf
```

### 1.2. Поднять интерфейс `wg0`

Агент не создаёт интерфейс — он им управляет. Поднимите `wg0` заранее, **без
секции `[Peer]`**: пиров добавит агент.

`/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PostUp = wg set %i private-key /etc/wireguard/trioz-private.key
# NAT для выхода клиентов (замените eth0 на свой внешний интерфейс)
PostUp = iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE
PostDown = iptables -t nat -D POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE
```

Приватный ключ узла в конфиг **не вписывается**: агент создаёт его при первом
запуске и подставляет строкой `PostUp`. Первый запуск:

```bash
wg genkey > /etc/wireguard/trioz-private.key
chmod 600 /etc/wireguard/trioz-private.key
wg-quick up wg0
systemctl enable wg-quick@wg0
```

Откройте UDP-порт `51820` (или свой) на файрволе и у хостера.

### 1.3. Зарегистрировать узел в админ-панели

В админ-панели: **Сервисы и система → Серверы → Добавить узел**, назначение
**VPN**. Скопируйте токен агента — он показывается один раз. Там же задаётся
**точка подключения** — IP или домен машины, куда клиенты стучатся по UDP (порт
можно опустить, подставится `51820`).

### 1.4. Запустить агент (systemd)

Разложите репозиторий в `/opt/trioz` и создайте
`/etc/systemd/system/trioz-vpn-agent.service`:

```ini
[Unit]
Description=TrioZ VPN agent
After=network-online.target wg-quick@wg0.service
Wants=wg-quick@wg0.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/trioz
Environment=TRIOZ_MAIN_URL=https://example.ru
Environment=TRIOZ_AGENT_TOKEN=<токен из панели>
Environment=WG_ENDPOINT_HOST=vpn1.example.ru
ExecStart=/usr/bin/node /opt/trioz/apps/vpn/src/index.mjs
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now trioz-vpn-agent
journalctl -u trioz-vpn-agent -f
```

Полный список переменных окружения и режим устойчивости к блокировкам
(AmneziaWG) — в [`apps/vpn/README.md`](../apps/vpn/README.md).

### 1.5. Включить сервис в панели

VPN по умолчанию **выключен**. В админ-панели включите сервис (**Сервисы и
система → VPN**), иначе новым пирам доступ не выдаётся, а узлам уходит пустой
список пиров.

### 1.6. Проверка

```bash
wg show wg0                          # текущие пиры и рукопожатия
journalctl -u trioz-vpn-agent -n 50  # 401 = токен отозван/узел выключен
```

Узел в панели должен показывать статус «на связи» и назначение **VPN**.

## Часть 2. Подключение пользователя «по кнопке»

### 2.1. Что нужно на устройстве

**Ничего устанавливать не нужно.** Клиент туннеля встроен в приложение TZ Connect
и лежит в его ресурсах (`resourcesPath/wireguard`), поэтому включение работает
сразу после установки приложения. В браузере системный туннель поднять нельзя —
там значок «TZ» просто откроет окно и предложит приложение.

| ОС | Что кладётся в установщик | Чем поднимается туннель |
|---|---|---|
| Windows | `wireguard-go.exe`, `wintun.dll` | встроенный `wireguard-go.exe` как обычный процесс + настройка через именованный канал UAPI, адреса/маршруты/DNS — штатный `netsh` |
| Linux | `wireguard-go` | встроенный `wireguard-go` + настройка через UAPI-сокет, маршруты через `ip` под `pkexec` |
| macOS | `wireguard-go` | то же, права — через `osascript` |

> **Никаких служб и чужих окон.** До этой правки на Windows в ресурсы клался
> официальный `wireguard.exe` и туннель ставился службой `WireGuardTunnel$trioz`.
> Такой вызов работает только при установленном стороннем WireGuard: без его
> службы-менеджера кнопка падала с «The specified service does not exist as an
> installed service», а любой непонятный аргумент `wireguard.exe` показывал окно
> WireGuard. Сейчас Windows идёт тем же путём, что Linux и macOS: свой процесс,
> своя настройка, ни одной сторонней службы. Если прежняя сборка успела создать
> службу, её надо убрать: `sc delete WireGuardTunnel$trioz` в консоли администратора.

Как это собрано:

- `apps/desktop/scripts/vendor-wireguard.mjs` (`npm run vendor:client`, входит в
  `npm run build`) раскладывает бинарники из `TRIOZ_CLIENT_SRC` в
  `apps/desktop/resources/wireguard/<платформа>/`;
- `electron-builder.yml` переносит их через `extraResources` — **вне** `app.asar`,
  иначе файл нельзя было бы запустить;
- `src/main/vpnHelper.ts` — работник с правами root: запускает встроенный клиент,
  отдаёт ему настройки по UAPI и поднимает интерфейс с маршрутами;
- `src/shared/vpnEmbedded.ts` — чистая логика (разбор профиля, UAPI-запросы,
  команды интерфейса), она под тестами.

> **Почему бинарники не в git.** Три платформы — это десятки мегабайт в истории
> репозитория навсегда. Источник задаёт тот, кто собирает релиз; сборка без
> клиента возможна (`--allow-missing`), но включение в ней честно скажет, что
> клиента в этой сборке нет.
>
> **Права ОС всё равно спросят.** Поднятие сетевого интерфейса — операция уровня
> системы, её нельзя сделать молча. Но это одно подтверждение UAC/polkit/пароля,
> а не установка сторонней программы.

### 2.2. Как включить

1. Откройте в приложении окно **Защищённое соединение** (значок «TZ» / Premium).
2. Выберите режим:
   - **Весь трафик компьютера** — через сервер идёт всё, внешний адрес меняется.
   - **Только приложение TZ** — в туннеле только TZ, остальной интернет идёт
     напрямую (в приложении это выбор по умолчанию).
3. Нажмите **круглую кнопку** в этом окне — или сразу значок **«TZ»** в левой
   панели, он и есть выключатель (правая кнопка по значку открывает окно с
   подробностями). Приложение:
   - создаст пару ключей и зарегистрирует публичную половину;
   - соберёт профиль в памяти и передаст его оболочке;
   - оболочка поднимет туннель (Windows/Linux/macOS попросят подтвердить права
     — UAC / polkit / пароль администратора).
4. Индикатор станет зелёным — «Соединение активно».

При первом подтверждении прав ОС спросит разрешение — это нормально: без него
интерфейс поднять нельзя.

### 2.3. Как выключить, сменить сервер, отозвать доступ

- **Выключить соединение** — снимает туннель локально. Запись о доступе на
  сервере остаётся, включить снова можно одной кнопкой.
- **Смена сервера** — если туннель поднят, он сам переедет на новый узел (адрес
  и точка подключения в профиле меняются, поэтому пересобирается новый профиль).
- **Отключить и удалить доступ на этом аккаунте** — снимает туннель и удаляет
  пира на сервере (узел уберёт его при следующем отчёте). Нужно, когда уходите с
  устройства насовсем.

При выходе из приложения туннель снимается автоматически — иначе в режиме «весь
трафик» закрытое приложение оставило бы машину замкнутой на сервер без окна,
чтобы это отменить.

### 2.4. Диагностика на клиенте

- **«Встроенный клиент не найден в ресурсах приложения»** / **«Встроенный клиент
  отсутствует в этой сборке»** — приложение собрали без шага `vendor:client`.
  Пересоберите: `TRIOZ_CLIENT_SRC=… npm run vendor:client:strict && npm run dist`.
- **«Встроенный клиент не успел поднять сетевое устройство»** — клиент запустился,
  но интерфейс не появился: чаще всего мешает уже поднятый туннель с тем же
  именем (`trioz`) от другого клиента.
- **«Не выданы права …»** — вы отклонили запрос UAC/polkit. Повторите включение.
- **Индикатор долго «Подключаем…»** — узел поднят, но рукопожатия нет: проверьте,
  что UDP-порт узла открыт и точка подключения в панели указывает на этот сервер.
- **«Сервис отключён администратором»** — включите VPN в админ-панели (см. 1.5).
- **«Узлы ещё не готовы»** — ни один узел не отчитался; проверьте агент (1.6).

## Кто и где хранит ключи (коротко)

| Ключ | Где создаётся | Кто видит |
|---|---|---|
| Приватный ключ **узла** | на узле при первом запуске агента | только узел (файл `600`) |
| Публичный ключ **узла** | производный | сообщается серверу, попадает в профили |
| Приватный ключ **пользователя** | в приложении при включении | **только устройство** (файл туннеля `600`) |
| Публичный ключ **пользователя** | производный | сервер и узел |

Один аккаунт — один пир. Повторное включение перевыпускает ключ и отключает
прежнее устройство.

## Служебный компонент туннеля (SERVICE-TUNNEL)

С этой версии VPN — это обычное сетевое устройство системы: адаптер `trioz`
(драйвер Wintun) виден в «Сетевые подключения» и в `Get-NetAdapter`, через него
идёт весь трафик. Никакие сторонние приложения и службы (WireGuard, Amnezia
и т.п.) не нужны и не используются.

### Кто создаёт адаптер

Создание сетевого адаптера в Windows — операция уровня ядра, она невозможна без
прав системы. Поэтому права запрашиваются ОДИН раз — установщиком, который
регистрирует наш собственный служебный компонент:

| Что | Где |
| --- | --- |
| Задание автозапуска | `TriozTunnelAgent` (Планировщик заданий, запуск от SYSTEM) |
| Пускатель | `<папка установки>\resources\tunnel-agent.cmd` |
| Код компонента | `apps/desktop/src/main/tunnelAgent.ts` |
| Канал обмена | `C:\ProgramData\TrioZ\tunnel` |
| Лог клиента | `%APPDATA%\trioz-connect\trioz-client.log` |

После установки кнопка TZ не показывает окно UAC вообще: приложение кладёт в
канал обмена файл-заявку `request.json`, компонент поднимает туннель и
отвечает `status.json`. Если компонента нет (старая сборка, задание удалили
вручную), приложение автоматически возвращается к разовому повышению прав,
чтобы не остаться совсем без VPN.

### Почему заявка содержит только профиль

Каталог `C:\ProgramData\TrioZ\tunnel` открыт на запись обычным пользователям, а
исполняет заявки процесс с правами системы. Поэтому:

* в заявке нет путей к программам и аргументов — иначе любой местный
  пользователь получил бы выполнение своего кода от SYSTEM;
* клиента туннеля компонент берёт только из своих ресурсов (`resources\wireguard`);
* текст профиля проверяется `isSafeConfigText` (ограниченный набор символов и
  размер) — значения попадают в аргументы `netsh`.

### Почему компонент сам сообщает о связи

UAPI-канал клиента создаётся процессом SYSTEM и обычному пользователю закрыт.
Если окно спрашивает клиента напрямую, оно всегда получает «нет ответа» — именно
так рождалось сообщение «Туннель поднят, но связи с VPN-узлом нет» на рабочем
туннеле. Теперь компонент каждые 5 секунд пишет время рукопожатия в
`tunnel.json`, и окно судит о связи по нему. Отсутствие сводки по-прежнему
НЕ считается успехом.

### Проверка на своём ПК (PowerShell)

```powershell
schtasks /Query /TN "TriozTunnelAgent"           # задание есть и выполняется
Get-Content "C:\ProgramData\TrioZ\tunnel\agent.json"   # компонент жив, отметка свежая
Get-NetAdapter -Name trioz                        # адаптер в сетевых устройствах
Get-NetIPAddress -InterfaceAlias trioz            # адрес 10.8.0.x
Get-Content "C:\ProgramData\TrioZ\tunnel\tunnel.json"  # время рукопожатия
(Invoke-RestMethod https://api.ipify.org?format=json).ip  # адрес узла, не свой
```

На сервере в этот момент должно появиться рукопожатие: `wg show wg0` — строка
`latest handshake`, и `tcpdump -ni ens3 udp port 51820` — ненулевой трафик.
