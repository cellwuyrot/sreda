# Обновление чатов сообществ

Основа: `sreda-main-amneziavpn-ci-fixed.zip`. Обновление не устанавливалось на trioz.ru и не подключалось к production-БД.

## Что изменено

- Позиция чтения сохраняется по ID первого видимого сообщения и его смещению, а не расстоянию до низа. Якорь учитывается при обновлении высот распорок, изменении границ окна, добавлении и догрузке сообщений.
- Видимое сообщение остаётся смонтированным при включении виртуализации и изменении массива истории. ResizeObserver компенсирует позднюю загрузку вложений и изменение высоты строк.
- В сообществах убран второй слой приблизительных высот `content-visibility` поверх оконного рендера. Сам оконный рендер сохранён. Автоматический browser scroll anchoring отключён для этого контейнера, чтобы не конкурировать с программным якорем.
- Автопрокрутка вызывается при изменении последнего сообщения, а не при каждой реакции, отметке прочтения или догрузке сверху. Начало прокрутки вверх немедленно отключает следование за низом.
- Повторные запросы одной страницы объединяются; сообщения объединяются по ID с устойчивым порядком при одинаковых датах.
- Переподключение сокета больше не заменяет читаемую историю последними 50 сообщениями.
- Переход к старому сообщению запрашивает ограниченный участок вокруг его ID. Лимита в 8 последовательных страниц нет. Проверяются права канала; удалённая/недоступная цель вызывает понятную ошибку.
- Для найденного участка поддержаны догрузка более ранних и более поздних сообщений, а также возврат к актуальному концу чата.
- В поиске слева добавлена кнопка «Показать более старые сообщения», курсорная пагинация, защита от устаревших ответов и сообщение об ошибке запроса.
- Кнопка «Ответить» использует выделенный фрагмент тела конкретного сообщения; без выделения отвечает на всё сообщение. Чужое выделение и текст кнопок не подставляются.
- Цитата сохраняется в отдельном nullable-поле `Message.replyQuote`. Сервер проверяет связь с исходным сообщением, канал и соответствие фрагмента.
- Удалены обрезка предпросмотра до 50 символов и однострочное ограничение отправленного ответа. Полный текст показывается с переносами; для цитаты используется весь выбранный фрагмент.

Поиск по веткам обсуждений остаётся отдельным вопросом: глобальный поиск этой версии, как и ранее, ищет сообщения основной ленты (`threadId: null`). Текущий патч не меняет интерфейс поиска/навигации внутри веток.

## Обязательная миграция

`apps/web/prisma/migrations/20261008000000_message_reply_quote/migration.sql`

Миграция только добавляет необязательный текстовый столбец, не удаляет сообщения и не меняет существующие ответы. Её необходимо применить **до запуска новой версии**. Иначе Prisma-запросы сообщений будут обращаться к отсутствующему столбцу.

Не заменяйте серверные `.env*`, пользовательские загрузки, хранилища, конфигурацию PM2/nginx и данные соседних проектов содержимым архива. Предварительно сделайте резервную копию БД и текущего приложения. Сверьте локальные изменения сервера с этим архивом.

## Установка с PM2

После переноса обновлённых исходников в `/var/www/trioz`:

```bash
cd /var/www/trioz
npm ci --ignore-scripts

cd apps/web
NODE_ENV=production node <<'NODE'
require('@next/env').loadEnvConfig(process.cwd(), false);
if (!process.env.DATABASE_URL) {
  console.error('DATABASE_URL не найден. Проверьте серверные настройки.');
  process.exit(1);
}
const { spawnSync } = require('node:child_process');
const result = spawnSync(process.execPath, [
  require.resolve('prisma/build/index.js'), 'migrate', 'deploy',
], { stdio: 'inherit', env: process.env });
process.exit(result.status ?? 1);
NODE
```

Если миграция завершилась успешно:

```bash
cd /var/www/trioz
npm run build
```

**Только после успешной сборки:**

```bash
pm2 restart trioz
pm2 save
pm2 logs trioz --lines 60 --nostream
```

Команды не перезапускают `interactive`, `nastolka` и другие процессы. Если приложение использует DATABASE_URL только из окружения PM2, а не из `.env*`, выполните миграцию с тем же окружением безопасным способом; не публикуйте URL БД или вывод `pm2 env` в чат.

## Проверки

- `npm run lint`: финальный результат — в `docs/test-reports/community-chat-validation.txt`.
- `npm run build`: production-сборка.
- `prisma generate` и `prisma validate`: успешны. `validate` использует тестовый адрес, не соединяется с БД.
- 38 целевых тестов: история и её права доступа, сохранение/валидация цитаты, выделение, поиск и пагинация, устаревшие ответы, существующее раскрытие хвоста и экспорт AmneziaVPN.
- Локальный Chromium: 30 шагов ручной прокрутки вверх на 1000 строках разной высоты; догрузка сверху; добавление сообщения при чтении; изменение высоты над экраном; позднее изменение высоты без обновления родителя; переход через порог включения виртуализации. ID и смещение читаемого сообщения сохраняются.
- Полный набор сравнивался с исходным архивом: 2087 успешных тестов против 2058 в исходной версии; те же 21 падающий тест, те же 7 проблемных файлов. Новых упавших проверок нет. Один из 7 файлов не загружается ещё в исходной версии.

Полный `tsc --noEmit` включает старые тестовые файлы с существующими ошибками типов; он не является зелёной проверкой всей репозитории. Production-сборка проверяется отдельно. Реальная миграция PostgreSQL, работа с production-данными и ручная проверка на trioz.ru в этой среде не выполнялись.

## Что проверить после установки

1. Листать вверх длинный канал с короткими/длинными сообщениями и вложениями, продолжать чтение при входящих сообщениях и реакциях.
2. Найти сообщение далеко за пределами последних 450 сообщений; догрузить более старые результаты; перейти к результату; пройти историю в обе стороны и вернуться к последним сообщениям.
3. Выделить фрагмент внутри одного сообщения, нажать существующую кнопку ответа, отправить и обновить страницу: фрагмент должен сохраниться.
4. Ответить без выделения на длинный текст: исходный текст должен быть доступен полностью, без старой обрезки.
5. Проверить переключение каналов во время медленной загрузки и восстановление соединения.

VPN, AmneziaWG, peer, ключи, маршрутизация и серверный учёт трафика этим обновлением не менялись.
