# Android: диагностика запуска TrustTunnel

## Что проверено в исходниках

- В данном архиве `apps/android/app/build.gradle.kts` добавляет `src/trustTunnelPilot/java` в debug **и release**; `implementation(files("libs/trusttunnel-test.aar"))` общая. Это отличается от старого debug-only пилота. AAR содержит только `arm64-v8a`, приложение — Android 8+; сборка release требует собственной подписи. Нельзя по архиву установить, какой APK реально стоит на устройстве.
- `MainActivity` устанавливает bridge для доверенного origin при поддержке `WEB_MESSAGE_LISTENER` WebView. В `AndroidManifest.xml` объявлена `TrustTunnelPilotService` с `BIND_VPN_SERVICE` и `android.net.VpnService`. Системный запрос идёт через `VpnService.prepare()` после подтверждения диалога TrioZ; если разрешение уже есть, Android может не показать его снова.
- До запроса проверяются серверное состояние/право и применение профиля, доступность мостов, другое VPN, строгий формат профиля и локальная политика. Android-валидатор жёстко ожидает `turn.trioz.ru` и `170.168.18.20:8443`: несовпадающая конфигурация сервера будет отклонена.
- `apps/android/vpn-admission-policy.json` включён. Установка любого из перечисленных пакетов (ВКонтакте, MAX, Яндекс Браузер, Яндекс, Яндекс Карты, Яндекс Навигатор) может блокировать запуск VPN даже если приложение не открыто. Проверка локальная, точные пакеты приведены в policy. Это намеренно сохранено: не меняйте политику без решения владельца. Сообщение на экран не передаёт перечень установленных приложений.
- Старый мост превращал отказ политики, конфликт и неверный профиль в одно сообщение «Не удалось выполнить операцию VPN». Поэтому оно не определяет причину на конкретном устройстве.

## Изменения

- `TrustTunnelStartGuard.kt`: безопасные сообщения для несовместимого профиля, занятого VPN, блокирующей политики и ошибки проверки политики. Входные профиль, пароли и перечень приложений не включаются в сообщения.
- `src/debug/.../TrustTunnelPilotBridge.kt`, `src/release/.../TrustTunnelPilotBridge.kt`: вывод безопасной причины вместо поглощения; обработка исключения системного запроса разрешения; сброс зависшего состояния при ошибке создания диалога. Без изменения origin-доступа, политики допуска и модели разрешений.
- `TrustTunnelPilotService.kt`: обработка отказа запуска foreground-службы без необработанного исключения и безопасные сообщения этапа запуска. Это **не** исправление доказанной причины потери сети на конкретном телефоне.
- `TrustTunnelStartGuardTest.kt` и тест панели: регрессии сообщений и отсутствие передачи приватных данных.
- `app/build.gradle.kts`: для всех вариантов подключён Compose runtime, необходимый включённому Compose compiler. Ранее debug собирался, а release падал с `IncompatibleComposeRuntimeVersionException`; элементы preview остаются debug-only.

## Проверки и ограничения

На Linux с JDK 17 и Android SDK 36 успешно выполнены `assembleDebug` и `assembleRelease`; release проверен только временным тестовым ключом, он не подходит для обновления установленной production-версии. В debug APK и release APK проверены манифест службы, локальная политика и arm64-библиотека. Прошли 17 Android unit-тестов (политика, профиль и guard), 26 веб-тестов панели/моста и 9 Python-тестов инструмента политики. При сборке предупреждение: некоторые native-библиотеки не удалось strip, поэтому они включены без strip. На физическом Android-устройстве разрешение, уведомление, системный значок VPN, жизненный цикл, TLS, маршруты, DNS, реальный трафик и возврат обычного интернета не проверялись. Наличие службы в исходниках не доказывает, что установленный APK содержит её и что сеть работает. На этапе создания туннеля интернет может пропасть; `killswitch_enabled = true` оставлен без изменения, так как его отключение влияет на приватность.

## Порядок проверки на устройстве

1. Собрать и установить APK из этого исходного кода. Debug имеет applicationId `ru.trioz.connect.debug`, release — `ru.trioz.connect`; разрешения и данные у них раздельные. Другой ключ подписи не может обновить уже установленный APK с тем же ID; не удаляйте установленное приложение до резервного копирования важных данных.
2. Отключить другие VPN, проверить наличие связи. В TrioZ открыть TrustTunnel и нажать подключение. Прочитать текст ошибки, затем подтвердить диалог TrioZ и, если Android запросит, системное разрешение. Не высылать профили, токены и логины.
3. Если видна блокировка локальной политикой — сравнить только локально с policy-файлом. Изменение этой политики требует отдельного решения и пересборки APK; оно не делалось автоматически.
4. Проверить значок VPN и доступ к сайтам; если связь пропала, отключить TrustTunnel в приложении или в системных настройках. Отключение VPN может вернуть трафик на обычную сеть. При проблеме сохранить точный текст ошибки, модель телефона, версию Android и тип APK. Не присылать приватные сетевые конфиги.

Не требуется менять сервер для самой Android-правки, если установленная веб-версия поддерживает текущий bridge. Для обновления нативного моста нужно пересобрать и обновить APK. Если сайт на сервере старее совместимого интерфейса — обновить также веб-часть. Никаких миграций БД эта диагностика не добавляет.
