# Почта: отправка через собственный сервис

Письма TrioZ уходят через почтовый сервис `github.com/acoulbot/smtp` — одним
HTTP-запросом, а не прямым SMTP-подключением.

## Почему через сервис

Прямое подключение умеет ровно одно: отдать письмо одному серверу по одним
кредам. Если этот сервер не ответил — письмо потеряно. Сервис же держит список
relay-провайдеров с приоритетами и идёт по нему сверху вниз, подписывает письма
DKIM, пишет журнал отправок и рассылает вебхуки о судьбе каждого письма.

Приложению остаётся один POST. Вся почтовая механика живёт там, где её видно и
где ею можно управлять из админки, а не в переменных окружения веб-приложения.

## Что задаётся

```
SMTP_SERVICE_URL   адрес сервиса, например https://smtp.trioz.ru
SMTP_SERVICE_KEY   ключ сайта из админки сервиса (Сайты → API ключ), sm_…
SMTP_FROM          необязательно
```

`SMTP_FROM` можно не задавать. Сервис сам сообщает адрес отправителя своего
сайта, и этот адрес заведомо согласован с доменом ключа. Задавать переменную
стоит только ради другого ящика того же домена: **ключ сайта отправляет письма
исключительно от своего домена**, чужой отправитель получает `403`. Поэтому
несовпадение проверяется на старте и называется вслух, а не выясняется по
первой неудачной регистрации.

Ключ обязан оставаться на сервере. Попав в браузер, он позволит любому
посетителю рассылать письма от имени домена.

## Ключ проверяется при запуске

`GET /api/me` — та же точка, которую сервис предлагает экрану «подключить
сервис»: `401` значит неверный ключ, `200` приносит домен, отправителя и
состояние DKIM. Ответ намеренно не содержит секретов, поэтому пишется в лог
целиком:

```
[email] сервис https://smtp.trioz.ru: домен trioz.ru, отправитель noreply@trioz.ru, DKIM настроен, relay свой
```

Запрос делается один раз при старте и переиспользуется — он же добывает адрес
отправителя. Проверка именно при запуске, а не при первом письме: неверный ключ
должен быть виден в логе, а не в жалобе пользователя на регистрацию.

Отдельно проговариваются три случая, которые иначе выглядят как «письмо просто
не пришло»: ключ не принят, сайт в сервисе отключён, `SMTP_FROM` не из домена
ключа. Причину отказа сервис пишет словами в поле `detail`, и она попадает в
лог — иначе осталось бы бесполезное «не удалось отправить».

У запроса есть таймаут. Без него зависший сервис держал бы запрос регистрации
до таймаута самого Next, а человек всё это время смотрел бы на крутящуюся
кнопку.

## Прямой SMTP остался запасным путём

Если `SMTP_SERVICE_URL` и `SMTP_SERVICE_KEY` не заданы, работает прежняя
отправка через nodemailer по `SMTP_HOST`. Это нужно установкам, которые ещё не
переехали, и случаю, когда сам сервис поднят как обычный SMTP-релей: у него
есть и SMTP-сервер, не только API.

В этом пути исправлены две вещи.

**Пароль читается из `SMTP_PASSWORD`.** Код брал `SMTP_PASS` — имя, которого
нет ни в `.env.example`, ни в `docker-compose.yml`, ни в `.gitlab-ci.yml`, ни в
инструкции README. Пароль до транспорта не доезжал, письмо уходило с пустым
паролем, сервер отвечал `535 Authentication credentials invalid`, и это
читалось как неверные учётные данные — хотя данные были верные, их просто не
брали. Старое имя оставлено запасным, чтобы не погасить установку, где в `.env`
уже лежит `SMTP_PASS`. Стартовый лог теперь называет, из какой переменной взят
пароль, и отдельной строкой сообщает про «логин есть, пароля нет» — это
единственная поломка почты, которую нельзя опознать по ответу сервера.

**Шифрование выводится из порта.** `SMTP_SECURE` не документирован и не
пробрасывается ни compose, ни CI, а на порту 465 (implicit TLS) значение
`false` не даёт внятной ошибки, а вешает соединение. Теперь 465 шифрованный,
остальные через STARTTLS, а переменная нужна только чтобы переопределить вывод.

## Неудачная отправка не занимает минуту

`POST /api/auth/send-code` создаёт запись `VerificationCode` до отправки, а
защита от спама («Подождите минуту перед повторной отправкой») смотрит именно
на неё. Когда почта падала, человек получал сначала «не удалось отправить», а
следом ещё и запрет повторить — не получив ни одного письма.

Теперь запись удаляется, если письмо не ушло. Минута отсчитывается от
отправленного кода, а не от попытки.
