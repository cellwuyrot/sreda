# Партнёрские игры: что требуется от разработчика

Документ можно отдавать студии как есть. От неё нужен **один** HTTP-эндпойнт.

## Эндпойнт

```
GET https://<домен-студии>/trioz/manifest
Authorization: Bearer <ключ, который студия выдала TrioZ>
```

Ответ:

```json
{
  "title":       "Название игры",
  "description": "Описание для карточки",
  "cover":       "https://.../cover.jpg",
  "players":     "2-8 игроков",
  "tags":        ["Стратегия", "PvP"],
  "launchUrl":   "https://play.example.com/trioz",
  "partner":     "Название студии",
  "online":      137
}
```

Обязательны только `title` и `launchUrl`, и `launchUrl` должен быть `https`.
Остальные поля необязательны: без `cover` карточка покажет заглушку, без
`online` — не покажет счётчик.

Ограничения, которые проверяет наша сторона: ответ до 64 КБ, до 8 метк, тексты
подрезаются (название 120, описание 1000 символов), `cover` и `launchUrl`
принимаются только по `https`.

## Почему один эндпойнт, а не несколько

Тот же запрос служит проверкой связи: кнопка «Проверить связь» в админ-панели
просто перезапрашивает манифест. Отдельного `/health` нет намеренно — каждый
дополнительный обязательный эндпойнт это ещё один способ получить наполовину
реализованную интеграцию, которая формально отвечает, но данных не даёт.

Поэтому же «подключить» и «обновить» — одно действие: манифест является
единственным источником данных о партнёрской игре, и карточка у нас не может
разойтись с игрой у партнёра дольше, чем до следующей сверки.

## Что происходит на нашей стороне

1. Админ вводит адрес API и ключ в **Админ-панель → Сервисы и система → Игры**.
2. Мы сразу запрашиваем манифест. Успех — карточка заполнена, `linkState = OK`.
   Неудача — запись всё равно создаётся, но выключенной и с текстом ошибки:
   иначе админ потерял бы введённое и не узнал причину.
3. Игру нельзя активировать, пока связка не в состоянии `OK`. Активная карточка,
   ведущая в неизвестность, хуже отсутствующей.
4. Если связка сломалась у уже активной игры, сверка снимает её с публикации.

## Ключ студии

Ключ шифруется при сохранении (`src/lib/encryption.ts`, AES-256-GCM на
`ENCRYPTION_SECRET`) и **не возвращается ни одним маршрутом** — ни в админку, ни
в публичный список. В панели видны последние 4 символа: их достаточно, чтобы
понять, тот ли ключ вставлен, и недостаточно, чтобы им воспользоваться.

Если `ENCRYPTION_SECRET` сменили, старые ключи расшифровать нечем. Сверка в этом
случае честно говорит «введите ключ заново», а не валит вину на партнёра.

## Исходящие запросы

Адрес партнёра вводит администратор, то есть доверенное лицо, но опечатка не
должна превращать наш сервер в инструмент для стука по внутренней сети. Поэтому
в `src/lib/gamesCatalog.ts`:

- только `https`, без логина и пароля в URL;
- домен резолвится, и все его адреса проверяются на приватные диапазоны
  (10/8, 172.16/12, 192.168/16, 127/8, 169.254/16, CGNAT, IPv6 ULA и link-local);
- `redirect: "manual"` — 302 на внутренний адрес был бы обходом проверки выше;
- таймаут 8 секунд.

## Свои игры

Своя игра описывается в панели руками: её код у нас, сверять нечего. `launchUrl`
по умолчанию `/games/<слаг>`, то есть внутренняя страница. Вельд'Эран перенесён
в каталог миграцией `20260804000000_games_catalog` активной записью, чтобы
раздел не оказался пустым после деплоя.
