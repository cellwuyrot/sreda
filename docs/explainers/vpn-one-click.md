# Explainer: VPN «по кнопке» в TZ Connect (`VPN-ONECLICK`)

Как «кнопка VPN», которая раньше лишь отдавала файл-профиль, превратилась в
настоящий выключатель туннеля — и почему это можно было сделать только в
десктоп-оболочке.

---

## Background

### Для тех, кто далёк от VPN (можно пропустить, если вы в теме)

VPN-туннель — это виртуальный сетевой интерфейс в операционной системе. Когда он
поднят, трафик уходит не напрямую в интернет, а шифруется и отправляется на
сервер, который распечатывает его и выпускает от своего имени. WireGuard — это
современный протокол для таких туннелей: у каждой стороны есть пара ключей
(приватный и публичный), клиент знает публичный ключ сервера, сервер — публичный
ключ клиента, и по ним они друг друга узнают. Профиль (`.conf`) — это просто
текстовый файл: приватный ключ клиента, адрес внутри туннеля, публичный ключ и
адрес сервера, список маршрутов (`AllowedIPs`).

> **Определение.** «Поднять туннель» — значит создать в ОС сетевой интерфейс
> (`wg0` в Linux, служба туннеля в Windows) и настроить маршруты. Это требует
> **прав уровня системы** — обычная программа так не может, тем более вкладка
> браузера.

**AmneziaWG** — форк WireGuard, который добавляет в профиль параметры маскировки
(`Jc`, `S1`, `H1`, …), чтобы туннель было труднее заблокировать. Команды у него
те же, только бинарник называется `awg` вместо `wg`.

### Что было в проекте до этой правки

Экосистема TrioZ уже умела почти всё серверное:

- **Главный сервер** (`apps/web`) хранит пиров и по `POST /api/vpn/me`
  регистрирует публичный ключ клиента, а в ответе отдаёт всё для сборки профиля.
- **Узел** (`apps/vpn`) на отдельной машине тянет список пиров и приводит к нему
  свой `wg0`.
- **Клиент** — окно «Защищённое соединение» (`PremiumInfoModal.tsx`). Оно
  генерировало пару ключей X25519 прямо в браузере (`lib/wgKeys.ts`),
  отправляло публичную половину и **строило `.conf`, который пользователь
  скачивал** и вручную импортировал в сторонний клиент (Amnezia).

То есть «включить VPN» на деле означало «скачать файл и настроить другую
программу». Настоящего туннеля клиент не поднимал: ни зависимости
`wireguard-tools`, ни нативного модуля, ни службы у него не было.

### Почему именно десктоп-оболочка

У проекта три клиента: браузер, Android-WebView и **десктоп-оболочка на
Electron** (`apps/desktop`). Только у последней есть Node-процесс (`main`) с
полным доступом к ОС: она уже умеет писать файлы, запускать процессы, показывать
нативные окна. Браузерная вкладка к сетевому стеку не подпускается в принципе.
Значит, «кнопка Вкл» может реально работать только в оболочке — там и живёт вся
новая логика.

## Intuition

Суть правки одной фразой: **профиль больше не отдают человеку файлом — его
отдают самой оболочке, и она поднимает туннель.**

Представьте на игрушечных данных. Пользователь нажимает «Включить». Как и раньше,
в памяти страницы рождается пара ключей и строится профиль:

```ini
[Interface]
PrivateKey = <приватный ключ, только в памяти>
Address = 10.8.0.7/32
DNS = 1.1.1.1
[Peer]
PublicKey = <публичный ключ узла>
Endpoint = vpn1.example.ru:51820
AllowedIPs = 0.0.0.0/0, ::/0
```

Раньше этот текст уходил в файл `trioz.conf`. Теперь он уходит по IPC в
main-процесс, который:

1. кладёт его во временный файл `…/userData/vpn/trioz.conf` с правами `600`;
2. смотрит, есть ли в нём параметры маскировки (`Jc`, `S1`…) — если есть, нужен
   `awg`, иначе `wg`;
3. находит установленный бинарник и запускает его **с повышением прав**:
   - Windows: `wireguard.exe /installtunnelservice trioz.conf` (ставит службу);
   - Linux: `pkexec wg-quick up …`;
   - macOS: `osascript … with administrator privileges`;
4. следит за рукопожатием и сообщает окну: `connecting → on`.

Кнопка «Выключить» делает обратное (`/uninstalltunnelservice` или `wg-quick
down`), а при выходе из приложения туннель снимается сам.

> **Почему это важный инвариант.** В режиме «весь трафик» поднятый туннель гонит
> через сервер *весь* интернет машины. Если бы приложение закрылось, оставив
> туннель, у пользователя не осталось бы окна, чтобы его выключить, — только
> ручное вмешательство в систему. Поэтому снятие при выходе — не мелочь, а
> обязательное условие.

Второй важный момент — **разделение ошибкоопасного и грязного**. Всё, где легко
ошибиться молча (выбор `wg`/`awg`, экранирование пути с пробелом и кавычкой при
повышении прав, разбор времени рукопожатия), вынесено в чистый модуль без
`electron` и покрыто тестами. Грязное (запуск процессов, запись файла) — рядом,
но там проверять без реальной ОС всё равно нечего.

## Code

### 1. Чистая логика — `apps/desktop/src/shared/vpnPlan.ts` (новый)

Ни одного побочного эффекта: только построение команд и разбор вывода. Отсюда и
тесты.

```ts
export const TUNNEL_NAME = "trioz";
export const TUNNEL_CONF_FILE = `${TUNNEL_NAME}.conf`;

// Обфускация — по ключам [Interface], а не поиском подстроки: «S1» мелькает
// в base64 любого ключа, и обычный профиль ошибочно поехал бы на AmneziaWG.
export function isObfuscatedConfig(config: string): boolean { /* … */ }

// Кандидаты-бинарники: win + обычный → wireguard.exe; linux + обфускация → awg-quick.
export function tunnelBackendCandidates(platform, obfuscated): TunnelBackendCandidate[] { /* … */ }

// up/down по платформе: Windows ставит службу из файла и снимает по имени,
// wg-quick поднимает и снимает по одному и тому же профилю.
export function tunnelUpArgs(platform, confPath): string[] { /* … */ }
export function tunnelDownArgs(platform, confPath, name): string[] { /* … */ }

// Самое хрупкое — повышение прав. Возвращает готовые { file, args } для spawn без shell.
export function elevatedInvocation(platform, exe, args): ElevatedInvocation { /* … */ }
```

Экранирование в `elevatedInvocation` — то место, ради которого всё выносилось:
для PowerShell одинарные кавычки удваиваются, для AppleScript строка сначала
собирается как POSIX-shell (аргументы в одинарных кавычках), затем экранируется
для двойных кавычек AppleScript, а `pkexec` принимает argv напрямую и в кавычках
не нуждается.

### 2. Менеджер туннеля — `apps/desktop/src/main/vpn.ts` (новый)

Побочные эффекты: состояние, поиск бинарника, запуск, файл, статус.

```ts
export async function vpnUp(config: string): Promise<VpnStatePayload> {
  // 1. проверить, что это правда профиль; 2. obfuscated? → кандидаты;
  // 3. найти бинарник (which/where + известные каталоги);
  // 4. записать trioz.conf с правами 600; 5. runElevated(up);
  // 6. connecting → опрос рукопожатия → on.
}
export async function vpnDown(): Promise<VpnStatePayload> { /* runElevated(down) + удалить файл */ }
export async function shutdownVpn(): Promise<void> { /* снять туннель при выходе */ }
```

Поиск инструмента не ограничен `PATH`: служба WireGuard на Windows ставит
`wireguard.exe` в `C:\Program Files\WireGuard`, а не в `PATH`, поэтому известные
каталоги проверяются отдельно.

### 3. Мост и каналы

- `shared/constants.ts` — новые IPC-каналы `VPN_UP`, `VPN_DOWN`, `VPN_STATUS`
  (invoke) и `VPN_STATE` (push main → renderer).
- `main/ipc.ts` — три обработчика, которые зовут `vpnUp/vpnDown/vpnState`.
- `preload/index.ts` — surface `vpn: { up, down, status, onState }`.
- `main/index.ts` — в `before-quit` откладываем выход на один проход и снимаем
  туннель, если он активен.

```ts
if (isVpnActive()) {
  event.preventDefault();
  void shutdownVpn().finally(() => app.quit());
}
```

### 4. Веб-часть

- `apps/web/src/lib/desktop.ts` — типы `DesktopVpnState`, `DesktopVpnApi` и
  опциональное поле `vpn?` в мосте (feature-detect обязателен: в браузере и
  старых сборках его нет).
- `apps/web/src/components/connect/overlays/PremiumInfoModal.tsx` — здесь и
  случилось главное:
  - **удалены** `downloadConfig`, `copyConfig`, показ сырого профиля и кнопка
    «Скачать trioz.conf»;
  - `enroll` теперь возвращает собранный профиль строкой (а не пишет его на
    экран);
  - `connect(mode)` собирает профиль и зовёт `bridge.up(config)`;
  - индикатор и кнопка отражают **живое состояние туннеля** (`connecting/on`),
    а не рукопожатие серверной записи;
  - в браузере/старой сборке — честная подсказка «включение в приложении».

```ts
const connect = useCallback(async (mode) => {
  const bridge = getDesktopApi()?.vpn;
  if (!bridge) return;                 // в браузере включать нечем
  const config = await enroll(mode);   // профиль в памяти
  if (!config) return;
  setTunnel(await bridge.up(config));   // оболочка поднимает туннель
}, [enroll]);
```

## Verification

**Автоматически (в этом окружении):**

- `vpnPlan.test.ts` — 15 тестов на чистую логику: распознавание обфускации (в том
  числе что `S1` в base64 ключа не путается с параметром маскировки), выбор
  бинарника, аргументы up/down, экранирование при повышении прав для всех трёх
  платформ (путь с пробелом и одинарной кавычкой), разбор рукопожатия. Прогон:
  `npx vitest run --project desktop-shell` — 48 тестов зелёные.
- `npm run typecheck -w apps/desktop` — проходит.
- ESLint по изменённым файлам (`PremiumInfoModal.tsx`, `lib/desktop.ts`,
  `vpnPlan.ts`, `vpn.ts`, `ipc.ts`, `index.ts`, `preload/index.ts`) — чисто.

> **Честная оговорка.** Реальное поднятие туннеля и окна повышения прав
> (UAC/polkit/osascript) в этом окружении не проверить: нет ни Electron-рантайма,
> ни прав, ни установленного WireGuard. Полный `next build` веба здесь тоже не
> запускается — движок Prisma блокируется (403) на скачивании. Это внешние
> ограничения среды, не кода.

**Ручная проверка (на реальной машine):**

1. Соберите и запустите оболочку: `npm run desktop:dev`.
2. Установите WireGuard (Windows/Linux/macOS — см. `docs/vpn.md`).
3. Войдите под аккаунтом с Premium или подпиской VPN, поднимите хотя бы один
   VPN-узел (см. `docs/vpn.md`, часть 1) и включите сервис в панели.
4. Откройте «Защищённое соединение» → выберите режим → «Включить». Подтвердите
   запрос прав. Индикатор должен стать зелёным.
5. Проверьте внешний адрес (например, на сайте «мой IP») — в режиме «весь
   трафик» он должен смениться на адрес узла.
6. «Выключить» → адрес возвращается. Закройте приложение с активным туннелем —
   туннель должен сняться сам (`wg show` не показывает `trioz`).

## Alternatives

### А. Бандлить сетевой движок в установщик приложения

Вместо того чтобы просить пользователя один раз поставить WireGuard, положить
`wg.exe`/`wireguard.dll` (и AmneziaWG) прямо в установщик TZ Connect.

| Плюсы | Минусы |
|---|---|
| Ничего ставить руками не нужно | В установщик едут неподписанные сетевые драйверы — риск и повод для антивирусов |
| Полный контроль версии движка | Заметно тяжелее установщик, отдельная сборка под каждую ОС/арх |
| Работает «из коробки» на голой машине | Обновление и подпись драйверов — отдельная головная боль |

Отвергнуто на этом шаге: одноразовая установка официального WireGuard честнее и
безопаснее, а детект инструмента уже даёт понятную подсказку. Бандлинг можно
добавить позже, не меняя контракт моста.

### Б. Нативный модуль на базе `wireguard-go` / embeddable DLL

Встроить `wireguard-embeddable` и управлять туннелем через N-API, без внешних
процессов и повышения прав на каждый вызов.

| Плюсы | Минусы |
|---|---|
| Нет окна UAC/polkit на каждое включение | Нативная сборка под каждую платформу и версию Electron |
| Тоньше контроль над жизненным циклом | На Windows всё равно нужен драйвер/служба с правами |
| Меньше зависимость от внешних бинарников | Заметно больше кода и точек отказа, чем `wg-quick` |

Отвергнуто: `wg-quick` / `wireguard.exe` — проверенные, стабильные инструменты;
модель «вызвать доверенный бинарник» проще и надёжнее для первого рабочего
варианта.

## Quiz

<details>
<summary>1. Почему настоящий туннель реализован в десктоп-оболочке, а не в веб-странице?</summary>

- **A.** Так быстрее рендерится React.
- **B.** ✅ Поднятие сетевого интерфейса требует прав уровня ОС, которых у вкладки
  браузера нет; доступ к системе есть только у main-процесса Electron.
- **C.** Потому что WebCrypto не умеет X25519.
- **D.** Из-за политики CORS.

Верно **B**. Браузер принципиально не подпускают к сетевому стеку. C — реальная,
но другая проблема (поэтому в проекте свой X25519), к месту поднятия туннеля она
отношения не имеет.
</details>

<details>
<summary>2. Как клиент понимает, что нужен AmneziaWG (`awg`), а не обычный `wg`?</summary>

- **A.** По домену точки подключения.
- **B.** Спрашивает у сервера отдельным полем.
- **C.** ✅ По наличию параметров маскировки (`Jc`, `S1`, `H1`…) в секции
  `[Interface]` профиля.
- **D.** Всегда пробует сначала `awg`, потом `wg`.

Верно **C**. `isObfuscatedConfig` разбирает строки и смотрит имя ключа слева от
`=`. Важно, что ищется не подстрока: «S1» встречается в base64 обычных ключей, и
поиск подстрокой ошибочно принял бы обычный профиль за обфусцированный.
</details>

<details>
<summary>3. Зачем экранирование команд повышения прав вынесено в чистый модуль?</summary>

- **A.** Чтобы уменьшить размер бандла.
- **B.** ✅ Это самое ошибкоопасное место (пробелы и кавычки в пути ломают запуск
  молча), а в чистом модуле без побочных эффектов его можно покрыть тестами.
- **C.** Так требует Electron.
- **D.** Чтобы переиспользовать код в вебе.

Верно **B**. Путь с пробелом или одинарной кавычкой — классический источник тихих
багов при переходе через PowerShell/AppleScript; тест на `o'brien` в пути это
фиксирует.
</details>

<details>
<summary>4. Что произойдёт с туннелем, если закрыть приложение при активном соединении?</summary>

- **A.** Останется поднятым до перезагрузки ОС.
- **B.** ✅ Оболочка в `before-quit` откладывает выход и снимает туннель, потом
  выходит.
- **C.** Ничего, туннель и так в памяти вкладки.
- **D.** Windows снимет его сам через 60 секунд.

Верно **B**. Иначе в режиме «весь трафик» закрытое приложение оставило бы всю
машину замкнутой на сервер без окна, чтобы это отменить.
</details>

<details>
<summary>5. Что изменилось для пользователя в браузере (не в приложении)?</summary>

- **A.** Ничего, файл по-прежнему скачивается.
- **B.** Появилась кнопка «Поднять туннель в браузере».
- **C.** ✅ Скачивание `.conf` убрано; окно честно сообщает, что включение
  работает в приложении TZ Connect для компьютера.
- **D.** VPN в браузере теперь работает через WebRTC.

Верно **C**. Системный туннель в браузере поднять нечем, а скачивание пакета —
ровно то, от чего уходили; поэтому в браузере окно направляет в приложение.
</details>
