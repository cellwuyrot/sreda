# Подготовка выдачи профиля для пилота (в работе)

Рабочая копия — не релиз; не развёртывать и не включать пилот. Основа восстановлена из первоначального архива и предоставленного владельцем архива изменений connect относительно b0d3fc99; ключевые хеши и файлы изменений сверены, но полная идентичность серверной рабочей копии не подтверждена. Сохранены предоставленные локальный Makefile и untracked файлы.

## Что добавлено

- `apps/web/src/lib/trustTunnelClientConfig.ts`: проверка входных данных и создание TOML TrustTunnelClient 1.1.12, включая HTTP/2, TLS verification, явный kill switch и маршруты. Соединение и kill switch не проверены.
- `apps/web/src/lib/trustTunnelPilotBundle.ts`: чтение AES-256-GCM контейнера с индивидуальной записью для каждого пользователя; настройка, ротация и безопасное хранение криптоключа и контейнера ещё не разработаны. Компрометация процесса или его окружения раскрывает ключ и профиль; шифрование не заменяет их защиту. Не логировать ключ, контейнер и полученный профиль. Память JS не гарантированно очищается.
- `POST /api/vpn/trusttunnel/pilot/config`: аутентификация, same-origin, свежая роль/бан/удаление из БД, allowlist проектных ADMIN, лимит по пользователю, отдельный закрытый по умолчанию флаг выдачи, отсутствие кэширования, аудит без секретов. Не переключает глобальный VPN. При невозможности записать аудит профиль не выдаётся. Профиль передаётся веб-клиенту; защита от XSS/логирования и хранение на устройстве требуют отдельной проверки до включения.
- `scripts/trusttunnel-pilot-seal.mjs`: экспериментальный Linux-инструмент для создания ключа и контейнера в закрытом каталоге из конфиденциального JSON на stdin; не связан с Endpoint или выдачей. Нельзя передавать пароли аргументами или присылать их в чат. Сам по себе инструмент не решает безопасное хранение, доставку, ротацию и отзыв. Ключ и контейнер в одном каталоге не защищают от компрометации каталога.
- На этапе написания этого документа было пройдено 23 Vitest теста с подменённой БД, без сетевых проверок; чистые модули проверены `tsc --noEmit --strict`; 17 локальных тестов Python работают только с фиктивными данными во временных файлах.

## Ещё обязательно реализовать

Безопасную загрузку и эксплуатационное хранение контейнера и ключа, создание/отзыв credentials на Endpoint и проверку применения/отката, довести и проверить Android native adapter, реализовать Windows lifecycle/UI, сборки, практическую проверку подключений и учёт трафика. Лимит в fallback работает отдельно в каждом процессе. Удаление пользователя из allowlist запрещает повторную выдачу, но НЕ отзывает ранее выданный пароль на Endpoint. До завершения `TRIOZ_TT_PILOT_ISSUE_ENABLED` и `TRIOZ_TT_PILOT_ENABLED` нельзя включать на реальном сервере. Новый код не разблокирует глобальное переключение.
