# Что нужно сделать на сервере руками

Правки из ветки `fix/audit-critical-access` закрывают дыры в коде, но часть
работы кодом не делается: сменить утёкшие пароли, перенести уже загруженные
файлы, дописать переменные окружения. Пока это не сделано, часть исправлений
просто не вступит в силу.

Порядок ниже рассчитан на развёртывание через `docker compose` из корня
репозитория. Всё вместе занимает минут двадцать, из них простой сервиса —
около минуты (шаг 3).

> Секреты не присылайте в переписку и не кладите в репозиторий. Всё, что ниже
> нужно записать, записывается в `.env` на сервере (файл в `.gitignore`).

---

## 1. Сменить утёкшие секреты

Эти значения лежали в открытом виде и считаются известными посторонним.
Менять нужно все, даже если «никто не мог увидеть».

| Что | Где было | Что сделать |
|---|---|---|
| Пароль TURN-сервера | `turnserver.conf`, `docker-compose.yml` | Придумать новый, записать в `.env` как `TURN_CREDENTIAL` |
| Пароль PostgreSQL | значение по умолчанию в `docker-compose.yml` | Сменить пароль пользователя БД, записать в `.env` как `POSTGRES_PASSWORD` |
| Пароль SMTP | присылался в переписке | Сменить в панели почтового провайдера, записать как `SMTP_PASSWORD` |
| Пароль приложения Gmail | присылался в переписке | Отозвать в аккаунте Google, выпустить новый |
| Ключ API сайта | присылался в переписке | Перевыпустить в панели сервиса |

Сгенерировать значение: `openssl rand -base64 32`.

Смена пароля БД, если база уже работает:

```bash
docker compose exec postgres psql -U trioz -d trioz \
  -c "ALTER USER trioz WITH PASSWORD 'новый_пароль';"
```

Затем тот же пароль в `.env` (`POSTGRES_PASSWORD`) — строка `DATABASE_URL`
собирается из него автоматически.

## 2. Дописать переменные окружения

В `.env` рядом с `docker-compose.yml`. У четырёх переменных больше нет значений
по умолчанию: без них `docker compose up` не стартует и прямо скажет, какой не
хватает. Это сделано намеренно — молчаливый запуск с общеизвестным паролем
хуже, чем отказ запускаться.

```dotenv
POSTGRES_PASSWORD=...      # обязателен
NEXTAUTH_SECRET=...        # обязателен
ENCRYPTION_SECRET=...      # обязателен, ДРУГОЕ значение, не равное NEXTAUTH_SECRET
TURN_CREDENTIAL=...        # обязателен

NEXTAUTH_URL=https://connect.trioz.ru   # обязательно https, иначе cookie сессии
                                        # уйдут без флага secure
ALLOWED_ORIGINS=https://connect.trioz.ru

# По желанию: пароль для Redis. Если задать — не забыть REDIS_URL.
# REDIS_PASSWORD=...
# REDIS_URL=redis://default:пароль@redis:6379
```

Про `ENCRYPTION_SECRET`: если его не задать, код возьмёт `NEXTAUTH_SECRET`, и
тогда один утёкший ключ вскрывает сразу и подписи сессий, и зашифрованные поля
в базе. Значение должно быть отдельным.

**Важно:** после смены `ENCRYPTION_SECRET` уже зашифрованные записи не
расшифруются. Если он у вас уже был задан — оставьте прежний. Задавайте новый
только если раньше его не было вовсе.

## 3. Перенести приватные загрузки

Раньше вложения лежали в `public/uploads`, а всё в `public/` раздаётся без
проверки входа. Теперь приватные каталоги приложение ищет в
`storage/uploads` — но **старые файлы туда не переедут сами**, и пока они
лежат на прежнем месте, их по-прежнему отдаёт кто угодно.

Сначала посмотрите точные имена томов (они с приставкой имени проекта):

```bash
docker volume ls | grep uploads
```

Дальше — с остановкой приложения, чтобы никто не писал в каталог во время
переноса. Подставьте свои имена томов вместо `trioz_`:

```bash
docker compose down

docker volume create trioz_uploads_private

docker run --rm \
  -v trioz_uploads_data:/from \
  -v trioz_uploads_private:/to \
  alpine sh -c '
    for d in messages voice videos documents tasks projects; do
      if [ -d "/from/$d" ]; then mv "/from/$d" "/to/$d"; echo "перенесён: $d"; fi
    done
    echo "--- стало в приватном томе:"; ls -la /to
    echo "--- осталось в публичном:";   ls -la /from
  '

docker compose up -d
```

В публичном томе должны остаться только `avatars`, `banners`, `groups`,
`badges`, `services` и картинки лендинга. Их переносить не надо: они и должны
открываться без входа.

Проверка, что перенос удался:

```bash
docker compose logs app | grep SECURITY
```

Если в журнале есть строка `[SECURITY] В public/uploads остались приватные
каталоги: …` — значит что-то не переехало, и по этим каталогам файлы всё ещё
раздаются свободно.

## 4. Проверить учётные записи администраторов

Seed раньше создавал `admin@trioz.ru` и `acoulbot@trioz.ru` с ролью ADMIN и
паролями `admin123` / `change-me-in-production`, а при каждом повторном запуске
возвращал пароль к этому значению. Даже если вы пароль меняли — он мог быть
сброшен обратно последней выкладкой.

1. Войдите под `admin@trioz.ru` со старым паролем. Если пускает — пароль
   немедленно сменить.
2. То же для `acoulbot@trioz.ru` и `user@trioz.ru`.
3. Если учётная запись `admin@trioz.ru` не нужна — удалите её через админку
   (свою, личную, оставьте).

Посмотреть список администраторов:

```bash
docker compose exec postgres psql -U trioz -d trioz \
  -c "SELECT email, username, role, \"createdAt\" FROM \"User\" WHERE role = 'ADMIN';"
```

Если когда-нибудь понадобится снова запустить seed, задайте пароли заранее —
без них он теперь останавливается с ошибкой:

```dotenv
SEED_ADMIN_PASSWORD=...      # не короче 12 символов
SEED_USER_PASSWORD=...
SEED_ACOULBOT_PASSWORD=...
```

Пароли существующих учётных записей seed больше не трогает.

## 5. Закрыть порты базы и Redis

В `docker-compose.yml` порты `5432` и `6379` теперь публикуются только на
`127.0.0.1`. После `docker compose up -d` убедитесь, что снаружи их не видно:

```bash
ss -tlnp | grep -E '5432|6379'     # должно быть 127.0.0.1:5432, не 0.0.0.0:5432
```

Если на сервере есть фаервол, полезно закрыть их и там:

```bash
ufw deny 5432/tcp
ufw deny 6379/tcp
```

Подключаться к базе снаружи после этого можно через SSH-туннель:

```bash
ssh -L 5432:127.0.0.1:5432 пользователь@сервер
```

## 6. Перезапустить nginx

В `nginx.conf` добавлено правило: ответы с приватными вложениями не кэшируются
(иначе прокси отдал бы файл следующему запросу уже без проверки).

```bash
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
```

Если nginx стоит на хосте, а не в контейнере, — `sudo nginx -t && sudo nginx -s reload`.

## 7. Проверить после выкладки

Пять минут ручной проверки — быстрее, чем узнать о проблеме от пользователей.

1. **Вложения закрыты.** Скопируйте ссылку на картинку из личной переписки
   (вида `/uploads/messages/…`), откройте в приватном окне без входа —
   должно быть `401 Unauthorized`. С входом — открывается.
2. **Аватары открыты.** Ссылка вида `/uploads/avatars/…` в приватном окне
   должна открываться: страница входа показывает аватары до авторизации.
3. **Поиск не выдаёт лишнего.** Из учётной записи обычного участника найдите
   слово, которое встречается только в скрытом или модераторском канале, —
   в результатах его быть не должно.
4. **Голос работает.** Зайдите в голосовой канал вдвоём: если TURN не получил
   новый пароль, звук не соединится вовсе — проверяется сразу.
5. **Загрузка файлов работает.** Отправьте картинку в переписку и откройте её.

## 8. Применить миграцию с индексами

Во второй части правок добавлены индексы под запросы, которые сейчас идут
перебором таблицы (участники сообщества, лента уведомлений, закреплённые,
сводка за сутки). Миграция — `20260811000000_perf_indexes`.

```bash
docker compose exec app npx prisma migrate deploy
```

Создание индекса ненадолго блокирует запись в таблицу. На `Message` и
`Notification` при большом объёме это может занять от секунд до минут, поэтому
лучше выкатывать не в час пик. Миграция написана с `IF NOT EXISTS` — повторный
запуск безопасен.

Проверить, что индексы на месте:

```bash
docker compose exec postgres psql -U trioz -d trioz -c "\di+ *_idx" | grep -E "GroupMember_groupId|Notification_userId_createdAt"
```

## 9. Включить проверку права на файл

Раньше вложение получал любой вошедший, кому переслали ссылку: от адреса файла
к каналу или беседе в базе пути не было. Теперь он есть — при загрузке рядом с
файлом заводится строка «чему принадлежит», и выдача спрашивает то же право,
что и сам канал.

У файлов, загруженных ДО этой правки, такой строки нет. Закрывать их сразу
нельзя — исчезли бы все старые картинки в переписке, — поэтому пока они
отдаются по факту входа, а в журнал идёт строка `[uploads] файла нет в
указателе`.

Порядок:

```bash
# 1. Применить миграцию (создаёт таблицу указателя)
docker compose exec app npx prisma migrate deploy

# 2. Посмотреть, сколько файлов предстоит разобрать
docker compose exec app node scripts/backfill-upload-index.mjs --dry-run

# 3. Разобрать историю (можно запускать повторно)
docker compose exec app node scripts/backfill-upload-index.mjs
```

Дальше день-другой посмотрите журнал:

```bash
docker compose logs app | grep "нет в указателе"
```

Пусто — значит разобрано всё. Тогда в `.env` добавьте строку и перезапустите
приложение:

```dotenv
UPLOADS_STRICT=1
```

С этого момента файл без записи в указателе не отдаётся никому. Если строки в
журнале остались — сначала разберитесь, откуда эти файлы: скорее всего, их
загрузил кусок кода, который не сообщает о загрузке.

Проверка после включения: попросите коллегу прислать вам ссылку на вложение из
переписки, к которой у вас нет доступа. Раньше файл открывался, теперь должно
быть `403 Forbidden`.

## Что осталось незакрытым (сознательно)

Пока не выполнен шаг 9, вложение по пересланной ссылке получит любой вошедший
пользователь. После разбора истории и включения `UPLOADS_STRICT=1` право
проверяется по каналу, беседе или задаче — как при обычном открытии переписки.

Остаётся мелочь: доступ кэшируется на минуту, поэтому человек, которого только
что выгнали из канала, ещё до минуты сможет открыть уже известную ему ссылку.

## Доставка уведомлений на телефон (PUSH)

Уведомления при закрытом приложении требуют трёх переменных в `.env` главного
сервера. Как получить файл доступов — `apps/android/README.md`, раздел
«Уведомления при закрытом приложении».

```dotenv
FCM_PROJECT_ID=<project_id из служебного JSON>
FCM_CLIENT_EMAIL=<client_email из служебного JSON>
FCM_PRIVATE_KEY="<private_key одной строкой, переводы строк как \n>"
```

Не заданы — сервер молча не отправляет, всё остальное работает как раньше.
Ключ служебного аккаунта — секрет: он живёт только в `.env` на сервере, в
репозиторий и в переписку не попадает.
