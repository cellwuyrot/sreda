# Управление превью ссылок и единый стиль «Сервисы и система»

## Что изменилось

### Личные, деловые и групповые чаты

- В редакторе сообщения появилась карточка ссылки с действием **«Без превью»**. Сам URL остаётся в тексте и остаётся кликабельным. Карточку можно вернуть до отправки.
- Выбор автора записывается вместе с сообщением в `previewSuppressed`. Он применяется ко всем получателям, переживает перезагрузку и не сбрасывается обычным редактированием текста. Учтены ответы в ветках, повторная отправка личного сообщения и отложенные групповые сообщения.
- После отправки **«Скрыть у меня»** сохраняет личную настройку на сервере, только для текущего пользователя. Это не удаляет карточку у собеседников. Есть действие возврата.
- Автор может отдельно **убрать превью у всех** или вернуть его. Проверяются авторство, доступ к чату и право отправки; удалённые сообщения не изменяются. Изменение распространяется через Socket.IO без создания нового сообщения или уведомления.
- До загрузки метаданных отправленного сообщения проверяется личная настройка. При сбое сохранения показывается ошибка: интерфейс не выдаёт временное скрытие за успешно сохранённое.
- Настройка черновика сохраняется локально с привязкой к пользователю, чату и первой ссылке. Хранится URL и выбор, не весь текст. После успешной отправки выбор очищается; ошибка отправки его не теряет.
- В защищённых/зашифрованных личных чатах внешние превью автоматически не загружаются. Они не включаются действием возврата.

### Ссылки любых сайтов

Один компонент используется и для TrioZ, и для сторонних доменов. Карточка использует доступные Open Graph/Twitter-обложку, заголовок, описание, favicon и строго проверенный `theme-color`. При отсутствии цвета акцент определяется по домену; при отсутствии обложки остаётся компактная читаемая карточка. Маленькое изображение не растягивается в большую размытую обложку. Домен виден отдельно от заголовка.

**Это не копирование чужого HTML/CSS или запуск кода сайта.** Стиль карточки остаётся безопасным и единым, а визуальная индивидуальность берётся из метаданных сайта. Если сайт не предоставляет метаданные или недоступен, воспроизвести его оформление полностью нельзя.

Изображения и favicon проходят через существующий авторизованный image proxy. Сохранены ограничения размера, тайм-ауты, защита от SSRF и проверка перенаправлений. Сторонние стили и скрипты не подключаются. При неудачной загрузке исходная текстовая ссылка остаётся доступной.

### Все пункты «Сервисы и система»

Общий каркас и переключатель разделов применяются к следующим страницам и их вложенным маршрутам:

1. Мониторинг проектов.
2. TZ ID.
3. ИИ-ассистент.
4. Настройки ограничений.
5. Логи редактора.
6. Услуги.
7. Надёжное соединение.
8. Игры.
9. Сборки.
10. Серверы.
11. Email и обработка данных.

Единые поля, поверхности, отступы, состояния фокуса, навигация и акценты: фиолетовый в светлой теме, бирюзовый в тёмной. Вложенные редакторы услуг, этапов и документов также учитывают тему. В мониторинге показатели ресурсов разделены на читаемые блоки; прежние источники данных и правила свежести сохранены. Подсказки в системных разделах открываются с клавиатуры и касанием и не создают горизонтальную прокрутку на телефоне.

Административные API, назначение проектов, права пользователей, финансовые операции и команды PM2/VPN не переписывались. Редактору навигация показывает только его разделы; серверные проверки доступа по-прежнему выполняются страницами и API. Внешний вид сам по себе не предоставляет новые права.

## Миграция базы — обязательна

Добавлена миграция:

`apps/web/prisma/migrations/20261030120000_chat_link_preview_controls/migration.sql`

Она добавляет:

- `Message.previewSuppressed`, `DirectMessage.previewSuppressed`, `ScheduledMessage.previewSuppressed` — `boolean NOT NULL DEFAULT false`;
- таблицу `ChatLinkPreviewHidden` для личных настроек с составным ключом пользователь/тип чата/сообщение и внешним ключом на пользователя.

Старые сообщения сохраняются. Персональные записи не удаляют сообщения; удаление пользователя удаляет его настройки. Идентификатор сообщения общий для двух типов сообщений и не имеет отдельного FK на одну из таблиц: доступ каждый раз проверяется по существующему сообщению. После удаления сообщений личные записи могут оставаться; отдельная фоновая очистка в этом изменении не добавлена.

Перед обновлением сделайте резервную копию PostgreSQL. Миграцию необходимо применить **до запуска новой версии приложения**. Не меняйте старые миграции и не запускайте `db push` вместо production-миграций.

## Обновление главного проекта

Архив содержит исходники главного проекта. Сначала перенесите изменения в ваш Git и отправьте их в основную ветку. Эта инструкция не обновляет Business или дочерние VPN-узлы — им это изменение не требуется.

Пример на главном сервере с ранее использовавшимся расположением Node.js:

```bash
cd /var/www/trioz &&
export PATH="/opt/tzbiz-node22/current/bin:$PATH" &&
ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci --include=dev &&
npm run migrate &&
NODE_OPTIONS="--max-old-space-size=4096" npm run build &&
pm2 restart trioz --update-env &&
pm2 save
```

Перед этой цепочкой получите нужную версию кода через `git pull --ff-only`. Не используйте `git reset --hard` при несохранённых локальных изменениях. Если какая-либо команда завершается ошибкой, остановитесь и исправьте её, не перезапускайте старую сборку как будто обновление завершено. Сохраните `.env` и используйте прежнего владельца процесса PM2. Путь к Node.js — пример из текущего размещения; при другом расположении используйте свой Node.js 22.

Для отката интерфейса верните предыдущий код и пересоберите его. Новые поля добавочные; удалять таблицу/колонки или историю миграций для отката кода не нужно.

## Приёмка после развёртывания

1. В личном и групповом чате отправить внешнюю ссылку с карточкой и без неё; проверить после перезагрузки и со второго аккаунта.
2. Скрыть карточку только у читателя: у автора и второго читателя она остаётся. Обновить страницу, затем вернуть.
3. Автором убрать карточку у всех; проверить открытый второй клиент и историю после перезагрузки, затем вернуть.
4. Проверить ветку ответов, отложенную отправку, ошибку отправки и повторную отправку.
5. В защищённом чате убедиться, что запросов к `/api/link-preview` и внешним изображениям нет.
6. Проверить ссылки сторонних сайтов с обложкой, без обложки, с недоступной картинкой и перенаправлением.
7. Просмотреть все 11 системных разделов, формы и диалоги в двух темах и на телефоне. Проверить, что прежние права ADMIN/EDITOR и доступ CONSULTANT к своим проектам не изменились.

QA-скриншоты, локальный стенд, логи прогонов, `node_modules` и результаты сборки в архив исходников не включены.
