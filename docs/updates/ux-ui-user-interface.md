# UX/UI: группа, профиль и настройки

## Что изменено

- UX-01: приватность и showOnline сохраняются одним PATCH /api/profile/privacy и одним UPDATE пользователя. HTTP-ошибка/обрыв сети не объявляется успехом. Выбор в форме остаётся для повтора.
- UX-02: исправлен контракт статуса: добавлен PATCH (customStatus/statusEmoji), существующий PUT присутствия сохранён. Сохранение/очистка проверяют ответ; очистка не стирает форму до подтверждения сервера.
- UX-03: ошибка стены показана рядом с формой, есть повтор. Текст, заголовок и ссылки на загруженные вложения восстанавливаются через sessionStorage отдельно для каждого пользователя. При повторе неизменённой публикации передаётся тот же clientRequestId. Сервер использует детерминированный ID с автором и уникальность существующего PK: повтор/конкурентная отправка не создаёт вторую запись. Изменённое содержимое с тем же ключом — 409. Ошибка рассылки подписчикам не выдаётся за неудачную публикацию.
- UX-04: у вопросов разделены загрузка, подтверждённый пустой список и ошибка. Повтор доступен; устаревший ответ не перезаписывает новый. При неудачном обновлении той же выборки данные не очищаются.
- UX-05: адаптивные SettingsRow/Choice/Tabs/Slider, контролы присутствия, ползунок усиления, строки эквалайзера, демонстрационный ответ. Подсказки вынесены в ограниченный viewport portal: скрытые подсказки не расширяют документ. Горизонтальное переполнение не замаскировано глобальным overflow:hidden.
- UX-06: общий useModalFocus для QA, Calendar, Docs preview, Tasks и подтверждений. Tab/Shift+Tab, Esc, возврат фокуса; стек для вложенных окон. Диалоги имеют доступное имя. В QA Esc с черновиком сначала запрашивает подтверждение.
- UX-07: профиль показывает безопасные ссылки website/GitHub/Telegram/VK. Разрешены явные http/https без credentials; javascript/data/file не выводятся. Внешняя вкладка получает noopener/noreferrer/nofollow и читаемый домен.
- UX-08: основные кнопки стены, вложений, подписок и переключатели получили область от 44 px. Удаление записи требует подтверждения. Обложки и оформление профиля сохранены.
- UX-09: контраст кнопки сохранения, статистики, счётчика био и нижней навигации исправлен в самих компонентах, без глобальных !important.
- UX-10: label связан с первым реальным контролом, в том числе вложенным. Переключатели сообщают role=switch/aria-checked; результаты — через live regions.
- UX-11: несохранённое «О себе» восстанавливается в той же вкладке; состояние dirty и предупреждение об уходе. Несохранённость имени, статуса, ссылок, приватности и уведомлений также обозначается. Черновики паролей, токенов и E2EE-ключей не сохраняются. При недоступном хранилище интерфейс не утверждает, что черновик сохранён.
- Отдельное UX-предложение: «Редактировать профиль» ведёт прямо в /settings?section=profile. Управление TZ ID осталось отдельной ссылкой.

## Границы сохранения

Локальный черновик — sessionStorage этой вкладки, не серверная синхронизация и не вечный архив. Он может исчезнуть после закрытия вкладки/очистки данных; состояние не переносится на другой компьютер. Вложения — уже загруженные ссылки, не байты ещё не отправленного файла. При заблокированном sessionStorage форма остаётся в памяти и предупреждает об уходе. Для остальных перечисленных полей используется dirty-предупреждение, а не сохранение всего профиля в локальном хранилище.

clientRequestId необязателен для совместимости старых клиентов. Защита повторов действует для нового клиента с тем же ключом; после изменения содержимого создаётся новый запрос. Письма/уведомления не получили систему гарантированной доставки в этой задаче.

## Обновление

1. Сделайте резервную копию БД, конфигурации (.env, ecosystem/PM2), uploads/storage. Не заменяйте рабочий .env примером.
2. Распакуйте `sreda-main` из архива в локальный репозиторий проекта. Проверьте git diff и включите новые файлы hooks/lib/tests/scripts/docs в коммит. Не заменяйте папку .git.
3. Закоммитьте изменения и отправьте в нужную ветку. После проверки/merge в main обновите основной сервер:

```bash
cd /var/www/trioz && git pull --ff-only origin main && npm ci && npm run migrate && NODE_OPTIONS="--max-old-space-size=4096" npm run build && pm2 restart trioz --update-env
```

При локальных изменениях git pull остановится — сначала разберите их. Не используйте reset --hard без резервной копии. Перезапуск идёт только после успешной сборки. Новых миграций схемы БД эта доработка не добавляет; стандартный migrate оставлен для совместимости процесса проекта. VPN-агент, дочерние серверы и Android обновлять из-за этих UI-правок не нужно.

4. Проверьте собственный/чужой профиль, запись на стене, настройки приватности после reload, вопросы группы и мобильное меню. Состояние PM2 и логи: `pm2 status`, `pm2 logs trioz --lines 100`.

## Автоматические проверки

```bash
npm ci
npm run lint -w apps/web
npm test -w apps/web -- --maxWorkers=2
npm run typecheck -w apps/web
npm run build
```

Браузерные тесты запускаются только на отдельной тестовой БД, никогда на production: они создают сообщения, меняют профиль и приватность.

1. Подготовьте PostgreSQL с именем БД, содержащим `test`, `audit` или `ux`; примените схему/миграции проекта. Задайте DATABASE_URL, NEXTAUTH_SECRET, NEXTAUTH_URL=http://localhost:3100, PORT=3100. Запустите Redis или локальный fallback проекта.
2. Для QA окружения установите Playwright/axe (они не добавлены в runtime-зависимости): `npm install --no-save --package-lock=false playwright axe-core`, затем `npx playwright install chromium`.
3. Запустите `UX_ALLOW_TEST_SEED=1 node scripts/qa/seed-ux-ui.cjs`. Секрет берётся только из окружения. Тестовая cookie записывается в /tmp/trioz-ux-auth.json, не в репозиторий; удалите её после прогона.
4. Соберите и запустите приложение с указанным окружением. Затем:

```bash
node scripts/qa/ux-ui-profile.cjs
node scripts/qa/ux-ui-group.cjs
node scripts/qa/ux-ui-layout.cjs
```

Параметры: UX_BASE_URL, UX_AUTH_FILE, UX_RESULT_DIR, CHROMIUM_PATH (необязателен). Для группы нужны подготовленные синтетические данные seeder. Используйте свежую тестовую БД при повторной приёмке: сценарий публикации проверяет количество созданных записей. Матрица layout записывает результаты и отдельные axe JSON; проверка полноты: 80 записей, scroll <= width в каждой. Браузерные скрипты используют bypassCSP только для инъекции тестового axe; это не проверка безопасности CSP.

## Что не заявляется проверенным

Физические Android/iOS, Safari/WebView и экранная клавиатура; реальные голосовые звонки/TURN/камера; полный цикл загрузки и предпросмотра каждого формата документа; все права модерации и создание всех сущностей; совместный холст; платежи, VPN, E2EE-восстановление. Содержимое iframe может иметь собственную обработку клавиатуры. Автоматический axe — не сертификация доступности и не замена проверки скринридером.
