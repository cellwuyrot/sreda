# Выбор сервера для профиля AmneziaVPN в веб-версии

## Причина

В окне TZ выбор сервера был доступен только при наличии desktop-моста и уже созданного профиля. В браузере этот блок скрывался, а POST `/api/vpn/me` не принимал выбранный `nodeId`: при первом создании узел подбирался автоматически.

## Исправление

- В окне TZ на `/connect` сервер можно выбрать в браузере, в том числе до первого создания профиля. Доступно обновление списка.
- Для нового веб-профиля нужно явно выбрать сервер. Существующий сервер профиля подставляется как текущий выбор.
- В браузере нажатие на сервер только меняет выбор. Создание/перенос выполняется после нажатия «Скачать профиль для AmneziaVPN». Затем доступны скачивание `.vpn`, резервного `.conf` и QR-код.
- Выбранный `nodeId` передаётся в POST. API проверяет назначение VPN, включённость, свежесть отчёта, параметры подключения и наличие мест. При ошибке выбранный узел **не подменяется** другим.
- При перевыпуске на своём сервере заполненность не мешает: новый слот не нужен. При переносе адрес выбирается для нового узла.
- API возвращает фактический `nodeId`; интерфейс больше не подставляет старый идентификатор. Файл и QR привязаны к узлу и параметрам профиля. Смена выбора скрывает старый экспорт до создания нового.
- При обновлении списка явный выбор сохраняется. Если сервер исчез, создание блокируется, а не переключается на другой сервер.
- В приложении сохранено переподключение активного туннеля после смены сервера. PATCH также проверяет свежесть отчёта целевого узла.
- Приватный ключ остаётся на устройстве; на сервер отправляются публичный ключ, режим и `nodeId`. Проверки подписки, блокировки аккаунта и ограничения частоты запросов сохранены.

**Важно:** прежнее правило «один аккаунт — один профиль подключения» сохранено. После создания профиля для другого сервера импортируйте новый файл в AmneziaVPN: старый профиль для прежнего узла перестанет работать. Сам браузер VPN не включает.

Клиенты API, которые не передают `nodeId`, сохраняют прежнюю логику. Новая веб-панель передаёт явный выбор.

Изменены только:

1. `apps/web/src/app/api/vpn/me/route.ts`
2. `apps/web/src/app/api/vpn/me/route.test.ts`
3. `apps/web/src/components/connect/overlays/PremiumInfoModal.tsx`
4. `apps/web/src/components/connect/overlays/PremiumInfoModal.test.tsx`

Добавлен этот документ в `docs/updates`. Код проектов, мониторинга, оплаты, выдачи подписок Business/TZ ID, VPN-агента, схема БД и миграции не изменялись.

В архив не возвращены 118 ранее согласованных QA-артефактов: удаление сверено по точным путям, размерам и SHA-256 исходного архива. Рабочие ресурсы (включая `docs/logostol.png`), тесты и миграции сохранены. Новые скриншоты, временные стенды, `node_modules` и `.next` в архив не включены. Полный сырой вывод локальных команд также не добавлялся в проект.

## Проверки

- Полный Vitest с `--maxWorkers=2` и переменными окружения CI: **191 файл, 2579 тестов — успешно**.
- Отдельный регрессионный прогон API и окна подключения: **57 тестов — успешно**.
- Типизация web и desktop: успешно.
- Полный ESLint и повторная проверка изменённых файлов: успешно.
- Production-сборка `npm run build`: успешно.
- Локальный Chromium, реальные компоненты и генератор профиля, подменённые ответы API: пять сценариев на ширинах 390/1440, светлая/тёмная тема. Проверены первый выбор, экспорт/QR, отказ выбранного узла, отсутствие серверов и заполненный сервер. Проверено содержимое обоих скачанных файлов: адрес выбранного сервера совпадает в `.vpn` и `.conf`. Приватный ключ не отправляется в запросе выдачи.

Предупреждения Next о старом имени middleware и широком tracing в существующем маршруте загрузки проектов не относятся к этому изменению. Эти файлы не менялись.

Локальные проверки не заменяют рукопожатие с рабочим VPN-узлом. Удалённый сервер и реальные аккаунты при подготовке архива не использовались; платежи не создавались.

## Обновление на сервере

Сначала перенесите изменения из архива в свой репозиторий, проверьте diff и отправьте их в Git. Не удаляйте существующие `.git`, `.env`, пользовательские загрузки и рабочие конфигурации. Архив — исходники, а не готовая папка `.next`.

После push, при чистом рабочем дереве сервера:

```bash
cd /var/www/trioz &&
export PATH="/opt/tzbiz-node22/current/bin:$PATH" &&
git pull --ff-only &&
ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci --include=dev &&
npm run build &&
/usr/bin/pm2 restart trioz --update-env &&
/usr/bin/pm2 save
```

Миграции для этого исправления не нужны. Business, TZ ID и агент VPN-узла обновлять из-за него не требуется. Если `git pull` сообщает о локальных изменениях — остановитесь и разберите их, не используйте `reset --hard`.

### Приёмка на рабочем узле

1. Войдите в TrioZ под аккаунтом с действующим доступом к соединению или Premium.
2. Откройте `/connect` → TZ. Выберите сервер по имени/региону.
3. Создайте профиль, скачайте `.vpn` и импортируйте в AmneziaVPN. Дождитесь очередного отчёта агента, затем проверьте подключение/рукопожатие.
4. При необходимости сверяйте `Endpoint` скачанного `.conf` с выбранным узлом. Не публикуйте файл: в нём есть приватный ключ.
5. Выберите другой сервер: старые кнопки экспорта/QR должны скрыться. Создайте и импортируйте новый профиль, проверьте новый узел.
6. При недоступном/заполненном узле должна появиться ошибка без выдачи профиля для другого сервера и без новой оплаты.
