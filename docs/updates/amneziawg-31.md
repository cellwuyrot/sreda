# TZ Connect: поддержка AmneziaWG 3.1

## Статус и границы

Это обновление исходного проекта на базе `TrioZ-Android-TrustTunnel-diagnostics-full.zip`.
Оно не устанавливалось на серверах и не меняет автоматически конфигурацию AWG.
Обновление кода само по себе не активирует новые функции на FINLAND.

На FINLAND подтверждён загруженный модуль 3.1.20260812. Его переустановка не нужна.
Отсутствие HeaderProtectionKey означает, что защита заголовков этим ключом не настроена.
Вывод showconf с названиями параметров не позволяет определить их значения: некоторые
из них могут быть нулевыми или значениями по умолчанию. Надпись версии в приложении
также не доказывает, что включены все функции защиты.

## Что изменено

1. Агент передаёт новые параметры из секции Interface через отдельный allowlist.
   PrivateKey, PresharedKey, скриптовые hooks и параметры Peer в него не входят.
2. API отчётов больше не отбрасывает имена длиннее восьми символов. Теперь принимаются
   только известные параметры AWG; явные boolean для двух переключателей сохраняются.
3. Добавлена валидация HeaderProtectionKey, диапазонов 0..65535, переключателей,
   префиксов S1–S4 при защите заголовков и непересечения диапазонов H1–H4.
   Для конфигурации 3.x допускаются стандартные H1–H4=1/2/3/4 и S1–S4=12.
4. Сборщик .conf и экспорт vpn:// передают новые поля, включая явные 0/false,
   без придумывания ключей и без принудительной надписи «3.1» для старых настроек.
5. Импорт ключа TRIOZ-NODE сохраняет новые параметры вместо их отбрасывания.
6. Если объявленные узлом параметры некорректны, nodeTunnel не выдаёт пригодный
   публичный ключ подключения. Тихого отката на профиль обычного WireGuard нет.
7. Оба desktop-парсера сохраняют новые поля. В userspace helper имена преобразуются
   в snake_case, HeaderProtectionKey переводится из base64 в hex для UAPI.
8. Windows amd64: официальный amneziawg.exe 3.1.0 в исходном архиве УЖЕ совпадал
   с официальным релизом. Он сохранён; добавлен соответствующий awg.exe.
   Все три компонента закреплены контрольными суммами. Сборка проверяет их после vendoring.
9. Android arm64-v8a: вместо Maven com.zaneschepke:amneziawg-android:2.3.7 подключён
   локальный модуль awg-tunnel: Java-код официального v3.1.20260814 и совпадающий JNI
   из APK того же релиза. Исправлены API вызова GoBackend и имя системного VpnService.
   Системный допуск VPN, защита сокетов upstream, запрет hooks и проверка handshake сохранены.

## Новые параметры

HeaderProtectionKey, ContentPaddingAddition, RekeyAfterTime, RekeyTimeout,
RejectAfterTime, KeepaliveTimeout, MaxHandshakeAttempts, RandomTrailers, DisableCookies.

Все они передаются только если явно присутствуют в конфигурации узла.
Агент читает файл из WG_CONF_PATH или /etc/amneziawg/awg0.conf (и прежний fallback),
а не defaults работающего модуля. Поэтому только обновить агент недостаточно,
если новые параметры отсутствуют в файле. Перед активацией нужно согласовать
постоянный конфиг, фактическое состояние интерфейса и клиентские профили.

HeaderProtectionKey — общий ключ защиты заголовков, доступный допущенным VPN-клиентам;
его нельзя публиковать в журнале диагностики или присылать вместе с полным профилем.
Он не заменяет приватные ключи сервера и клиентов.

## Порядок внедрения

Перед началом: резервная копия проекта и БД; серверные конфиги и ключи — в закрытой
резервной копии на сервере, НЕ в репозитории. Сравните архив со своей актуальной веткой:
если после исходного архива были другие доработки, переносите diff, не заменяйте проект вслепую.

1. Перенесите изменения в свой репозиторий, проверьте diff и включение новых файлов
   и нативных компонентов. Если .gitignore исключает resources/jniLibs, понадобится
   осознанный git add -f для закреплённых компонентов или собственный эквивалент в CI.
2. Проверьте компоненты: `node scripts/verify-awg31-components.mjs`.
3. Соберите Windows x64 и Android arm64-v8a из этого проекта обычным процессом.
   До изменения серверных настроек установите обновлённые приложения пользователям.
   Проверки на реальных устройствах и полноценная сборка установщиков здесь не выполнены.
4. Обновите основную веб-часть обычным процессом сборки/развёртывания. Миграций БД
   именно для этих изменений нет. Не запускайте seed/reset ради этого обновления.
5. На FINLAND выясните путь исходников активного агента:
   `systemctl show trioz-vpn-agent -p WorkingDirectory --value`.
   Обновите нужный checkout, включая ВСЕ файлы apps/vpn/src, в том числе новый
   awg-params.mjs. Затем `node --check apps/vpn/src/index.mjs` из корня проекта
   и `sudo systemctl restart trioz-vpn-agent`. Это не команда перезапуска awg0,
   но агент по своей обычной логике продолжает синхронизировать доступы/пиры.
6. Дождитесь нового отчёта узла. Старые настройки 2.x остаются старой конфигурацией —
   это нормальное поведение, а не причина добавлять фиктивную метку версии в экспорт.
7. Только после готовности клиентов — отдельное окно переключения параметров AWG.
   Конкретный профиль выбирается по фактическим значениям текущего конфига и
   рекомендациям upstream. Здесь нет автоматической генерации/применения нового HPK,
   перезаписи H1–H4 или массовой ротации клиентских ключей.
8. После согласованной активации клиентам нужно переподключиться и получить свежие
   настройки. Скачанные профили AmneziaVPN нужно заново скачать и импортировать.
   Актуальность кеша и подпись версии проверить в используемой версии AmneziaVPN.

Не запускайте deploy/awg-node.sh --reset и не удаляйте AWG через AmneziaVPN:
это другая установка — нативный awg0 под systemd, не контейнер приложения.

## Проверки и ограничения

См. соседний `amneziawg-31-checks.md` для фактически выполненных локальных проверок.
Ни один тест не подключается к пользовательскому VPN или не меняет серверы.

Не собраны и не подписаны EXE/APK. Не проверены реальный запуск JNI на Android,
VPN consent/foreground service, Windows UAC/service install, реальные handshakes,
скорость, энергопотребление, обновление с установленной старой сборки и отображение
версии в AmneziaVPN. Это требует проверки на целевых ОС; локальные тесты её не заменяют.
Linux/macOS helper сериализует новые параметры, но нативные бинарники для них здесь
не обновлялись и не проверялись — им нужен совместимый backend 3.1.

Отдельно: кнопка «Точка подключения» по-прежнему использует window.prompt;
её UI не переделывался в рамках поддержки протокола.

## Откат

До активации новых серверных параметров: верните предыдущую версию веб-части,
агента и приложений обычным способом. Серверный AWG-конфиг не менялся.
После активации: сначала согласованно верните закрытую резервную копию параметров
узла и совместимые клиентские профили, затем откатывайте приложения/веб/агент.
Просто поставить старый клиент на узел с новым HPK нельзя.
Не меняйте Endpoint на FINLAND ради отката версии, если хотите сохранить каскад.
