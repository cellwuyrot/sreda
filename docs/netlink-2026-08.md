# Надёжное соединение и подписка «Ускоренный интернет» (NETLINK)

Дата: 2026-08. Маркер в коде: `NETLINK`.

## Зачем это сделано

Раньше сервис умел только два состояния — «выдан доступ» и «не выдан». Сколько
человек израсходовал, что будет при исчерпании и на каком сервере он сидит — не знал
ни он, ни администратор. Лимит без учёта расхода — это не лимит, а намерение.

## Что появилось

### Учёт трафика

- `VpnSettings`: `trafficLimitGb` (по умолчанию **250**), `usagePeriodDays` (30),
  `overLimitAction` (`BLOCK` / `THROTTLE`), `throttleKbps` (2048).
- `VpnPeer`: `rxBytes`, `txBytes` (накопленный расход за период), `lastRx`, `lastTx`
  (последние кумулятивные значения с узла), `usageResetAt`.
- Миграция `20260921000000_connection_traffic` — только `ADD COLUMN IF NOT EXISTS`.
- Тип `Float`, а не `BigInt`: `BigInt` не сериализуется в JSON и падал бы в ответах API.
- Период у каждого свой и сбрасывается лениво — при очередном отчёте узла. Никакого
  глобального «первого числа месяца»: подключившиеся 30-го получали бы лимит на день.

### Агент узла (`POST /api/servers/report`)

Добавлено поле `transfers: [{ publicKey, rx, tx }]` — **кумулятивные** счётчики WireGuard
(`wg show ... transfer`). Сервер сам считает дельту и переживает перезапуск узла
(если новое значение меньше прежнего — счётчики обнулились, берётся вся величина).

В ответе узлу:

- пиры с исчерпанным лимитом при `BLOCK` в список **не попадают**;
- при `THROTTLE` попадают, но с полем `throttleKbps` — ограничение скорости ставит узел
  (`tc`), сервер лишь сообщает цифру.

### Администратор (`/admin/vpn`)

Новая секция «Что входит в подписку» стоит **выше** параметров туннеля: условия тарифа
видят подписчики, а DNS и маршруты — никто.

- лимит в ГБ на одного (0 — без ограничения, расход всё равно считается);
- длина расчётного периода;
- правило при исчерпании и потолок скорости;
- сводка: подписчиков, сколько на связи, израсходовано, сколько вышли за лимит;
- в каждом узле — загруженность в процентах и прокачанный трафик.

Premium и «Ускоренный интернет» по соединению равнозначны — один лимит, одни серверы.
Отдельной настройки на два тарифа сознательно нет: два поля вместо одного неизбежно разъедутся.

### Клиент: кнопка «TZ»

`components/connect/overlays/ConnectionMenu.tsx` — оборачивает старый значок `PremiumMark`
(раскраска не дублируется) и добавляет плашку:

- состояние (точка на значке видна без открытия);
- тариф и срок подписки;
- остаток трафика полоской и дата сброса;
- выбор сервера с его загруженностью (`PATCH /api/vpn/me`);
- «Выключить» (`DELETE /api/vpn/me`) и «Настроить» — ведёт в окно, где выдаются ключи.

Выдача ключей в плашке не дублируется нарочно: приватный ключ показывается один раз, и его
надо успеть сохранить — узкая плашка, закрывающаяся по клику мимо, для этого не место.

Смена сервера меняет адрес и точку подключения, поэтому ответ содержит `needsReissue: true`,
а человеку сразу говорится перевыпустить профиль: иначе тишина после переезда читается
как поломка сервиса.

### Слова

Видимые тексты: **Надёжное соединение**, подписка **«Ускоренный интернет»**
(`lib/connectionCopy.ts` — один источник названий).

Технические имена не переименованы сознательно: `VpnPeer`, `VpnSettings`, `kind: "VPN"`,
`/api/vpn/*`, `/admin/vpn`, `lib/vpn.ts`. Переименование потребовало бы миграции базы и
обновления агентов на всех узлах, не изменив ни одной строки на экране.

## После развёртывания

1. `npx prisma migrate deploy && npx prisma generate`.
2. Научить агентов узлов присылать `transfers` и уважать `throttleKbps`.
   До этого расход будет нулёвым, а лимит — недостижимым.
3. Проверить в `/admin/vpn`, что лимит = 250 ГБ и правило при исчерпании выбрано осознанно.
