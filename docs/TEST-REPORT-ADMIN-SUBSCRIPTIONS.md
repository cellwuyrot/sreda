# Проверки обновления «Подписки пользователей»

## Успешные проверки
- Полный набор `npm run test -w apps/web -- --maxWorkers=2`: **2490 тестов, 182 файла, все прошли**.
- Отдельный первоначальный регрессионный прогон центрального реестра, экрана, листания, перенаправления платежей и serviceHub: **34 теста, 5 файлов, все прошли**. Эти проверки входят в полный прогон и не суммируются с ним.
- `npm run test -w apps/id`: **8 тестов прошли**.
- `npm run lint -w apps/web`: успешно.
- `npm run typecheck -w apps/web`: успешно.
- `npm run build`: успешно (общий пакет, Prisma Client, Next.js production build).

## Что проверяют новые тесты
- ADMIN/EDITOR, отказ обычному пользователю и анонимному запросу до чтения базы.
- EDITOR не получает email и не ищет по нему.
- Чтение центральных подключений одним ограниченным запросом; исключение удалённых пользователей, безопасное листание, no-store.
- Просроченное подключение не показывается действующим даже до прохода фоновой задачи истечения.
- Ответ не содержит ключей клиента, внешних платёжных идентификаторов; GET не выдаёт права и не пишет в подключения.
- Сбой базы — ошибка 503, а не успешный пустой список; технические детали не раскрываются.
- Лимит истории показан явно, пустой список не вызывает лишний запрос подключений.
- На экране видны услуга и права Premium/соединения; нет форм «Подписка + оплата» и реквизитов.
- Перезагрузка по кнопке и фокусу; повтор после ошибки; сохранение поиска и листания.
- Старый адрес платежей перенаправляет на подписки.
- Профиль использует только переход к настроенным предложениям Business без загрузки старых ручных реквизитов.

## Визуальная проверка
Отрисованы реальные React-компоненты с тестовым API и сессией, не production-сайт. Просмотрены по одному: мобильный тёмный экран с VPN/Premium, светлый desktop, мобильные пустой список и ошибка. Горизонтального переполнения, пересечений и ошибок JS не обнаружено. Снимки находятся в `docs/qa-admin-subscriptions/`.

## Границы проверки
Тесты используют подмены базы, сессии и сети. Сервер пользователя и его production-база не менялись. Реальные банковские операции, SSO и VPN на устройстве не выполнялись. Успешный банковский платёж и доставка прав из Business по действующей серверной интеграции остаются отдельной проверкой после развёртывания; чтение реестра не заменяет обработку очереди Business.

Новых миграций, зависимостей или env-переменных нет. Исторические платёжные данные и обработчики не удалялись: изменён текущий интерфейс подписок и навигация.
