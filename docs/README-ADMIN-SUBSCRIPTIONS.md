# Подписки пользователей: единый реестр, оформление в Business

Это полный основной проект sreda с предыдущими улучшениями TZ.Connect и новым исправлением админки.

## Изменения
- `/admin/premium` больше не использует старые формы «Подписка + оплата» и ручную выдачу, не связанную с Business. Экран показывает пользователей, фактические флаги доступа по тем же правилам, что приложение, и подключения из центральной таблицы `TzManagedConnection`, которую записывает интеграция Business/TZ ID.
- Для подключения показаны услуга, тип, состояние, срок и ожидание ручного подключения/отключения. Premium включает соединение. Доступ по роли администратора отделён от покупки.
- Чтение происходит напрямую из центральной базы без копирования платёжных данных: каждые 30 секунд, при фокусе окна, по кнопке «Обновить». Страница и API не кэшируют ответ. Нет N+1 запросов: подключения выбранной страницы загружаются одним запросом.
- Поиск, листание, сообщение об ошибке с повтором. Ошибка не означает отсутствие подписки. После 1000 подключений на странице показывается явное предупреждение уточнить поиск.
- Удалены «Платежи» из «Сервисы и система» и быстрого доступа. Старый адрес `/admin/payments` перенаправляет на `/admin/premium`.
- Удалены ручные реквизиты оплаты подписок в настройках профиля и запрос `/api/payments/methods` из настроек. Переходы к опубликованным предложениям Business сохранены.
- Финансовые таблицы, прежние записи и старые API не удалены; это не миграция финансового архива и не демонтаж всех исторических платёжных обработчиков. Данные не обнуляются. Новый экран не создаёт платежи и не выдаёт права по нажатию администратора.

## Граница синхронизации
Платёж подтверждает банк в Business, затем Business передаёт доступ в TZ ID / основной проект по уже настроенной серверной интеграции. Новый экран читает её результат, не пытается самостоятельно списать деньги или признать заказ оплаченным. Если Business не смог передать доступ и задача осталась в очереди, обновление страницы не заменяет исправление интеграции. Выполненные ранее платежи не симулируются.

Доступ к реестру: ADMIN и EDITOR основного проекта. EDITOR не получает email и не может искать по email. Права администратора отдельного проекта не превращаются в глобальные права основного проекта.

## Развёртывание
Новых зависимостей, env-переменных, миграций в этом обновлении нет. Нужны ранее настроенные общие услуги и база. Не заменять `.env`, базу и пользовательские загрузки из архива.

После загрузки исходников в Git выполните на сервере:

```bash
cd /var/www/trioz &&
export PATH="/opt/tzbiz-node22/current/bin:$PATH" &&
git pull --ff-only &&
npm ci --ignore-scripts &&
npm exec -w apps/web -- prisma generate &&
npm run test -w apps/web -- --maxWorkers=2 &&
npm run build &&
/usr/bin/pm2 restart trioz --update-env &&
/usr/bin/pm2 save
```

Перезапускается только `trioz`. `tz-id` и `tzbiz` этим обновлением не изменяются.

## Проверка после запуска
1. В админке проверить отсутствие «Платежи» в системном разделе и быстрых ссылках.
2. Открыть «Подписки пользователей», найти аккаунт с успешно синхронизированным подключением Business. Сверить услугу и срок с «Услуги и доступ» в TZ ID.
3. Для Premium проверить оба права, для отдельного соединения — только соединение.
4. Вернуться в окно после изменения подключения в Business: список должен обновиться. Кнопка «Обновить» выполняет только чтение, не повторную оплату.
5. В профиле проверить отсутствие ручных реквизитов; оформление открывает Business отдельной вкладкой.
6. При проблеме загрузки должна показываться ошибка, не пустой успешный список.
