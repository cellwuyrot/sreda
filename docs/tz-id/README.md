# TZ ID — единый аккаунт TrioZ

## Что реализовано

- `https://id.trioz.ru` — отдельный OAuth 2.0 / OpenID Connect issuer на `oidc-provider` 9.12.2. Он запускается отдельным процессом PM2 `tz-id`, слушает только `127.0.0.1:3100`.
- **Один существующий User**: `sub` = неизменяемый `User.id`. Новая база паролей / второй пользователь не создаются. Проверка пароля, лимиты попыток входа и проверка блокировки вынесены из текущего Credentials provider в общий `tzIdCredentials.ts`.
- Регистрация, подтверждение и восстановление email/пароля остаются в существующем TrioZ. Сам issuer предлагает вход существующего аккаунта и ссылку на эти формы.
- Код авторизации + обязательный PKCE S256; подписанные RSA ID tokens, opaque access/refresh tokens, discovery, JWKS, userinfo, revocation, introspection и RP-initiated logout.
- У каждого приложения свой client_id; confidential client получает отдельный client secret. Redirect URI точные, HTTPS, без wildcard, credentials и fragment. Открытая динамическая регистрация выключена.
- Разрешение пользователя содержит имя приложения, origin его callback и запрошенные scopes. Пароли, переписка, роли, Premium, платежи и VPN-ключи не являются внешними claims.
- Клиенты, artifacts и разрешения сохраняются в PostgreSQL. Секретная metadata и payload artifacts зашифрованы AES-256-GCM; ключи artifacts — SHA-256 от model + opaque identifier. Повторное потребление code/refresh token блокируется атомарно.
- Консоль администратора: **Админ → Сервисы и система → TZ ID**, `/admin/tz-id`. Создание, список и включение/отключение приложений. Secret показывается после создания, но не возвращается списком. При отключении существующие разрешения отзываются; повторное включение их не восстанавливает.
- Настройки: **TZ ID**, **Безопасность**, **Приложения**, **Профиль**, **Конфиденциальность**. Постоянный ID копируется; соцстатистика вынесена в «Профиль», кеш десктопа — в TZ.Connect. Сохранены старые `?cat=` ссылки, добавлены `?section=tzid|security|applications`; выбранный раздел сохраняется в URL.
- Социальные страницы `/profile`, `/profile/[username]`, стена и текущие связи сохранены. Кнопка своей страницы ведёт в управление TZ ID.
- Текущий вход через Credentials сохранён. По настройке first-party client доступна дополнительная кнопка **Войти через TZ ID** в браузерной версии. NextAuth проверяет state, nonce, PKCE и ID token; локальная роль загружается из User, а не из claims; поиск по email для привязки не используется.
- В Electron/Android существующий Credentials flow **не заменён**. Новая кнопка SSO там намеренно скрыта: полноценный system-browser/deep-link callback для нативных оболочек — отдельная задача. Настройки аккаунта доступны как прежде.

## Сеансы и отзыв доступа

JWT TrioZ теперь связан с `UserSession.id` через `sid`. Подпись cookie сама по себе больше не даёт доступ: API/новое Socket.IO подключение проверяют активный, неистёкший сеанс и состояние пользователя. При отзыве через web существующие связанные сокеты отключаются.

- «Завершить другие сеансы» оставляет текущий сеанс TrioZ и закрывает остальные, включая сеансы TZ ID.
- «Отключить приложение» отзывает все разрешения этого приложения **только для текущего пользователя**.
- Смена обычного пароля и сброс пароля обновляют `passwordChangedAt` и закрывают сеансы. После смены пароля интерфейс предлагает новый вход.
- Удаление владельцем аккаунта использует существующее обезличивание вместо физического каскадного удаления User: вход закрывается, личные сведения очищаются, материалы сообществ сохраняются. Это не означает удаление данных, которые уже успели сохранить сторонние приложения.
- OAuth code: 60 секунд; access / ID token: 5 минут; interaction: 10 минут. Cookie/сеанс TZ ID: 2 дня с продлением при активности; сеанс TrioZ также продлевается при проверках не чаще одного DB write в час. Максимальный refresh TTL — 30 дней, **но refresh token не переживает закрытие/истечение связанного серверного сеанса**.
- ID token — доказательство входа для проверяющего приложения, **не bearer token для userinfo**. Уже выданный JWT нельзя «стереть» у другого приложения; срок ID token ограничен. На access/refresh/userinfo/introspection отзыв действует по состоянию БД.
- Выход в самом TrioZ закрывает его текущий сеанс; независимый SSO-сеанс TZ ID может остаться активным. Полный logout issuer или завершение его сеанса в «Безопасности» закрывает именно этот сеанс TZ ID.
- Локальную сессию стороннего проекта сам TZ ID автоматически не уничтожает. Проект должен проверять доступ / выполнять introspection в нужных точках, применять собственный срок сессии и обрабатывать отказ issuer.

## Миграция

`apps/web/prisma/migrations/20261010000000_tz_id/migration.sql`: nullable `UserSession.expiresAt` + `TzIdClient`, `TzIdArtifact`, `TzIdAuthorization`. Никакого пересоздания User / VpnPeer. Новая миграция проверена на прежней схеме с существующим пользователем и сеансом; diff с итоговой Prisma schema — пустой.

**После первого обновления старые JWT без sid перестанут проходить авторизацию. Пользователям потребуется один повторный вход.** Это намеренная граница безопасности, а не потеря аккаунта/профиля. Миграцию нужно применить до запуска нового кода.

VPN, AmneziaWG, AmneziaVPN export, routing, traffic accounting, BLOCK/THROTTLE и существующие исправления чата не переписывались. Ранее удалённые админ-карточки CloudPayments не возвращены.
