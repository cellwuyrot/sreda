# TrustTunnel: подготовительный этап пилота — не выпуск

## Состояние

Это рабочий исходный архив, а не готовый VPN и не инструкция к развёртыванию. Не устанавливать на рабочие серверы и не публиковать сборки. Глобальный провайдер и блокировки готовности не изменены. Исходный Git в архиве отсутствует; имеющийся `.codebase-memory/graph.db.zst` сохранён, но индекс относится к исходному commit из `artifact.json`, а не к изменениям этого архива. Его нужно перестроить штатной системой после внесения изменений в настоящий репозиторий.

## Изменения этого этапа

- `apps/web/src/lib/trustTunnelPilotPolicy.ts` и тест: ограничение пилота пользователем с актуальной ролью проекта ADMIN, не ролью администратора группы. По умолчанию закрыто; заблокированные и удалённые пользователи отклоняются. Это политика доступа, а не механизм аутентификации.
- `GET /api/vpn/trusttunnel/pilot`: после авторизации перечитывает роль и состояние пользователя из БД; без конфигурации отдаёт 404. Разрешённым администраторам отдаёт только `eligible: true, connectionReady: false`. Не выдаёт ключи и не включает VPN. Ответы не кэшируются. Каждый будущий защищённый метод обязан отдельно применять актуальную проверку.
- `vpnProvider.ts`: уточнены устаревшие тексты статуса Endpoint и gateway, все блокировки сохранены.
- `build-desktop.bat`: перед упаковкой запускает существующий `scripts/desktop-version.mjs` и передаёт версию electron-builder. Для архива без Git resolver может выбрать версию `package.json` и она может оказаться ниже текущей опубликованной. Обязательно задать `DESKTOP_VERSION` и убедиться, что она строго выше опубликованной; фактическая сборка и обновление в Windows ещё не проверены.
- Из доставляемой копии исключены 8 резервных файлов `.env` и сохранены `.env.example`. Настоящие серверные env-файлы, Git и untracked файлы не изменять и не перезаписывать архивом.

## Не реализовано и не проверено

Endpoint credentials lifecycle и управление ими, защищённая выдача на устройство, traffic accounting, Android TrustTunnel adapter и APK, Windows TrustTunnel adapter и установщик, UI пилотного подключения, authenticated endpoint health, эксплуатационная готовность и смена глобального провайдера. Нельзя снимать блокировки readiness. Не включать `TRIOZ_TT_PILOT_ENABLED` до завершения реализации.

Тесты политики можно выполнить с Node.js 24: `node --test scripts/trusttunnel-pilot-policy.node-test.mjs`. В изолированном окружении выполнены Vitest-тесты политики, маршрута и прежних блокировок: 13/13 успешно, без реальных серверов и базы. Для повторного запуска необходимы зависимости проекта. Никаких тестов сети/серверов этот файл не запускает.

## Следующие этапы

1. Подтвердить поддерживаемый на установленном TrustTunnel Endpoint интерфейс создания и отзыва per-user credentials, в том числе его модель обновления и безопасного доступа; не использовать общий smoke-пароль.
2. Реализовать изолированный от Amnezia pilot provisioning, безопасное хранение и отзыв, а также учёт трафика и авторизованный health report.
3. Встроить нативный Android SDK, защитить хранение учётных данных, собрать debug APK в Android Studio и проверить только выбранных администраторов. Мобильный IP сейчас не входит в allowlist gateway; отдельно согласовать безопасную сетевую схему, не открывать всем.
4. Интегрировать Windows-клиент и его привилегии, собрать стандартным Electron Builder, согласовать большую версию, проверить существующий механизм обновления.
5. После проверок подготовить полноценный архив, журналы изменений, обновление codebase-memory, миграции и пошаговый план с откатом. Глобальное переключение — только после готовности и отдельного решения владельца.

## Исследование Endpoint 1.1.0

По исходному коду и документации upstream версии v1.1.0 (commit `fab5b8353a19332f935fa30869307d37d4a898d1`), credentials хранятся в `credentials.toml`; описанный SIGHUP перезагружает TLS hosts, а не credentials. Выдачу нельзя строить на предположении, что пользователи автоматически подхватываются без рестарта. Metrics per-client раскрывает имена и IP, поэтому не должна публиковаться в интернет. Источники: https://github.com/TrustTunnel/TrustTunnel/blob/v1.1.0/CONFIGURATION.md и https://github.com/TrustTunnel/TrustTunnel/blob/v1.1.0/endpoint/src/main.rs. Реальный механизм обновления credentials ещё необходимо безопасно спроектировать и проверить отдельно.
