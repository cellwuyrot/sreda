Основа: `cellwuyrot/sreda`, коммит `57e1b8be3f53122904f9ea93425cd53b867fafbd`.

**Статус: подготовлены изменения исходников. Сбой подключения CS2 к матчу не исправлен и не воспроизведён.** Рабочий сервер и GitHub-репозиторий не изменялись. Архив не является готовым установщиком Windows.

## Что изменено

- На круглой кнопке включения VPN отображается расход для Premium и «Ускоренного интернета». В открытом видимом окне данные проверяются каждые 30 секунд и при возвращении фокуса. Сам VPN-узел по умолчанию присылает отчёт раз в 60 секунд, поэтому это не посекундный счётчик скорости.
- Пока узел не прислал телеметрию, вместо выдуманного нуля показывается ожидание отчёта. При сбое обновления сохраняется последнее показание с предупреждением; показания старше двух минут помечаются устаревшими. Закрытое окно и скрытая вкладка не создают периодического опроса.
- Некорректный отчёт с отсутствующим или недопустимым `rx`/`tx` пропускается: раньше отсутствующий счётчик превращался в ноль, что могло привести к повторному начислению накопленного расхода.
- Сохранено и проверено правило: безлимит по роли получает только **ADMIN проекта**. Администратор группы не получает эту льготу. Существующая глобальная настройка лимита `0` по-прежнему означает безлимит для всех; если подписчики должны иметь лимит, в настройках должен быть указан положительный размер.
- Усилено скрытие PowerShell при управлении AmneziaWG; скрыт вспомогательный поиск исполняемого файла. Запрос UAC не обходится. На реальной Windows отсутствие всплывающего окна ещё нужно проверить.
- `apps/desktop/scripts/trioz-diag.ps1` заменён диагностикой только для чтения. Старый вариант сам менял MTU и DNS; новый этого не делает, не читает ключи и не отправляет данные наружу.

## Что намеренно сохранено

AmneziaWG, его бинарники и параметры маскировки; ключи, endpoint, AllowedIPs, MTU 1280, keepalive; серверный агент VPN, firewall/NAT, установщики узла и схема базы данных. Никакого перехода на обычный WireGuard, обхода VPN для CS2 или открытия игровых портов.

## Безопасное применение и откат

1. Распаковать в отдельную папку. Не заменять рабочий сервер целиком и не запускать `deploy/firewall.sh` или установщики VPN-узла ради этого обновления.
2. Сохранить действующие исходники/сборки, локальные конфиги, `.env`, загрузки пользователей и резервную копию БД. Сверить `UPDATE-MANIFEST.json`: там полный перечень изменённых и новых файлов с хешами.
3. Проверить web и новый desktop на тестовом развёртывании/одном Windows 10. Сначала обычный интернет, выключение/включение VPN, оба тарифа, расход и ADMIN; затем CS2. Для изменения поведения Windows нужна пересборка desktop. Версия приложения автоматически не повышалась.
4. Развёртывать только после успешной проверки в вашем окружении. Изменений схемы БД это обновление не требует.
5. Для отката восстановить прежние версии файлов из списка изменений и прежние сборки, удалить добавленные файлы из списка. Ключи и настройки VPN не перевыпускать.

## Следующий шаг для CS2

При подключённом VPN запустить в PowerShell из корня распакованного проекта:

```powershell
powershell.exe -NoProfile -File .\apps\desktop\scripts\trioz-diag.ps1 -Seconds 60
```

Пока идёт запись, попробовать войти на карту. Если политика Windows запрещает сценарий, не менять её глобально: использовать одобренный администратором способ запуска.

Сценарий создаёт `trioz-cs2-diagnostics.json` в текущей папке: интерфейсы, MTU, маршруты, состояния служб, привязки UDP Steam/CS2 и изменение счётчиков адаптера. Файл содержит сетевые адреса — перед передачей просмотреть его. Приложить точный текст ошибки CS2, время попытки и результат такой же попытки без VPN. Эти сведения сузят причину; при необходимости дальше потребуется проверка UDP на рабочем узле. Обычная активность адаптера сама по себе не доказывает доступность игровой сессии.
