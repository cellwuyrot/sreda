# TrustTunnel: экспериментальный TCP-шлюз IPv4 → IPv6

## Статус и область применения

Это тестовый исходный компонент, а не production-развёртывание или готовый VPN. Он не запускается автоматически, не изменяет агент, Nginx, базу и действующий AmneziaWG. Не использовать его для клиентских подключений без проверки модели угроз, нагрузочных и длительных тестов, устойчивого размещения и отдельного разрешения. Существующий тест с настоящим Endpoint и временным Python-прокси подтвердил выбранную сетевую цепочку, но не проверял этот новый компонент.

TCP передаётся как поток без расшифровки и анализа; TLS заканчивается на Endpoint. По умолчанию доступ разрешается только перечисленным IPv4-адресам-источникам. Для клиентов с меняющимися IP предусмотрен отдельный публичный режим, который включается только явной настройкой. Этот режим не является аутентификацией пользователя и не заменяет авторизацию TrustTunnel. Приложение применяет глобальный и per-source лимит соединений, token bucket и ограничение числа отслеживаемых адресов; это не полноценная защита от DDoS, не балансировка и не система наблюдаемости. Шлюз всегда соединяется только с заданным IPv6 endpoint и не передаёт UDP/QUIC. DNS и URL из клиентских данных не используются.

Для запуска нужны Node.js >= 20 и явные локальные настройки процесса. По умолчанию интерфейс прослушивания — только `127.0.0.1`; `0.0.0.0` и IPv4 в качестве назначения запрещены. По умолчанию нужен точный IPv4 allowlist. Для клиентов с динамическими адресами можно явно задать `TRIOZ_TT_GATEWAY_ALLOW_ANY_IPV4=true`; в этом режиме allowlist должен быть пустым. Это публичный вход к одному фиксированному TrustTunnel endpoint, а не общий TCP-прокси; всё равно нужны Endpoint credentials и отдельно согласованная firewall-политика:

| Переменная | Значение |
|---|---|
| `TRIOZ_TT_GATEWAY_BIND` | Конкретный IPv4 интерфейса, по умолчанию `127.0.0.1` |
| `TRIOZ_TT_GATEWAY_PORT` | TCP-порт шлюза, обязателен |
| `TRIOZ_TT_GATEWAY_TARGET_IPV6` | IPv6 назначения без скобок и зоны, обязателен |
| `TRIOZ_TT_GATEWAY_TARGET_PORT` | TCP-порт назначения, обязателен |
| `TRIOZ_TT_GATEWAY_ALLOWED_IPV4` | Разделённые запятыми точные IPv4-адреса; обязательно в allowlist-режиме, CIDR не поддерживается |
| `TRIOZ_TT_GATEWAY_ALLOW_ANY_IPV4` | Только точное значение `true` включает публичный ingress; при этом allowlist должен быть пустым |
| `TRIOZ_TT_GATEWAY_MAX_CONNECTIONS` | 1–256, по умолчанию 32 |
| `TRIOZ_TT_GATEWAY_MAX_PER_SOURCE` | Одновременные соединения на source IPv4, 1–256, по умолчанию 16 |
| `TRIOZ_TT_GATEWAY_SOURCE_RATE_PER_MINUTE` | Скорость открытия соединений на IPv4, 1–3600/мин, по умолчанию 60 |
| `TRIOZ_TT_GATEWAY_SOURCE_BURST` | Начальный token-bucket burst на IPv4, 1–256, по умолчанию 20 |
| `TRIOZ_TT_GATEWAY_MAX_TRACKED_SOURCES` | Максимум отслеживаемых source IPv4, 16–65536, по умолчанию 4096 |
| `TRIOZ_TT_GATEWAY_CONNECT_MS` | 100–30000 мс, по умолчанию 5000 |
| `TRIOZ_TT_GATEWAY_IDLE_MS` | 1000–600000 мс, по умолчанию 60000 |

Переменные не содержат пароли. Шлюз не выводит входящие данные, адреса и авторизационные заголовки в журналы. Приложение и клиент обязаны проверять сертификат и hostname Endpoint; отключать верификацию TLS нельзя. Для рабочего размещения необходимо отдельно решить: ограничение доступа, доступность клиентам с IPv4, TLS и домен, процессный надзор, UDP/QUIC, перезапуски, DDoS и мониторинг. Промежуточный узел не должен превращаться в открытый прокси. IPv6-выход сам по себе не обеспечивает доступ к IPv4-only сайтам.

## Тестирование

```bash
npm run test:gateway -w apps/vpn
```

Тесты используют IPv4/IPv6 loopback, временный TLS-сертификат и тестовый upstream; проверяются explicit public mode и per-source rate limit. Для TLS-теста требуется OpenSSL. Запуск тестов не меняет системную конфигурацию. На системах без IPv6 loopback некоторые тесты пропускаются: это не успешная проверка IPv6. Настоящий TrustTunnel Endpoint, Windows, Android, реальная клиентская сеть, systemd, QUIC, нагрузка и защита от DDoS не проверяются. Не интерпретировать эти тесты как готовность к production.
