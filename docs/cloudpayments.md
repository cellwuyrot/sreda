# CloudPayments: настройка и поток подписок

В проект добавлена серверная интеграция CloudPayments для двух месячных подписок:

- Premium
- «Ускоренный интернет» (VPN)

## Настройка в админке

Откройте:

`Сервисы и система → Платежи`

Для каждой подписки отдельно:

1. Включите интернет-эквайринг.
2. Выберите провайдера `CloudPayments`.
3. Укажите `Public ID CloudPayments`.
4. Укажите `API Secret / пароль API`.
5. Нажмите `Сохранить реквизиты`.
6. После сохранения нажмите `Настроить уведомления`.

API Secret хранится на сервере в зашифрованном виде и не отдаётся клиенту.

## Что происходит при оплате

1. Пользователь нажимает кнопку оплаты.
2. Сервер создаёт внутренний `CloudPaymentOrder` с уникальным `InvoiceId`.
3. Сервер создаёт заказ CloudPayments через `/orders/create` и получает платёжную ссылку.
4. Пользователь переходит на страницу CloudPayments.
5. Для заказа включён месячный рекуррентный сценарий `CreateMonthly`.
6. После оплаты CloudPayments отправляет Pay-уведомление на сервер проекта.
7. Сервер проверяет HMAC, `InvoiceId`, `AccountId`, сумму, валюту и успешный статус платежа.
8. После подтверждения создаётся/продлевается локальная Premium или VPN-подписка.
9. Пользователь возвращается на `/settings`.
10. Страница не доверяет самому факту редиректа: она запрашивает статус заказа у сервера.
11. Если webhook ещё не пришёл, сервер дополнительно может проверить CloudPayments через `/v2/payments/find`.
12. После подтверждения UI показывает успешную оплату и обновляет подписку.

## Webhook URL

Для каждого CloudPayments-терминала используются:

- `POST /api/webhooks/cloudpayments/check`
- `POST /api/webhooks/cloudpayments/pay`
- `POST /api/webhooks/cloudpayments/fail`
- `POST /api/webhooks/cloudpayments/recurrent`

`Pay`, `Fail` и `Recurrent` можно включить кнопкой `Настроить уведомления` в админке.

`Check` необходимо проверить/включить в личном кабинете CloudPayments, если для терминала он ещё не настроен.

## Безопасность

- API Secret хранится только на сервере.
- Webhook проверяется по HMAC `SHA256 + Base64`.
- Сумма и валюта сравниваются с созданным внутренним заказом.
- `InvoiceId` связан с конкретным пользователем и видом подписки.
- Повторное `Pay` с тем же `TransactionId` не выдаёт подписку повторно: транзакции хранятся в отдельном журнале с уникальным идентификатором.
- Редирект пользователя сам по себе не является подтверждением оплаты.

## Ограничение по планам

CloudPayments-поток в текущей реализации выдаёт месячную подписку. Старые одноразовые платёжные ссылки проекта для других сроков остаются доступными отдельно.
