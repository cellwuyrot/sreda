# Два способа подключения и восстановление сети

Это описание актуальнее прежних документов о глобальном выборе провайдера; старые документы сохранены как история. Архив — исходный код для проверки, а не подтверждённый релиз.

## Как работает

- Общий сервис VPN и проверка подписки остаются обязательными. AmneziaWG и TrustTunnel доступны независимо; пользователь выбирает технологию в окне. На одном устройстве оба туннеля одновременно не запускаются. Выбор вкладки сам по себе не запускает и не останавливает VPN.
- Поле `VpnSettings.activeProvider` оставлено для совместимости с БД и старыми клиентами, но серверные маршруты выдачи профилей и снимки узлов больше не используют его как переключатель. Старый API глобального переключения возвращает 410 для ADMIN и не меняет БД. Старые приложения могут отображать прежний интерфейс — обновите клиенты.
- При первом успешном опросе после обновления старые имеющие право AmneziaWG-пиры и TrustTunnel-учётные записи снова попадут на соответствующие узлы независимо от прежнего `activeProvider`. Это может восстановить ранее отключённый доступ и перезапустить endpoint. До обновления заранее проверьте активные записи и согласуйте окно обслуживания; не публикуйте обновление без проверки.
- Общий выключатель услуги по-прежнему выключает оба способа. При его выключении узлам уходят пустые списки; после включения доступ вернётся для разрешённых записей.
- Учёт трафика и квоты TrustTunnel не реализованы. Статистика AmneziaWG не относится к TrustTunnel.

## Профиль TrustTunnel

Кнопка «Отключить TrustTunnel» останавливает локальное соединение и доступна также при ошибке API/службы. «Отозвать профиль» сначала пытается отключить локальный клиент, затем отзывает учётные данные на сервере. «Пересоздать профиль» также сначала отключает локальный клиент, увеличивает поколение ключа и ждёт применения. Оба действия затрагивают все устройства с данным профилем; ни пароль, ни профиль не показываются в окне. Для действия на сервере требуется интернет/доступ к TrioZ. При недоступном агенте отзыв не считается применённым немедленно, а при изменении списка endpoint может перезапустить службу и оборвать другие сессии. Не нажимайте повторно пересоздание в ожидании ACK: это снова поменяет поколение.

## Восстановление сети Windows

Профиль сохраняет `killswitch_enabled = true`. Это защита от передачи трафика в обход VPN, которая может блокировать интернет, пока туннель не восстановлен или не остановлен. Не отключайте её незаметно: выключение защиты меняет модель конфиденциальности. Нажмите «Отключить TrustTunnel» и подтвердите UAC. Если страница TrioZ не открывается, в Windows нажмите правой кнопкой на значок TrioZ в системном трее (при необходимости раскройте скрытые значки), выберите «Аварийно отключить TrustTunnel», подтвердите действие и запрос UAC. Это локальное действие, интернет для него не нужен; после отключения трафик может идти напрямую. Работа службы не доказывает доступность сайтов.

Если интерфейс недоступен, откройте PowerShell **от имени администратора** и выполните только:

```powershell
Stop-Service -Name TrioZTrustTunnel -ErrorAction Continue
Get-Service -Name TrioZTrustTunnel -ErrorAction SilentlyContinue
```

Затем проверьте интернет. Если служба отсутствует, это не причина самостоятельно удалять сетевые адаптеры, маршруты или настройки firewall: обратитесь к диагностике. Остановка локальной службы не отзывает серверный профиль; отзыв можно выполнить позже через приложение. Если интернет не восстановился, причину необходимо диагностировать отдельно.

На Android отключите VPN в приложении или в системных настройках VPN. Не меняйте настройки «постоянный VPN»/«блокировать соединения без VPN» без понимания последствий.

## Что известно о Discord и пинге

Прямой HTTP/1.1 proxy-запрос через gateway и endpoint вернул 200, но это не проверяет путь Windows TUN и HTTP/2. Захват VDS показал один нестандартный поток и HTTP 400; достоверная привязка потока к конкретному запросу Windows и причина не установлены. В исходниках клиент использует HTTP/2 CONNECT, а gateway пересылает TCP; этот факт не доказывает источник ошибки. MTU 1200 ранее не помог; оптимальное значение не доказано. Исследование upstream changelog не подтвердило конкретную ошибку совместимости версий как причину. Высокий пинг тоже не диагностирован количественно. Данное обновление не заявляет, что Discord или задержки исправлены.

## Безопасный порядок проверки и обновления

1. Сделать резервные копии БД и текущего рабочего кода. Не включать реальные env, ключи, пароли и профили в архив или журналы. Проверить, что на сервере единая версия web и прежние ключи синхронизации сохранены.
2. Проверить и согласовать восстановление ранее активных пиров и учётных записей из-за перехода к двум технологиям. Применение снимков может разорвать активные сессии. Не выпускать всем пользователям до изолированной проверки.
3. Проверить состояние миграций, затем штатно обновить код, зависимости, `npm run migrate`, собрать web и перезапустить приложение с сохранением среды. Новых миграций в этом изменении нет; существующие миграции проекта обязательны. Не заменять production env. Не менять настройки gateway, endpoint или агента автоматически.
4. Собрать Windows с версией выше установленной/опубликованной и проверить UAC, включение, ошибку службы, отключение, возможность восстановления сети и переход между технологиями. Windows vendor скрипт проверяет закреплённые SHA-256. Код и бинарники не подписаны.
5. Собрать Android штатным ключом и с versionCode выше опубликованного; проверить на реальном ARM64-устройстве разрешение VPN, отключение, отзыв, ротацию и выбор технологии. Сторонний SDK доступен только для arm64-v8a.
6. На тестовом аккаунте проверить, что доступны оба способа, старые профили после отзыва действительно перестали работать, а новые — применились после ACK. Проверить, что доступ не получают заблокированные, просроченные или неавторизованные пользователи. Затем проверить Discord, голос и игры, а также отключение при непроходимом endpoint. Только реальные проверки могут подтвердить исправность.

Для отката использовать предыдущий проверенный код и резервные копии по процедуре проекта. Предыдущая версия вновь применяет глобальный `activeProvider`: это может отозвать один из наборов подключений и оборвать сессии, поэтому откат не бесшовный.
