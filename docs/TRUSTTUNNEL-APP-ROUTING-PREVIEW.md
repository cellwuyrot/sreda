# TrustTunnel: маршрутизация приложений — Android, предварительная версия

## Область и ограничения

Это **частичная реализация**, не финальный релиз функции: выбор приложений для Windows (в том числе исключение Discord на Windows) не реализован. Встроенный Windows-клиент TrustTunnel v1.1.12 не предоставляет маршрутизацию по процессам. Маршруты по IP или доменам не равнозначны правилам приложений. Для Windows нужно отдельно исследовать и внедрить поддерживаемое per-app решение с безопасным драйвером, затем провести тесты и решить вопрос его поставки и подписи. Не выдавать Windows UI за работающий split tunneling.

## Android

В окне TrustTunnel → «Расширенные настройки» → «Выбрать приложения на Android» доступны:

- Все приложения через VPN (значение по умолчанию).
- Чёрный список: выбранные приложения напрямую, остальные через VPN.
- Белый список: только выбранные приложения через VPN, все остальные напрямую.

Список выбирается и хранится только на устройстве; на сайт и сервер не передаётся. Показываются видимые запускаемые приложения, а не обязательно все системные процессы. Смена сохраняется только после подтверждения и применяется при следующем включении. Менять настройки следует при отключённом TrustTunnel. Пустой чёрный или белый список не сохраняется; отсутствие выбранного пакета при создании VPN останавливает запуск, вместо молчаливого изменения правил. Android может маршрутизировать совместно пакеты одного UID; системная функция «Блокировать подключения без VPN» может не позволить исключениям работать напрямую. Обычное соединение не защищено VPN.

Реализовано через Android VpnService.Builder.addAllowedApplication / addDisallowedApplication; никакие сетевые профили и политики сервера не изменены. Требуется новая сборка Android **и** развертывание изменённого веб-интерфейса; старый Android-клиент не умеет открыть настройки. Прежнее поведение без изменения настроек сохранено. Из-за новых ограниченных queries в манифесте проверьте требования распространения приложения.

## Обязательная проверка перед выпуском

Android SDK в среде разработки отсутствовал: компиляция, установка и работа на устройствах не проверялись. Не считать этот вариант готовым к публикации. На тестовом устройстве с тестовыми данными собрать debug в Android Studio, не обновлять production, убедиться в наличии штатного способа отключить VPN. Проверить:

1. Без изменений настроек весь обычный внешний трафик идёт через VPN; включение и отключение восстанавливает обычный интернет.
2. В чёрном списке выбранный Discord и ещё одно приложение выходят через обычный IP; другие приложения — через VPN. Повторить после перезапуска приложения и VPN.
3. В белом списке выбранное приложение имеет VPN IP, а другое — обычный IP. Проверить DNS/IPv4/IPv6 и отметить, что трафик других приложений намеренно идёт напрямую.
4. Проверить пустой список, удаление выбранного приложения, отказ системного разрешения VPN, перезапуск и отсутствие сети, а также настройки Android Always-on/блокировки без VPN; убедиться, что нет молчаливого перехода к иному режиму.
5. Проверить Discord голос и сообщения, в том числе UDP; результат проверять на каждом устройстве отдельно. Убедиться, что переключение не меняет AmneziaWG.
6. На Windows расширенные настройки честно сообщают об отсутствии этой функции; существующий VPN и отключение работают как прежде.

Не отправляйте в чат профили, токены, учётные данные, список установленных приложений или подробные сетевые логи.
