# Исправление CI и мобильного интерфейса

## Что исправлено

- Тесты API `/api/admin/builds` изолированы от внешнего `NEXTAUTH_URL`. В CI адрес приложения — `http://localhost:3000`, поэтому тестовые запросы используют тот же origin. Проверка same-origin в API не отключена. Добавлены проверки отказа для чужого и отсутствующего Origin.
- Мобильный глобальный поиск открывается отдельным полноэкранным диалогом: поле ввода сверху, область результатов прокручивается, кнопка закрытия не меньше 44 × 44 px. Остальные мобильные модальные окна сохраняют прежнее поведение.
- На Android в шапке главной добавлен заголовок «Сообщества», увеличен вторичный текст. Колокольчик не включён: его маршрут `/settings/notifications` выходит за разрешённую область оболочки `/connect`.

## Важные ограничения APK

Предоставленный APK — **отладочный**, `ru.trioz.connect.debug`, Android 8.0+ (API 26), подписан debug-ключом. Это не релиз и не обновление установленного приложения: package ID и подпись отличаются. Он запускает существующую WebView-оболочку и по умолчанию обращается к `https://trioz.ru`, то есть вход и действия выполняются на настоящем сервере. Нативный Compose-экран — незавершённое отдельное debug-превью, не launcher. Подробности — `apps/android/app/NATIVE-MIGRATION.md`.

**Веб-интерфейс не встроен в APK.** Для нового дизайна нужно сначала развернуть изменённую веб-часть из архива на тестовом или рабочем сервере, на который указывает приложение. Изменения в ZIP сами сервер не обновляют. Используйте отдельный HTTPS-стенд и отдельные тестовые данные. Debug APK для стенда можно собрать командой:

```sh
cd apps/android
./gradlew -Ptrioz.debugAppUrl=https://АДРЕС-СТЕНДА :app:assembleDebug
```

Нужен HTTPS origin без пути. Проверки на реальном Android-устройстве, на сервере, с экранной клавиатурой и реальным обновлением приложения не проводились. В собранном debug APK не было `google-services.json`: получение push в закрытом приложении не настроено и не проверено. Публикация production и установка поверх существующей версии требуют исходного release-ключа, корректной версии и отдельной приёмки; ключи не находятся в архиве. Инструкция — `docs/android-release.md`.

## Проверки

- Веб-тесты в окружении CI с `NEXTAUTH_URL=http://localhost:3000`: 219 файлов, 2822 теста прошли.
- Проверка типов веба и desktop, веб-lint и production-сборка `npm run build`: прошли.
- `testDebugUnitTest lintDebug assembleDebug`: прошли; debug-подпись APK проверена.
- Локальный рендер настоящих компонентов с тестовыми данными: экраны 360×800, 390×844, 430×932 и 390×500; проверены положение поля, размеры закрытия, переключение области, Escape и возврат фокуса. Это не проверка устройства или реальной клавиатуры.
- Удалённый GitHub Actions и миграции PostgreSQL локально не запускались. После внесения архива в репозиторий нужно заново запустить полный CI.

## Проверка CI локально

Из корня проекта после установки зависимостей и генерации Prisma-клиента:

```sh
NEXTAUTH_URL=http://localhost:3000 npm run test -w apps/web -- --maxWorkers=2
npm run typecheck -w apps/web
npm run typecheck
npm run lint
```

Для полноценной сборки и миграций потребуются настроенные сервисы и переменные окружения проекта. Не подменяйте боевой `NEXTAUTH_URL`: он должен точно соответствовать внешнему адресу, с которого администраторы открывают сайт.
