# Android и админка сборок — частичный этап

## Границы

Полноценный нативный Android ещё **не реализован**. В архиве сохранён предыдущий debug-прототип Compose. Обычная релизная сборка по-прежнему запускает исходную WebView-оболочку. Она не становится нативной при нажатии «Android» в админке. Не подменяйте launcher и не удаляйте установленное приложение: ключи защищённых диалогов и другие данные ещё не перенесены. Личные и групповые звонки, VPN, отправка сообщений, push, полная админка и остальные сценарии в нативном прототипе не реализованы. Подробности: `apps/android/app/NATIVE-MIGRATION.md`.

## Что изменено

- В «Сервисы и система → Сборки» добавлены краткие требования подписи и Firebase и инструкция, в стиле существующей админки, для светлой и тёмной тем. Это **информация**, а не форма конфигурации: сервис не проверяет фактические файлы агента и не принимает ключи через UI.
- Действия постановки/отмены требуют same-origin. Внешний URL в `NEXTAUTH_URL` должен точно совпадать с адресом, используемым в браузере. Прежде чем обновлять production, проверьте это на тестовом окружении и сохраните доступ к управлению.
- Отменить из админки теперь можно только задачу в очереди. Для работающей сборки безопасная отмена недоступна: старый скрипт может опубликовать файл до получения команды отмены. Проверка на очередь атомарная.
- Публичный агент отказывает при `TRIOZ_ANDROID_DEBUG=1`; debug больше не может заменить `connect.apk` через этот скрипт. Копии keystore.properties и google-services.json, созданные скриптом в disposable-клоне, удаляются при обычном выходе и ошибке. При принудительном SIGKILL или сбое питания ручная проверка клона всё равно нужна.

## Перед выпуском

Сборщик берёт `main` из своего репозитория, а не код из этого ZIP автоматически. Сначала проверьте изменения на отдельном стенде и только затем обновите соответствующий код веб-сервера и самого агента сборки; сами по себе файлы в архиве сервер не меняют. Успешный release автоматически заменяет публичные файлы. Не запускайте его до проверки.

Для реального обновления Android нужно сохранить package ID и ту же подпись, увеличить `versionCode`, настроить `TRIOZ_ANDROID_CONFIG_DIR` на машине агента и отдельно задать серверные параметры FCM. APK не содержит серверный private key. Не пересылайте ключи в чат. Полная инструкция: `docs/android-release.md`.

## Проверки этапа

- Unit-тесты `apps/web/src/app/api/admin/builds/route.test.ts`.
- `bash apps/builder/tests/test-android-build.sh` — изолированная проверка с поддельными Git/Gradle, не реальная Android-сборка.
- Проверка типов веб-приложения и lint изменённых файлов.

На этом этапе не проверены настоящий builder, доставка Firebase, установка/обновление APK, Android-устройство, защищённые чаты и звонки. Перед production обязательны интеграционные испытания и сохранение ключей подписи и пользовательских данных.
