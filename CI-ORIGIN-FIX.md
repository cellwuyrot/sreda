# Исправление CI: Origin в тестах мониторинга

Причина: workflow задаёт NEXTAUTH_URL=http://localhost:3000, а новые POST-тесты отправляли Origin=http://localhost без порта. Проверка same-origin закономерно отвечала 403. Исходные четыре падения воспроизведены перед исправлением.

Исправлен только тестовый код apps/web/src/app/api/admin/monitor/route.test.ts:
- единый явный APP_ORIGIN для URL запросов и Origin;
- NEXTAUTH_URL устанавливается через vi.stubEnv перед каждым тестом и восстанавливается через vi.unstubAllEnvs;
- дополнительные регрессии на отсутствующий Origin и отсутствующий порт.

Код API, same-origin-защита, роли, агент, зависимости, миграции и workflow не изменены. Business и tz-id обновлять не требуется.

Проверено локально на чистой копии исходного архива с установкой зависимостей из lock-файла (Node 22.23.4):
- до правки: 4 failed / 5 passed;
- после: 11/11 целевых тестов с CI-адресом;
- 11/11 с отличающимся внешним NEXTAUTH_URL (проверка изоляции);
- полный прогон с NEXTAUTH_URL=http://localhost:3000 и тестовыми переменными workflow: 191 файл, 2555 тестов успешно;
- TypeScript web и ESLint изменённого файла: успешно.

Сам GitHub Actions здесь не запускался; PostgreSQL-миграции и production-сборка повторно не запускались, поскольку рабочий код не изменён. Результаты предшествующих сборок описаны в TEST-REPORT-PROJECT-MONITORING.md.

Для этого исправления достаточно перенести указанный route.test.ts из архива в свою копию sreda, закоммитить и отправить в Git. Сохраните свои остальные изменения. Перезапуск PM2 и изменение рабочего .env не нужны.

Повторная проверка из корня репозитория:

```bash
npm run test -w apps/web -- --maxWorkers=2
```
