# TrustTunnel — актуальный статус обновления проекта

Этот архив подготовлен как полный исходный проект для обновления, а не как patch. Текущий контрольный документ — `docs/TRUSTTUNNEL-1.2-DEPLOY.md`; старые `*-WIP.md` и заметки о пилотных блокировках являются историей этапов и не описывают текущую реализацию.

## Изменения текущего обновления

- Разблокировано глобальное переключение `AmneziaWG` / `TrustTunnel` при корректной серверной конфигурации. Настройка одна на весь проект и хранится в `VpnSettings.activeProvider`; по умолчанию остаётся AmneziaWG. Роль `ADMIN` проекта — единственная роль, которой разрешено менять её.
- Все три стороны выбора согласованы: выдача AmneziaWG-профилей, выдача TrustTunnel-профиля и полный pull-снимок endpoint-agent. При выборе AmneziaWG следующий успешный sync отзовёт управляемые TrustTunnel credentials. Существующий общий выключатель `VpnSettings.enabled` также прекращает выдачу и приводит к пустому endpoint snapshot при выключении сервиса. DB error не превращается в пустой snapshot.
- Обновлено пользовательское окно «Надёжное соединение»: фиолетовая палитра, кнопка подключения, тариф/право из API, ожидание ACK, отсутствие кнопки скачивания и данных профиля, состояния ошибки и конфликта с другим VPN, клавиатурное управление/фокус.
- Android TrustTunnel SDK 1.1.12, сервис и bridge добавлены в release source set и зависимости; вариант ограничен `arm64-v8a`. Версия исходника `0.5.0`, `versionCode=4` (перед публикацией сверить с Play Console).
- Windows состояние службы больше не называется подтверждённым туннелем, пока нативная проверка не подтвердит прохождение. Windows binaries не были включены в ZIP; для сборки предусмотрен vendor script.
- Добавлены тесты для provider config, ADMIN-only, impact confirmation, прав подписчика, статуса доступа и server sync snapshot. Добавлены примеры TrustTunnel env без секретов.

## Что подтверждено и что нет

Владелец проекта сообщил, что тесты технологии и межсерверная связь уже пройдены. В этой работе сетевые/server команды не запускались и версии живых серверов не сверялись. Discord/high ping root cause остаётся неустановленной: HTTP/1.1 proxy-тест не проверяет весь клиентский HTTP/2 маршрут; связь наблюдавшегося HTTP 400 с запросом Windows не доказана; численные ping/UDP измерения не предоставлены.

Android APK/AAB здесь не собраны: в окружении нет Android SDK/toolchain и production signing keystore. Windows-сборка также не выполнялась; настоящая Windows, UAC, service ACL и трафик не проверялись. Это обновлённый исходный код, не доказательство готовности к публичному релизу. Учёт/лимиты TrustTunnel не реализованы; Windows code signing не подтверждён.

## Перенос и rollout

Порядок миграций, env, endpoint-agent, глобального переключения и отката находится в `docs/TRUSTTUNNEL-1.2-DEPLOY.md`. Android подпись, APK/AAB и устройство — в `docs/android-release.md`. Перед переключением предупредить пользователей: оба направления прерывают активные сессии. При выборе TrustTunnel VPN-узел получает пустой AWG peer list на следующем опросе (обычно около 5 секунд); при возврате на AmneziaWG Endpoint получает пустой TrustTunnel snapshot и может перезапуститься. Старые приложения не мигрируют автоматически.

## Сохранённое

Пользовательский `apps/desktop/build/Makefile` сохранён без изменений. ZIP не должен содержать `.env`, резервные env-копии, ключи, keystore, `node_modules` или сборочные каталоги. Граф `.codebase-memory/graph.db.zst` сохранён как исторический артефакт и требует переиндексации после коммита обновлённого проекта в рабочий Git.
